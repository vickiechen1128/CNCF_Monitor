## 0. 设计原则

**一行 = 一次告警发生（occurrence）。**

- 业务自然键：`(fingerprint, starts_at)`，复合唯一索引。
- 物理主键：`id` 自增，不参与业务语义。
- 事实源：AM 原生字段（`fingerprint`、`startsAt`、`labels`、`annotations`、resolved 通知的 `endsAt`）。
- 物化字段：`alertname` / `severity` / `domain` / `summary` / `description` 是 labels/annotations 的冗余投影，只为查询性能。
- 状态用 `status` 一个字段表达，不设 `is_open`，未结束用 `status IN ('firing','silenced','inhibited')` 判断。
- `end_time` 只存真实恢复时间（仅 `resolved` 有值）；`closed_at` 存记录关闭时间，**所有结束态都有值**。
- 真实恢复时间不伪造；`resolved_lost` / `resolved_during_silence` / `resolved_during_inhibition` 的 `end_time` 留空，用 `closed_at` 做统计。
- **表里每一行都是“用户本该知道的告警”**：对账不补插 suppressed，只补 active 漏记。不需要来源/通知类字段。

**核心不变量**：

1. 同一 `(fingerprint, starts_at)` 全局唯一。
2. 同一 `fingerprint` 最多一条未结束记录。
3. 未结束判断用 `status IN (...)`，**不用** **`end_time IS NULL`**（`resolved_lost` / `resolved_during_silence` / `resolved_during_inhibition` 的 `end_time` 也为空）。
4. 未结束状态互跳和对账判定关行只由对账写；webhook 只负责插入新 firing、回填 resolved、刷新展示字段。
5. 对账补插只补 active 漏记，suppressed 一律跳过。
6. 对账对 suppressed 绝不新增；已有未结束记录更新状态，对账判定关闭的记录重新出现时恢复原行。

## 1. 数据模型

### 1.1 主表 `alert_history`

| 字段            | 来源                               | 说明                                  |
| :------------ | :------------------------------- | :---------------------------------- |
| `id`          | 自定义                              | bigint 自增主键                         |
| `fingerprint` | **AM 原生**                        | 无指纹时用 `hash(labels + starts_at)` 生成 |
| `starts_at`   | **AM 原生**（`startsAt`）            | 告警真实开始时间，occurrence 标识的一部分          |
| `alertname`   | label 物化                         | 冗余投影，查询用                            |
| `severity`    | label 物化                         | 冗余投影，可删                             |
| `domain`      | 自定义 label 物化                     | 从业务 label 解析，可删                     |
| `summary`     | annotation 物化                    | 冗余投影，可删                             |
| `description` | annotation 物化                    | 冗余投影，可删                             |
| `labels`      | **AM 原生**                        | 完整标签 JSON，事实源                       |
| `annotations` | **AM 原生**                        | 完整注解 JSON，事实源                       |
| `status`      | 自定义状态机                           | 见 1.2                               |
| `start_time`  | **AM 原生**                        | 真实开始时间（通常 = `starts_at`）            |
| `end_time`    | **AM 原生**（resolved 通知的 `endsAt`） | 真实恢复时间，仅 `resolved` 有值              |
| `closed_at`   | 自定义（webhook / 对账写入）              | 记录关闭时间，**所有结束态都有值**                 |
| `created_at`  | 自定义                              | 入库时间                                |
| `updated_at`  | 自定义                              | 行最后更新审计时间                           |

**已删除字段及理由**：

| 字段                    | 删除理由                                                                                       |
| :-------------------- | :----------------------------------------------------------------------------------------- |
| `is_open`             | 用 `status` 判断，冗余                                                                           |
| `last_seen_active_at` | 对账 60s 一次，精度不提升，价值低                                                                        |
| `closed_reason`       | `status` 已表达原因（`resolved_during_silence` / `resolved_during_inhibition` / `resolved_lost`） |
| `occurrence_key`      | 用复合唯一索引 `(fingerprint, starts_at)` 表达                                                      |
| `source`              | 对账不补 suppressed，全表即用户视图，不需要来源标识                                                            |
| `notified`            | 同上，口径收窄后无意义                                                                                |
| `last_notified_at`    | 同上，用户不在乎推送时间审计                                                                             |
| `receiver`            | 恒为 `history-webhook`，无信息量                                                                  |
| `group_key`           | 同上，单历史 receiver 下无展示价值                                                                     |

### 1.2 状态枚举

**未结束**：

| 状态          | 含义          |
| :---------- | :---------- |
| `firing`    | 告警中，未被静默/抑制 |
| `silenced`  | 静默或时间区间静音中  |
| `inhibited` | 抑制中         |

**结束**：

| 状态                           | 含义     | `end_time` | `closed_at`         |
| :--------------------------- | :----- | :--------- | :------------------ |
| `resolved`                   | 真实恢复   | **有值**     | **有值（= end\_time）** |
| `resolved_during_silence`    | 静默期间结束 | **空**      | **有值**              |
| `resolved_during_inhibition` | 抑制期间结束 | **空**      | **有值**              |
| `resolved_lost`              | 恢复信息丢失 | **空**      | **有值**              |

### 1.3 索引与约束

sql

```
-- 同一发生实例唯一
UNIQUE (fingerprint, starts_at);

-- 同一 fingerprint 最多一条未结束
CREATE UNIQUE INDEX uq_open_fingerprint
  ON alert_history (fingerprint)
  WHERE status IN ('firing','silenced','inhibited');

-- 查询索引
CREATE INDEX idx_status_start ON alert_history (status, start_time);
CREATE INDEX idx_closed_at ON alert_history (closed_at);
```

### 1.4 时间字段语义

| 字段           | 语义                                      | 谁写                      |
| :----------- | :-------------------------------------- | :---------------------- |
| `start_time` | 告警真实开始时间                                | webhook 插入 / 对账补插       |
| `end_time`   | **告警真实恢复时间**，取 AM resolved 通知的 `endsAt` | webhook resolved        |
| `closed_at`  | **这行记录关闭的时间**，所有结束态都有                   | webhook resolved / 对账关闭 |

**写入规则**：

text

```
webhook firing 插入：
  start_time = starts_at
  end_time   = NULL
  closed_at  = NULL

对账关闭（记录从活跃集消失）：
  end_time   = NULL              -- 不伪造
  closed_at  = 本轮对账时间
  status     = resolved_during_silence / resolved_during_inhibition / resolved_lost

webhook resolved 到达（记录存在）：
  end_time   = 通知里的真实恢复时间
  closed_at  = end_time          -- 关闭时间 = 真实恢复时间
  status     = resolved

迟到 resolved 到达（记录已是对账关闭的）：
  end_time   = 通知里的真实恢复时间
  closed_at  = end_time          -- 更新为真实恢复时间，覆盖对账发现时间
  status     = resolved
```

**`updated_at`** **更新规则**：插入记录时初始化为入库时间；后续仅当 `status`、`end_time`、`closed_at` 或展示字段实际发生变化时，更新为本次写库时间。重复 firing、重复 resolved 以及状态未变化的对账不刷新 `updated_at`。

统计口径：

text

```
closed_at 有值  → 结束时刻（所有结束态都有）
closed_at 为空  → 未结束，用 now() 作为区间终点
end_time 有值   → 真实恢复时刻（仅 resolved）
```

## 2. 状态机

text

```
                    webhook firing（occurrence 不存在）
                                ↓
                             ┌──────┐
               对账互跳 ────→ │firing│ ←──── 对账互跳
               （silenced/   └──────┘      （inhibited/
                inhibited）      │           silenced 恢复）
                                │
                     webhook resolved（回填 end_time，closed_at = end_time）
                                ↓
                             ┌────────┐
                             │resolved│
                             └────────┘
                                ↑
               迟到 resolved 回填│（更新 closed_at）
                                │
  对账关闭：firing → resolved_lost ─┤
            silenced → resolved_during_silence
            inhibited → resolved_during_inhibition
            （end_time 空，closed_at 有值）

对账判定关闭后重新活跃 → 原行恢复未结束状态，清空 closed_at
已 resolved 的记录不恢复；结束后新 starts_at 再次 firing → 新行
```

关键规则：

- 未结束三态互跳**只由对账写**，且**只对已有未结束记录**做，不新增。
- `resolved_during_silence` / `resolved_during_inhibition` / `resolved_lost` 可被迟到 resolved **升级**为 `resolved`，`closed_at` 更新为真实恢复时间。
- 对账判定关闭的记录重新出现在活跃集时，在原行恢复未结束状态并清空 `closed_at`；已真实 `resolved` 的记录不恢复。
- 已 `resolved` 的记录收到重复 resolved → 幂等忽略。
- 同一 fingerprint 结束后再次 firing（新 `starts_at`）→ 新行。

## 3. Webhook 实时通道

**端点**：`POST /api/v1/webhooks/alerts`

### 3.1 返回码策略

| 情况            | 返回  | 处理                 |
| :------------ | :-- | :----------------- |
| 解析失败 / 永久坏消息  | 2xx | 落死信表，不阻塞 AM        |
| 写库暂时失败 / 入队失败 | 5xx | 让 AM 重试；接收端幂等，重试无害 |
| 成功            | 2xx | <br />             |

批次能够解析时逐条处理：正常告警继续入库，坏消息单独落死信，单条坏消息不影响同批其他告警。整个报文无法解析时，将原始报文落死信。只有正常记录和死信都持久化成功才返回 2xx；任一暂时性写入失败返回 5xx，重试时由接收端幂等兜底。

### 3.2 收到 firing

text

```
按 (fingerprint, starts_at) 查：
  存在（任意状态）：
    ❌ 不新增
    ❌ 不改状态
    可更新 summary/description/annotations 等非状态展示字段
  不存在：
    插入 status=firing, start_time=startsAt, end_time=NULL, closed_at=NULL
```

**迟到 firing 不复活**：同一次发生已结束，再来 firing 通知只更新展示字段，不改回未结束。

### 3.3 收到 resolved

text

```
按 (fingerprint, starts_at) 查：
  存在且 end_time 为空：
    UPDATE ... SET end_time=?, closed_at=?, status='resolved', updated_at=now()
    WHERE fingerprint=? AND starts_at=? AND end_time IS NULL
    -- closed_at 更新为 end_time，覆盖对账发现时间
  存在且已是 resolved：
    幂等忽略
  不存在：
    补插一行 status=resolved, end_time=endsAt, closed_at=endsAt
    -- 覆盖"触发通知丢了但恢复通知到了"
```

`end_time` 和 `closed_at` 都取该条告警的 `endsAt`，不取 webhook 接收时间。`resolved` 通知缺少有效 `endsAt` 时按坏消息处理，不写入恢复记录。状态词只有 `resolved` 算恢复，其它一律按 firing 处理。

### 3.4 写权限边界

| 操作                             | webhook | 对账              |
| :----------------------------- | :------ | :-------------- |
| 插入新 firing                     | ✅       | ✅（只补 active 漏记） |
| 刷新展示字段                         | ✅       | ✅               |
| 回填 `end_time` / 更新 `closed_at` | ✅       | ❌               |
| 未结束三态互跳                        | ❌       | ✅（只对已有记录）       |
| 对账判定关行                         | ❌       | ✅               |

## 4. 分钟级对账通道

每 60s 拉取：

- 当前活跃告警全集（`/api/v2/alerts`，含 silenced / inhibited）
- Alertmanager 启动时间（`/api/v2/status`）

### 4.1 安全阀

| 条件                        | 行为                           |
| :------------------------ | :--------------------------- |
| AM 不可达或响应不完整              | 整轮跳过，不动数据                    |
| AM 启动不满 3 分钟              | 只做对齐和补插，**不关行**              |
| 记录 `created_at` 距今不满 2 分钟 | 该记录不关行                       |
| 活跃集为空                     | 空集可能是正常状态；连续 N 轮完整拉取均为空后允许关行 |
| 单轮关闭比例异常                  | 暂停关闭并告警，连续 N 轮确认后再关          |

### 4.2 对账三件事

#### 4.2.1 对齐状态并纠正误判关闭（不新增）

对每条未结束（`status IN ('firing','silenced','inhibited')`）且仍在活跃集里的记录：

text

```
if silencedBy 非空 or mutedBy 非空:
    status = 'silenced'          // 静默和时间区间静音统一记为 silenced
elif inhibitedBy 非空:
    status = 'inhibited'
else:
    status = 'firing'
```

sql

```
UPDATE alert_history
SET status=?, updated_at=now()
WHERE fingerprint=? AND starts_at=?
  AND status IN ('firing','silenced','inhibited')
  AND status <> ?;
```

如果已被对账判定关闭的记录重新出现在活跃集，说明此前关闭判断不成立。按当前 `silencedBy` / `mutedBy` / `inhibitedBy` 计算未结束状态，并在原行上恢复：

sql

```
UPDATE alert_history
SET status=?, closed_at=NULL, end_time=NULL, updated_at=now()
WHERE fingerprint=? AND starts_at=?
  AND status IN ('resolved_lost','resolved_during_silence','resolved_during_inhibition');
```

已真实 `resolved` 的记录不恢复。状态对齐只对已有未结束记录改状态；suppressed 可能是“先 firing 入库，后被静默/抑制”，也可能从首次触发起就被压制。后者没有记录且不补插。

#### 4.2.2 关闭消失的

对每条未结束但不在活跃集里的记录（且通过安全阀）：

text

```
if 原 status == 'silenced':
    new_status = 'resolved_during_silence'
elif 原 status == 'inhibited':
    new_status = 'resolved_during_inhibition'
else:
    new_status = 'resolved_lost'
```

sql

```
UPDATE alert_history
SET status = ?,
    closed_at = ?,
    end_time = NULL,
    updated_at = now()
WHERE fingerprint=? AND starts_at=?
  AND status IN ('firing','silenced','inhibited');
```

`end_time` 不伪造，留空；`closed_at` 记录对账发现消失的时刻。

#### 4.2.3 补插漏记（只补 active）

text

```
for alert in active_alerts:
    if (fingerprint, starts_at) exists in db:
        // 未结束或对账关闭记录已在 4.2.1 处理；真实 resolved 不恢复
        continue

    if alert.status.state != 'active':
        // suppressed 不补插；unprocessed 尚未确定是否通知，也不补插
        continue

    // state == 'active'：本该通知但通知丢了
    insert(status='firing', start_time=starts_at, end_time=NULL, closed_at=NULL)
```

| 场景            | 库里无记录   | AM 状态      | 是否补插         |
| :------------ | :------ | :--------- | :----------- |
| 触发通知丢失        | 是       | active     | ✅ 补插 firing  |
| 触发时就被静默/抑制    | 是       | suppressed | ❌ **不补插**    |
| 先 active 后被抑制 | 否（已有记录） | suppressed | 已在 4.2.1 改状态 |

## 5. `suppressed` 的判定

AM API 的 `status.state` 只有三种：

| state         | 含义           | 是否发通知 |
| :------------ | :----------- | :---- |
| `unprocessed` | 尚未处理         | 不确定   |
| `active`      | firing 且未被压制 | 会     |
| `suppressed`  | firing 但被压制  | 不会    |

`suppressed` 是上位状态，区分原因看同一 `status` 对象：

| 字段            | 非空含义    |
| :------------ | :------ |
| `silencedBy`  | 至少被静默   |
| `inhibitedBy` | 至少被抑制   |
| `mutedBy`     | 按时间区间静音 |

| 条件                          | 结论          |
| :-------------------------- | :---------- |
| `silencedBy` 或 `mutedBy` 非空 | `silenced`  |
| 前两项为空且 `inhibitedBy` 非空     | `inhibited` |
| 三项均为空                       | `firing`    |

静默和时间区间静音统一记为 `silenced`，优先于抑制。抑制既可能发生在首次通知之后，也可能在首次通知前就生效。已有记录时按上述字段更新状态；没有记录时不因 suppressed 补插。

## 6. 查询与统计

### 6.1 告警区间

text

```
closed_at 有值   → [start_time, closed_at]
未结束          → [start_time, now()]
```

SQL 表达：

sql

```
COALESCE(closed_at, now())
```

### 6.2 展示

| 状态                                  | 展示                               |
| :---------------------------------- | :------------------------------- |
| `firing` / `silenced` / `inhibited` | 持续中，开始于 `start_time`             |
| `resolved`                          | 恢复时间：`end_time`                  |
| `resolved_during_silence`           | 恢复时间未知（静默期间结束，`closed_at` 发现已结束） |
| `resolved_during_inhibition`        | 恢复时间未知（抑制期间结束，`closed_at` 发现已结束） |
| `resolved_lost`                     | 恢复时间未知（恢复通知丢失，`closed_at` 发现已结束） |

### 6.3 默认视图

全表即用户视图，无来源过滤。所有查询直接基于 `alert_history`。

### 6.4 核心指标

应用层按业务时区算好自然日边界传入：

text

```
today_start     = 今天 00:00:00
tomorrow_start  = 明天 00:00:00
```

按 occurrence 行数计数，同一 fingerprint 一天多次发生算多次。

#### 6.4.1 今日告警

sql

```
SELECT count(*) AS today_alerts
FROM alert_history
WHERE start_time >= :today_start
  AND start_time <  :tomorrow_start;
```

按 `start_time` 算，不按 `created_at`。对账补插的 active 漏记，`start_time = starts_at`，属今天则计入。

#### 6.4.2 今日恢复

sql

```
-- 合计（真实恢复 + 判定结束）
SELECT count(*) AS today_resolved_total
FROM alert_history
WHERE status IN ('resolved','resolved_during_silence','resolved_during_inhibition','resolved_lost')
  AND closed_at >= :today_start
  AND closed_at <  :tomorrow_start;
```

sql

```
-- 真实恢复
SELECT count(*) AS today_resolved_real
FROM alert_history
WHERE status = 'resolved'
  AND closed_at >= :today_start
  AND closed_at <  :tomorrow_start;
```

sql

```
-- 判定结束（恢复时间未知）
SELECT count(*) AS today_resolved_inferred
FROM alert_history
WHERE status IN ('resolved_during_silence','resolved_during_inhibition','resolved_lost')
  AND closed_at >= :today_start
  AND closed_at <  :tomorrow_start;
```

"今日恢复合计" = 真实恢复 + 判定结束，展示时标注"其中 N 条恢复时间未知"。

#### 6.4.3 历史遗留告警

**当前快照**：仍未结束且开始时间早于今天零点。

sql

```
SELECT count(*) AS legacy_open_alerts
FROM alert_history
WHERE status IN ('firing','silenced','inhibited')
  AND start_time < :today_start;
```

按状态拆分：

sql

```
SELECT status, count(*)
FROM alert_history
WHERE status IN ('firing','silenced','inhibited')
  AND start_time < :today_start
GROUP BY status;
```

#### 6.4.4 历史遗留告警今日恢复

sql

```
-- 合计
SELECT count(*) AS legacy_resolved_today
FROM alert_history
WHERE status IN ('resolved','resolved_during_silence','resolved_during_inhibition','resolved_lost')
  AND start_time < :today_start
  AND closed_at >= :today_start
  AND closed_at <  :tomorrow_start;
```

sql

```
-- 其中真实恢复
SELECT count(*) AS legacy_resolved_today_real
FROM alert_history
WHERE status = 'resolved'
  AND start_time < :today_start
  AND closed_at >= :today_start
  AND closed_at <  :tomorrow_start;
```

sql

```
-- 其中判定结束
SELECT count(*) AS legacy_resolved_today_inferred
FROM alert_history
WHERE status IN ('resolved_during_silence','resolved_during_inhibition','resolved_lost')
  AND start_time < :today_start
  AND closed_at >= :today_start
  AND closed_at <  :tomorrow_start;
```

#### 6.4.5 指标汇总与自洽关系

| 指标         | 类型   | 条件核心                                         |
| :--------- | :--- | :------------------------------------------- |
| 今日告警       | 今日增量 | `start_time ∈ 今天`                            |
| 今日恢复       | 今日增量 | 结束态 且 `closed_at ∈ 今天`                       |
| 历史遗留告警     | 当前快照 | 未结束 且 `start_time < 今天零点`                    |
| 历史遗留告警今日恢复 | 今日增量 | 结束态 且 `start_time < 今天零点` 且 `closed_at ∈ 今天` |

自洽校验（近似）：

text

```
今日零点遗留快照
  - 历史遗留告警今日恢复
  ≈ 当前历史遗留告警
```

指标仅用于展示，不做一致性告警。迟到 resolved 会用真实 `endsAt` 改写 `closed_at`，历史日期指标可能因此重算；对账补录的零点前告警也不包含在今日零点快照中，因此上述关系仅作近似参考。

#### 6.4.6 实现注意

1. **时区**：自然日边界由应用层算好传入，不用 DB `now()` 直接 `date_trunc`。
2. **索引**：依赖 `(status, start_time)`、`(closed_at)`。
3. **快照指标**：可缓存 30–60s；需要趋势时每日零点固化或小时采样。
4. **计数单位**：按 occurrence 行数，不按 fingerprint 去重；规则维度指标另做 `count(distinct fingerprint)`。

## 8. 并发与一致性

- 单节点只运行一个对账任务，上一轮未结束时本轮不重入。
- webhook 与对账仍可能并发，所有状态更新用条件更新：

sql

```
-- 对齐状态
UPDATE alert_history
SET status=?, updated_at=now()
WHERE fingerprint=? AND starts_at=?
  AND status IN ('firing','silenced','inhibited')
  AND status <> ?;

-- 关行
UPDATE alert_history
SET status=?, closed_at=?, end_time=NULL, updated_at=now()
WHERE fingerprint=? AND starts_at=?
  AND status IN ('firing','silenced','inhibited');

-- 回填 resolved（覆盖对账结论）
UPDATE alert_history
SET end_time=?, closed_at=?, status='resolved', updated_at=now()
WHERE fingerprint=? AND starts_at=?
  AND end_time IS NULL;

-- 补插
INSERT ... ON CONFLICT (fingerprint, starts_at) DO NOTHING;
```

- `end_time IS NULL` 作回填条件，保证真实恢复只写一次，且能覆盖 `resolved_lost` / `resolved_during_silence` / `resolved_during_inhibition`。
- 迟到 resolved 优先于对账判定，`closed_at` 更新为真实恢复时间。

## 9. 边界与特殊情况

| 情况                      | 处理                                                                         |
| :---------------------- | :------------------------------------------------------------------------- |
| 无 fingerprint           | labels 按 key 排序序列化后，用 `hash(labels + starts_at)` 生成 fallback fingerprint   |
| webhook 重复 firing       | 已存在 → 只刷新展示字段，不新增                                                          |
| 迟到 firing（记录已关）         | 已存在 → 只刷新展示字段，不复活                                                          |
| 对账关闭后重新活跃               | 仅对账判定关闭的记录恢复原行并清空 `closed_at`；已 `resolved` 的不恢复                            |
| 迟到 resolved（记录已关）       | `end_time IS NULL` → 回填 `end_time`，`closed_at` 更新为 `end_time`，转 `resolved` |
| resolved 缺少有效 `endsAt`  | 按坏消息落死信，不写入恢复记录                                                            |
| 重复 resolved             | 已 resolved 且有 end\_time → 幂等忽略                                             |
| 同一 fingerprint 结束后再触发   | 新 `starts_at` → 新行                                                         |
| AM 返回空活跃集               | 连续 N 轮完整拉取均为空后允许关行                                                         |
| 记录 `created_at` 不满 2 分钟 | 该记录暂不关行                                                                    |
| unprocessed 且无记录        | 不补插，等后续对账确认                                                                |
| suppressed 且无记录         | **不补插**，直接跳过                                                               |
| suppressed 且已有记录        | 只改状态，不新增                                                                   |
| 静默与抑制同时存在               | 静默优先，记 `silenced`                                                          |

***

## 10. 一句话总结

一行 = 一个 `(fingerprint, starts_at)` 的发生实例；`status` 一个字段表达全部状态；`end_time` 只存真实恢复时间（仅 `resolved` 有值）；`closed_at` 存记录关闭时间，**所有结束态都有值**，统计统一用它，迟到 resolved 到达时更新为真实恢复时间；抑制/静默只改状态不新增；补插只补 active 漏记，suppressed 一律跳过；全表即用户视图。
