# 设计对齐记录：M06 租户语义、登录模型与网域分类（2026-08-18）

## 对齐信息

- **日期**：2026-08-18
- **参与**：chenrt（产品/业务方）、AI 助手（后端/架构分析）
- **触发原因**：
  1. 对 M06 租户定义产生歧义（租户 = 公司客户 vs 业务单元）；
  2. 明确 MVP 登录、网域创建、网域分类、管理域/边缘域等关键概念；
  3. 提前识别 PRD 与本次需求之间的冲突点，形成决策输入。

## 已达成结论

### 结论 1：租户 = 数据隔离与权限作用域单位，对应 CMDB 业务

- **一句话定义**：租户是 MetricCenter 内部的数据隔离与权限作用域单位，语义上对应客户组织内可独立管理的一摊「业务」，与 BlueKing CMDB 的 **Business（业务）1:1 映射**。
- **不是「公司客户」**：公司客户是更外层的运营/交付概念。MetricCenter 当前以私有化单客户部署为主，「客户」这一层由部署实例本身承担；实例内部用租户向下拆分。
- **MVP 范围**：只存在系统预置租户 `platform_admin`，不开放租户 CRUD；租户管理（创建、编辑、禁用、租户-网域关联）归 **v0.2**。

### 结论 2：登录模型采用「租户 + 用户 + 密码」三段式作为长期方向，MVP 暂不实现

- **长期形态**：`租户名 + 用户名 + 密码`。租户名用于确定作用域，用户名用于区分操作人，密码用于认证。
- **MVP 折中**：MVP 不开发 M03 网关认证能力；网域管理接口在 MVP 期间处于**无细粒度鉴权状态**，依赖部署网络隔离。PRD 需显式声明这是已知风险。
- **模型预留**：即使 MVP 只有一个 `platform_admin` 租户管理员，数据模型也要从「用户挂靠租户」开始设计，避免 v1.0 接入 IAM/SSO 时推翻认证体系。

### 结论 3：网域术语统一为「管理域」与「边缘域」

- **管理域**：全系统**有且只有一个**，由系统预置（`default`），承载平台级默认配置与未显式分配租户的资源。禁止删除、禁止禁用。
- **边缘域**：其余所有网域均为边缘域，是采集器/Edge Agent 安装的网域。用户登录后自助创建。
- **API 约束**：创建网域接口不接受 `domain_type=management`；编辑接口不允许修改 `domain_type`。

### 结论 4：网域 ID 从 MVP 起强制租户前缀

- 规则：`network_domain_id = <tenant_id>-<domain_code>`。
- `default` 是唯一例外（历史预置管理域）。
- 原因：避免 v0.2 多租户上线时出现「存量无前缀 + 新增有前缀」两套规则，导致全局唯一性校验和路由混乱。

### 结论 5：`zone_type` 必须受控，但填写人是用户

- **受控 ≠ 平台替用户填，而是用户只能「选」不能「写」**。`zone_type` 是下拉框，选项来自一份受控字典。
- **必须受控的原因**：`zone_type` 会被 M09 注入指标标签。自由文本会碎裂标签，导致跨网域 PromQL 聚合查询失效。
- **用户的自由分类诉求**：由新增的 `category`（行政分组）字段承接，不进标签、可自由文本。
- **字典治理规则**：
  1. 条目 = `code`（进标签，稳定） + `display_name`（中文展示，可改） + `description`；
  2. `code` 创建后不可变，避免历史指标标签断裂；
  3. 已被网域引用的条目只能 `disabled`（停用），不能删除；
  4. 后端校验 `zone_type ∈ 启用字典项`，不只靠前端下拉。
- **MVP 落地**：配置文件预置字典（至少包含 `default`），提供只读接口 `GET /api/v2/platform/zone-types`；v0.2 升级为「平台预置 + 租户级扩展」两级字典，并增加字典维护入口。

## 仍待明确的问题（需评审拍板）

1. **网域禁用的级联语义**：网域下存在 M07 资源或 M09 已纳管 EdgeAgent 时，禁用操作是**直接禁止**还是**允许但弹出影响范围警告**？
2. **管理域的唯一性强约束**：在数据库层是否加唯一索引 `domain_type = 'management' AND is_deleted = false`？
3. **种子数据初始化路径**：`platform_admin` 租户与 `default` 管理域是由 Go migration 在启动时 upsert，还是由部署脚本一次性 seed？
4. **审计字段**：`NetworkDomain` 行政字段表是否在 MVP 即增加 `created_by` / `updated_by`（MVP 固定为 `system`），为 v1.0 审计留结构？
5. **`category` 字段是否进 MVP**：如果用户当前强烈需要自由分类，可接受将其加入 MVP 网域创建/编辑表单；否则放 v0.2。
