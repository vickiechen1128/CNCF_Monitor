## 总体判断

当前 `feat/module-05-homepage-mvp` 的前端实现功能逻辑正确（告警数字、快速入口、使用指引、`/query` 路由均已落地），但**视觉层与信息架构层尚未经过系统性的原型验证**。三个反馈本质上都是「入口页向 Dashboard 感升级」的设计债，属于 prototype-designer 在 Track B 豁免原型后应补的设计规范，而非代码缺陷。

建议不推翻决策 72 的核心结论（MVP 子集范围、零后端改动、方案 A），而是在该范围内做一次**视觉与信息架构的补设计**，输出高保真/中保真原型与视觉 Token 规范，再让前端按规范调整样式。

## 反馈 1 设计意见：使用指引应包含「配置告警」，/query 空页不应复用 Prometheus UI

### 1.1 指引动线建议：六步闭环

将当前五步动线扩展为「监控闭环六步」，把「配置告警」显性化：

```
登记网域 → 导入资源 → 建采集 Job → 下发配置 → 配置告警通知 → 查指标/看告警
```

| 步骤 | 用户语言 | 深链目标 | 完成态判定（可延后实现） |
|------|----------|----------|--------------------------|
| 1 | 登记网域 | `/domain-onboarding` 或 `/network-domains` | 存在 ≥1 个网域 |
| 2 | 导入资源 | `/resources` | 资源总数 > 0 |
| 3 | 建采集 Job | `/scrape-jobs` | 采集 Job 总数 > 0 |
| 4 | 下发配置 | `/config-preview` | 最近下发成功 |
| 5 | 配置告警通知 | `/alert-config` | AM 配置已挂载（可用 `dashboard/summary` 扩展或 M08 API 判断） |
| 6 | 查指标 / 看告警 | `/query` / `/alert-status` | 跳转到查询页或告警状态页 |

**设计理由**：
- 原五步到「查指标」结束，但用户核心诉求是「配置完成后看到告警」。把告警配置作为独立步骤，既补齐闭环，又能在首页给出明确的下一步动作。
- 第 6 步提供两个并行入口：查指标（`/query`）和看告警（`/alert-status`），用「主按钮 + 次按钮」或 Tab 形式呈现，避免强制跳转空页。

### 1.2 `/query` 页面：不建议复用 Prometheus UI，建议补齐自定义轻量查询页

**否定 Prometheus UI 复用的理由**已在 `dev-feedback.md` 中详细说明，核心红线：
- iframe 嵌入 Prometheus `/graph` 会绕过 M02 查询代理，破坏租户/网域注入；
- 抽取 Prometheus UI 组件成本过高且违反 upstream 隔离。

**推荐方案**：在 `ui-custom/web/src/pages/query/QueryPage.tsx` 实现一个最小可用的自定义查询页：
- 一个 PromQL 输入框（Ant Design `Input.TextArea` 或 `Input.Search`），支持执行按钮；
- 结果展示：表格（labels / value / timestamp）+ JSON 折叠区；
- 调用 M02 已上线的 `/api/v1/query` 代理接口（`src/api/query.ts` 大概率已封装，如未封装则按 M02 契约新增）。
- MVP 阶段不做复杂图表，但可以保留「未来接入图表」的占位区或提示。

**若本次不补 QueryPage**：第 6 步「查指标」应暂时隐藏或深链指向 `/targets`（目标状态页，已有数据），避免用户点击后看到空页。待 QueryPage 实现后再改回 `/query`。

### 1.3 PRD 修订建议（v1.4）

- §3.1「使用指引」改为六步，第 5 步「配置告警通知」深链 `/alert-config`，第 6 步「查指标 / 看告警」深链 `/query` 与 `/alert-status`。
- §6 验收标准同步修改：第 6 步深链正确、快速入口区增加「告警配置」快捷卡片（可选）。
- 在 `design-decisions.md` 登记「决策 72-1：使用指引扩展为六步闭环，QueryPage 走自定义实现」。

## 反馈 2 设计意见：Dashboard 概览应更具「概览感」

当前实现偏向「功能入口聚合页」，Dashboard 感不足。在不引入后端改动、不引入图表库（ECharts/AntV）的前提下，可通过以下信息架构与视觉调整提升概览感。

### 2.1 推荐首页布局（自上而下）

```
┌─────────────────────────────────────────────────────────────┐
│  页面标题区                                                   │
│  MetricCenter 概览  |  欢迎回到 MetricCenter，当前 default 网域运行正常  │
├─────────────────────────────────────────────────────────────┤
│  第一行：关键指标卡（2 × 3 或 3 × 2 网格）                     │
│  [资源总数] [已监控] [采集 Job] [活跃告警] [网域数量] [待确认草稿] │
├─────────────────────────────────────────────────────────────┤
│  第二行：告警治理态大卡片（左 40%）+ 最近下发 / 快捷入口（右 60%）│
│  ┌──────────────┐  ┌──────────────────────────────────────┐  │
│  │  通知中  3   │  │  系统快速入口（5 卡片网格）            │  │
│  │  已静默  1   │  └──────────────────────────────────────┘  │
│  │  已抑制  0   │  ┌──────────────────────────────────────┐  │
│  │  firing 2 / pending 1                     │  最近下发 5 条（带状态色点）           │  │
│  └──────────────┘  └──────────────────────────────────────┘  │
├─────────────────────────────────────────────────────────────┤
│  第三行：新用户指引（六步 Steps，横向或垂直均可）              │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 关键设计点

- **标题区**：增加「MetricCenter 概览」大标题 + 副标题，明确用户当前位置，避免页面看起来像零散卡片的堆砌。
- **指标卡统一规格**：
  - 图标 + 数字 + 标签，三行纵向居中；
  - 图标尺寸统一 32px，颜色按语义（资源蓝、成功绿、告警红、网域橙）；
  - 卡片高度一致，hover 态轻微上移 + 阴影加深。
- **告警治理态大卡片**：
  - 左侧色条（红色表示告警），主数字「通知中」放大显示；
  - 下方分三行显示已静默 / 已抑制 / Prom firing / pending；
  - 底部加「查看告警中心 →」深链。
  - 空态：显示「尚未挂载通知配置，去配置 →」引导按钮（红色描边按钮或链接）。
- **快捷入口**：
  - 由当前文字链/列表改为**图标卡片网格**（2 × 3 或 3 × 2），每个入口含图标、名称、一句描述，hover 有边框高亮。
- **最近下发**：
  - 表格精简为 3 列：变更单号 / 网域 / 状态 + 时间；
  - 状态用色点 + 文字，避免大段灰色文字。
- **新用户指引**：
  - 用 Ant Design `Steps` 组件横向展示六步，当前未完成的步骤用灰色，已完成的有对勾图标；
  - 每步标题可点击跳转；
  - 增加一句引导文案：「按以下步骤完成首次监控闭环，大约需要 5 分钟」。

### 2.3 可进一步提升 Dashboard 感（可选，仍在零后端改动范围内）

- **采集覆盖率迷你卡**：在关键指标卡下方增加一行「覆盖率」展示：
  - `已监控资源 / 资源总数`，用进度条或环形图占位（可用 Ant Design `Progress`，无需 ECharts）。
  - 数据来自 `dashboard/summary.resource_count` 与 M01 提供的「已监控」计数；若 M01 未提供该数字，可延后到 v0.3。
- **最近告警 mini 列表**：在告警治理态卡片下方或右侧展示最近 3 条告警名称 + 时间，数据来自 `/api/v1/alerts`，零后端改动。

### 2.4 PRD 修订建议（v1.4）

- §3.1「页面结构」按上述布局更新。
- §3.1 新增「Dashboard 视觉层级」小节：标题区 → 关键指标 → 告警治理 → 快捷入口/最近下发 → 使用指引。
- §6 验收标准补充：指标卡网格、告警治理态大卡片、快捷入口图标网格、使用指引 Steps 组件。

## 反馈 3 设计意见：整体样式与排版应更美观

### 3.1 当前问题诊断

- **色彩过碎**：图标、按钮、Tag 使用了多种高饱和色（青/绿/蓝/橙/紫/红），缺乏主色统领，显得花哨。
- **间距不统一**：卡片之间、区块之间、文字与图标之间间距不一致，视觉节奏松散。
- **字体层级弱**：标题、数字、辅助说明字号/字重区分不够，重点不突出。
- **卡片风格平淡**：白底 + 细边框，缺乏企业级 Dashboard 的精致感。

### 3.2 视觉 Token 规范建议（可直接用于生产调整）

沿用原型 `theme.ts` 中的 Volcengine Token，但对首页做收敛：

| 元素 | 规范 |
|------|------|
| 页面背景 | `colorBgBase: #F7F8FA`（全局已配置，保持） |
| 卡片背景 | `colorBgContainer: #FFFFFF`，圆角 `borderRadius: 8`（比当前 6 略大，更柔和） |
| 卡片阴影 | 默认 `box-shadow: 0 1px 2px rgba(0,0,0,0.06)`；hover 态 `0 4px 12px rgba(0,0,0,0.08)` |
| 主色使用 | 品牌青 `#0ECDEB` 仅用于主按钮、关键图标、链接；避免每个卡片图标都用不同色 |
| 功能色使用 | 成功绿、告警红、警告橙仅用于状态/语义，不用于装饰性图标 |
| 图标尺寸 | 快捷入口图标 40px，指标卡图标 32px，统一使用 `@ant-design/icons` |
| 间距体系 | 页面内边距 24px；卡片 gutter 16px；卡片内边距 20px；标题与内容间距 12px |
| 字体层级 | 页面标题 `Title level={3}` 24px/600；区块标题 `Title level={5}` 16px/600；数字 `24px/700`；辅助说明 `14px/400 colorTextSecondary` |

### 3.3 排版收敛建议

- **减少色块数量**：指标卡图标统一使用品牌青 `#0ECDEB` 或中性灰，只有「告警」卡片使用红色；状态信息用 Tag/Badge 表达语义，不用彩色图标。
- **卡片标题规范**：所有卡片必须有标题，标题左对齐，右侧可放「查看更多」链接；避免卡片内再嵌套小标题。
- **对齐基线**：所有卡片顶部对齐，同一行卡片高度一致；使用 Ant Design `Row gutter={[16, 16]}` 统一间距。
- **空态统一**：统一使用 `Empty` 组件或自定义空态插图 + 引导文案，避免「暂无数据」灰色小字散放。

### 3.4 原型更新建议

- 在 `docs/prototypes/module-05/src/pages/DashboardPage.tsx` 中按上述规范调整布局与视觉，作为生产实现的主要参考。
- 更新 `docs/prototypes/module-05/src/pages/UsageGuidePage.tsx` 为六步指引。
- 原型版本从 `0.1.0` 提升到 `1.2.0`（与 PRD v1.4 对齐，或先出 `1.2.0-draft`）。
