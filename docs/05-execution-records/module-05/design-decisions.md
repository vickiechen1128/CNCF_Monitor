## 补充对齐：2026-08-31（Grafana 集成三层归属与用户自由度边界，决策 51）

- **触发**：MVP 收口评估确认「可视化大屏」缺口走 Grafana iframe 嵌入（决策 50，全文见 module-02 design-decisions）；需明确嵌入能力的模块归属与控制面边界。
- **结论（决策 51）**：Grafana 集成按三层归属——
  1. **M05（本模块）**：门户嵌入入口（「监控大屏」页 iframe）、新用户引导操作指南（登记网域 → 导入资源 → 建采集 Job → 下发 → 查指标）、预置仪表盘模板展示与「配置告警」深链回 M08；首页轻量实时图表用 ECharts/AntV 消费 M02 `query_range`；
  2. **一体化交付包**：Grafana 自身配置（datasource 指向 M02 查询代理、anonymous/auth、provisioning 目录、预置模板文件）安装期静态下发，不进运行态模块；
  3. **M11 预留**：Dashboard-as-Code 治理（API 管 dashboard、版本化、按租户分发）v0.4+ 评估，v0.3 不实现。
- **自由度边界**：控制面只守两条线——数据源红线（必须指向 M02 代理，禁止直连 Prometheus）不可改；预置模板只读（升级覆盖，用户克隆后自由编辑）。不锁 Grafana UI，用户自建业务面板完全自由。
- **版面引导**：预置模板按平台治理标签组织下钻层级——网域（`network_domain`）→ 业务（`biz`）→ 应用（`app`）→ 实例（`resource_id`/`instance`），dashboard variables 的 `label_values()` 查询走 M02 代理。
- **告警不引向 Grafana**：告警规则与通知配置由 M01/M08/M09 承接（决策 49，全文见 module-08 design-decisions），大屏页提供深链衔接动线。
- **影响范围**：Module_05 PRD v1.2（§1 / §3 / §3.1 新增交互契约 / §4 / §6）；Module_02 PRD v1.6（可视化边界三层归属交叉引用）。
- **关联决策**：决策 50（可视化方案收敛）；决策 52（网域「消费隐藏」——看板默认不感知网域）。

- **触发**：用户要求在 MVP 完善首页——系统快速入口、使用指引、告警状态数字；明确不做可视化大屏（v0.3 豁免大屏快捷入口）。DeepSeek 方案经 Orchestrator 事实核查修正后确认（核查要点：决策 68-2 已落地，`alerting:` 段在 AM 配置挂载后自动生成，「AM 通知数字恒为 0」风险已消除，残余前置条件转化为空态引导）。

  2. **告警数字实现路径（方案 A）**：前端直调既有只读接口取数组长度计数（`GET /api/v1/alerts`、`GET /api/v2/platform/alertmanager/alerts`，均无分页，`alertStatusApi` 已封装），**零后端改动**；`platform/dashboard/summary` 保持纯 GORM 聚合单一职责，不引入 Prometheus 代理调用（否决方案 B）。

  4. **配套项**：`QueryPage` 挂入 `/query` 路由，使用指引第 5 步「查指标」深链落地（否决暂指 `/targets`——targets 是排障入口而非查询入口）。
  5. **联动预留**：若后续采纳「告警中心（治理视图） vs 触发排障」拆菜单方案，首页告警卡跳转目标指向治理视图，设计提案层对齐避免二次改动。
- **影响范围**：Module_05 PRD v1.3（头部 / §1 / §3 首页行 / §3.1 新增交互契约 / §6 验收）；前端 HomePage 重构 + App.tsx 挂 `/query` 路由 + HomePage.test.tsx 同步；`02_Product_Roadmap.md` §1.5 M05 行 MVP 列同步。
- **关联决策**：决策 51（可视化三层归属与大屏导航，v0.3 部分不变）；决策 68-2（Prometheus→AM 投递接线，空态引导的依据）。

## 决策登记：2026-09-14（首页 MVP 子集设计补丁，决策 72-1 / 72-2）

- **触发**：产品负责人在 `feat/module-05-homepage-mvp` 代码审查后提出三点设计意见（详见 `dev-feedback.md` 与 `design-proposals/homepage-mvp-feedback-design-opinion.md`），并书面确认采用设计意见。
- **结论（决策 72-1，指引与查询页）**：
  1. 使用指引由五步扩展为六步开箱动线：登记网域 → 导入资源 → 建采集 Job → 下发 → **配置告警通知** → 查指标/看告警；第 5 步深链 `/alert-config`，第 6 步深链 `/query` 或 `/alert-status`。
  2. `QueryPage` 采用**自定义轻量实现**：PromQL 输入框 + 结果表格/JSON，调用 M02 `/api/v1/query` 代理接口；**禁止复用 Prometheus UI**（iframe 会绕过 M02 查询代理、破坏租户/网域注入；抽取组件成本过高且违反 upstream 隔离）。
- **结论（决策 72-2，视觉与信息架构）**：
  1. 首页页面结构调整为：标题区 → 关键指标卡网格（2×3）→ 告警治理态大卡片（左侧约 40%）+ 系统快速入口/最近下发（右侧）→ 六步使用指引区。
  2. 视觉 Token 规范：色彩收敛（品牌青 `#0ECDEB` 仅用于主按钮/关键图标/链接；功能色仅用于状态语义）、卡片圆角 8px、统一阴影与间距、字体层级、图标尺寸统一（快捷入口 40px / 指标卡 32px）。
- **用户确认**：2026-09-14 用户书面确认——「1.我同意 2.推荐在 QueryPage.tsx 内实现最小自定义 PromQL 查询页 3. 我同意采用 4.直接按意见让前端调整样式，同样不要做全量测试以节约token」。
- **影响范围**：Module_05 PRD v1.4（头部 / §1 / §3 首页行 / §3.1 交互契约 / §6 验收）；前端 `feat/module-05-homepage-mvp` 样式与结构精修 + QueryPage 最小实现；原型对齐顺延。
- **关联文档**：`dev-feedback.md`、`design-proposals/homepage-mvp-feedback-design-opinion.md`。

## 决策登记：2026-09-14（首页内容重构 as-built 回填，决策 72-3）

## 决策登记：2026-09-18（首页视觉密度与告警卡重构，决策 73）

- **触发**：产品负责人审阅 MVP 首页原型（v1.2.1）后提出六点反馈——①首页样式不够美观；②关键指标卡高度不够醒目；③系统快速入口版面高度太高；④告警状态卡版面留空太多；⑤用户想看到的告警数值是**当日告警数量、近 7 天告警数量**；⑥告警信息只有告警名不够，还要**告警具体内容**。用户确认「直接改 PRD 和原型即可」（豁免 design-proposal 提案文档），并追问「告警状态右侧会不会高度太空」「使用指引是否可以移到右侧」两个补充问题。
- **结论（决策 73，首页视觉密度与告警卡重构）**：
  1. **告警状态卡主数字改口径**：由 AM 治理态「通知中」改为**当日告警 / 近 7 天告警**为主数字（决策 72 第 3 条相应修订）；数据来自 M02 `GET /api/v1/alerts/history`（P0/MVP 已规划，M08 历史告警页消费中），按 `fired_at` 前端计数（当日 = 今日 0 点起、近 7 天 = `fired_at ≥ now-7d`，均含已恢复），复用决策 72 方案 A「前端直调只读接口计数」模式，**零新后端能力**。
  2. **四格统计条**：告警卡顶部数字区改为四格统计条——当日告警 / 近 7 天告警（主，24px/700）/ 通知中（红 `#FF4C3A`）/ 已静默 · 已抑制（次），格间竖分隔线，每格 Tooltip 口径注释；填满原数字区横向留白。
  3. **两行制告警列表**：最新告警列表由 10 条单行五列改为 **8 条两行制**（行 1：级别浅底 Tag + 告警名 + 相对时间 + 状态；行 2：实例名 · 告警具体内容 `summary`，12px 灰字，超长省略悬浮全文）；`LATEST_ALERT_LIMIT` 10 → 8，单条信息量翻倍，总信息量不降，「查看全部 →」兜底。
  4. **视觉 Token 修订**（决策 72-2 相应修订）：指标卡数字 24px/700 → **30px/800**（`tabular-nums`）、卡内横向排版 → **纵向排版**（标签 12px 在上、数字在中下、44px 圆角图标容器右下，内 22px 图标、品牌青 10% 浅底）；指标卡内边距 `16px 18px` → `14px 16px`；快捷入口 40px → **28px 圆角容器**（内 16px 图标）。
  5. **快捷入口压扁**：由三列大卡改为**一行五列压扁布局**（28px 图标容器 + 名称 13px/600，一句描述移入 Tooltip）。
  6. **使用指引移入右列**：自底部整行移入右列第三张卡（右列自上而下：系统快速入口 → 最近下发记录 → 使用指引），右列 ≈ 632px 与左列告警状态卡（四格统计条 + 8 条两行制）≈ 642px 高度对齐，整页高度 ~910px → ~830px，同时解决「告警状态右侧高度太空」问题。
- **跨模块待确认点**：

## 决策登记：2026-09-19（首页三层信息架构重构与拨测口径，决策 91）

- **触发**：用户以**业务经理视角**（而非工程师视角）体验 MVP 首页后提出：要按监控类型、应用名称以不同层级展示关键指标，必须体现已有资源情况与监控覆盖率，再加告警状态与使用指引；**系统快速入口与最近变更记录去掉**。追问轮次中另确认四项——「资源类型作大类、采集类型作子类方便工程师看」「子类明细避免把应用服务误解为仅 Java Spring」「右下角告警数要写明是当前未恢复」「资源类型卡铺满整行不美观需改版式」。

- **结论（决策 91，首页三层信息架构重构）**：
  1. **五段布局**：L0 全局态势（资源总数 / 已纳入监控 / 整体覆盖率 / 当前未恢复告警）→ L1 资源类型区（5 张资源类型卡 + 1 张「按应用查看」入口卡）→ L2 应用明细表（按覆盖率升序）→ 整宽告警状态卡 → 整宽使用指引一行。**移除系统快速入口区与最近下发记录表**：前者由左侧导航承接，后者仍在配置中心 `/deployments` 查阅。
  2. **大类 + 子类两级同卡呈现**：L1 按 `resource_category` 五类分组；卡内嵌「采集类型子类」明细行——主机按操作系统类型、数据库按 `database_type`、中间件按 `middleware_type`、其他监控目标按端点类型。**应用服务不设子类**：Module_01 §5.1.9 已定「平台不按语言 / 框架拆分监控对象类型」，Java Spring Boot Actuator / Go client / Python / 自研框架同归 `application_http`，形态差异用手填采集参数覆盖。子类行可点击下钻资源清单并预筛选。
  3. **拨测不计入资源台账**：Blackbox 拨测由 `job_type=blackbox` 采集任务的拨测目标列表承载，**不占资源类型、不计入「资源总数」与「整体覆盖率」的分子分母**；仅在入口卡下方附注拨测目标数与异常数。覆盖率类统计按采集任务类型区分，与 Module_01 验收口径一致。拨测告警参与「当前未恢复」计数，但因无 `resource_category` 不进任一类卡片，汇总为「不属于资源台账对象」附注。
  4. **告警数字统一为「当前未恢复」口径**：L0 第 4 卡与各资源类型卡右上角胶囊取 Prometheus 当前触发态（`GET /api/v1/alerts`），按 `resource_category` 前端分组计数——该回连键由 Module_08 v1.15 决策 70 的 `resource_identity` 链路产出，**本决策零后端改动**；零告警显示「无未恢复」。告警状态卡的「当日 / 近 7 天」保留为**历史累计口径**（含已恢复），两者并存、不互相替代。
  5. **版式**：资源类型卡由整行通栏改为 **3 列网格**（单卡 200px × 228px），第 6 格虚线入口卡填满网格避免半行留白；页面按自然文档流滚动（沿用决策 89 第 4 条撤回「整页禁下拉」的结论）。
  6. **数据供给**：概览接口新增 `by_category`（含 `by_subtype`）/ `by_app` / `unclassified_resource_count` / `unclassified_monitored_count` / `probe_target_count` / `probe_target_abnormal_count` 分组聚合字段（PRD §5.1）；L2 应用归属 {v0.2} 起统一来自应用字典，字典上线前按登记表原值聚合并在「未归类应用」行提供补填引导（应用字典见 Module_07 决策 92）。
  7. **原型同步**：原型升 **v1.4**，按三列网格版式重做首页（原型在本线内不再「零改动」——决策 88 的原型零改动结论仅适用于客户专属皮肤，首页版式属产品基础视觉，须同步）。

- **影响范围**：`Module_05_Custom_UI.md` v1.7（§3.1 / §4.2 / §5.1 / §5.2 / §6 / §9 / §10 / §11.3）；`docs/prototypes/module-05/` 原型 v1.4（含 `package.json` 提版与补缺失的 prototype README）；生产前端 `ui-custom/web/src/pages/home/` 待改造（HomePage 五段布局、告警分组、移除 QuickAccess 与下发记录表）；后端 `platform/dashboard/summary.go` 补分组聚合字段。

## 决策登记：2026-09-19（L1 五类一行与拨测态势面板，决策 93）

- **触发**：用户对 v1.7 三层首页的空态截图提出四问——①采集类型过多时如何保证版面高度一致；②拨测结果重要但只藏在附注里，是否需要独立展示面板；③「按应用查看」入口卡与紧随其后的按应用明细表信息重复，是否有必要；④其他监控目标录入 0 时能否自动隐藏。三轮样图迭代（v1→v3）后收敛定稿。

- **结论（决策 93，L1 五类一行与拨测态势面板）**：
  1. **L1 五类合并一行（修订决策 91 第 5 条的 3 列网格）**：改用 CSS grid `repeat(5, minmax(0,1fr))`（antd 24 栅格无法 5 等分）；≥1440px 视口五卡单行，窄屏回落 3+2、单列。**子类封顶 3 条**：第 4 条起聚合为「更多 +N」虚线 chip（点击同穿资源清单并带子类筛选），行高获得确定性上界、同行等高不再被子类数量拉爆；卡内数字与 chip 文案紧凑化（值右对齐、超长省略）。
  2. **删除「按应用查看」入口卡（修订决策 91 第 1 / 5 条）**：入口卡信息（应用数、覆盖率升序说明）与 L2 按应用明细表逐字重复，唯一功能是页内锚点而表格就在下一屏；L1 仅剩 5 张资源类型卡，网格无填充位。原承载于入口卡的拨测附注与「不属于资源台账对象」告警附注迁移：前者升格为拨测态势面板，后者迁至告警状态卡附注行。
  3. **页面顺序定稿（六段）**：L0 全局态势（5 卡）→ L1 按资源类型（五类一行）→ L2 按应用明细表 → L3 拨测态势面板（整宽）→ 告警状态卡 → 使用指引。台账视角（按应用）优先于补充视角（拨测）；拨测面板自带「异常排前」，下移不漏异常。
  4. **L0 扩为 5 卡（修订决策 91 第 1 条）**：新增第 5 张「拨测」卡——主数字 = 当前拨测异常数（红色语义，0 时中性色），sub「/ N 个拨测目标」，ⓘ 口径声明「走 blackbox Job，不计入资源台账」。**口径红线沿用决策 91 第 3 条**：拨测不计入资源总数与覆盖率分子分母；**不并入告警卡**——「拨测异常」与「未恢复告警」是两种口径（异常未必已产生告警），严格分离。
  5. **拨测态势面板（整宽，替代决策 91 的入口卡附注形态）**：5 列——拨测目标（URL，超长省略+悬浮全文）/ 状态（Badge：异常红 / 正常绿）/ 业务域 / 应用 / 最近拨测时间。**异常固定排最前**（浅红底行 + 红 Badge），同状态按最近拨测时间倒序；每页 5 行分页（对齐决策 89 告警列表节奏）；卡头摘要「拨测目标 N · 正常 K · 异常 M」+「拨测任务管理 →」深链。
  6. **拨测归属定则：业务域必填、应用可选**：拨测的归属链为「业务 →（可选）应用 → 端点」——异常责任分派靠业务域；官网 / 证书 / 第三方依赖 / 网络质量类拨测不属任何应用，强制挂应用必产生脏数据；应用维度可用性已由 L2 按应用明细 + `application_http` 采集覆盖，不重复承载。先例：Module_07 决策 92 中 switch / loadbalancer 设备类 `app_code` 留空。面板「应用」列可空显示 `-`，按应用筛选拨测仍可用（已挂载的才出现在筛选项）。**联动**：Module_01 blackbox 拨测目标配置承载 `biz_code`（必填）/ `app_code`（可选）归属字段；Module_07「其他监控目标」登记表单同步该必填规则。
  7. **拨测空态引导**：0 拨测目标时整卡替换为引导态（不渲染空表）——说明文案（blackbox 承载、不录入台账、登记时挂业务域）+ 主 CTA「去配置拨测任务」深链采集 Job 页。
  8. **数据供给**：`dashboard/summary` 新增 `probe_targets[]` 明细分组字段（`target_url` / `probe_status` / `biz_code` / `biz_name` / `app_code` / `app_name` / `last_probe_time`），与既有 `probe_target_count` / `probe_target_abnormal_count` 并存；`last_probe_time` 的上报口径依赖 Module_01 blackbox 探测结果回传（M01 侧字段，本模块只消费）。
  9. **空分类卡不自动隐藏**：其他监控目标 / 应用服务录入 0 时保留卡位（避免显现 / 隐藏的版面跳变，保住 L0「资源总数 = 五类之和」的表达与新用户的录入引导），空态减负——不渲染示例 chip、子类区显示「暂无录入 · 去录入 →」行动出口（深链资源导入 / 登记）。
