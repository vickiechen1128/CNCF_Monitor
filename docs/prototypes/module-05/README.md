## v1.5 变更说明（同步 PRD v1.7 → v1.8，决策 93 首页版式与拨测态势面板）

1. **L0 全局态势扩为 5 卡一行**（CSS grid `repeat(5,1fr)`，窄屏回落 3+2 / 单列）：新增第 5 张「拨测」卡——主数字 = 当前探测异常数（红色语义，0 时中性色），副行「/ N 个拨测目标 · 异常数」，ⓘ 口径声明拨测由 blackbox 承载、不计入资源台账与覆盖率；与「告警」卡口径严格分离（拨测异常未必已产生告警）。
2. **L1 资源类型五卡合并一行**（替换 v1.4 的 3 列网格 + 第 6 格入口卡）：卡内数字与子类文案紧凑化（值右对齐、超长省略）；**子类明细封顶 3 条**，第 4 条起聚合为「更多 +N」虚线品牌青 chip（点击同穿资源清单），行高有确定性上界、同行等高。
3. **删除「按应用查看」入口卡**：其信息（应用数 / 排序说明）与 L2 按应用明细表逐字重复，唯一功能是页内锚点而表格就在下一屏；拨测附注升格为拨测态势面板，「不属于资源台账对象」告警附注迁至告警状态卡。
4. **页面顺序调整为六段**：L0 全局态势 → L1 五类一行 → L2 按应用明细表 → L3 拨测态势面板（整宽）→ 告警状态卡 → 使用指引。台账视角（按应用）优先于补充视角（拨测）。
5. **新增 L3 拨测态势面板**：5 列（拨测目标 URL / 状态 / 业务域 / 应用 / 最近拨测时间）；异常固定排最前（异常行浅红底 + 红 Badge），同状态按最近拨测时间倒序（前端排序）；每页 5 行分页（对齐告警列表节奏）；卡头摘要「拨测目标 N · 正常 K · 异常 M」+「拨测任务管理 →」深链。
6. **拨测归属定则：业务域必填、应用可选**：异常责任分派靠业务域；官网 / 证书 / 第三方依赖类拨测不属任何应用，且应用可用性已由 L2 按应用明细承载——「应用」列可空显示 `-`。先例：Module_07 决策 92 设备类 `app_code` 留空。
7. **拨测空态引导**：0 拨测目标时整卡替换为引导态——说明文案 + 主 CTA「去配置拨测任务 →」深链采集 Job 页。
8. **L1 空分类不自动隐藏**：录入 0 时保留卡位（避免版面跳变），子类区显示「暂无录入 · 去录入 →」行动出口；应用服务卡不再渲染「Java Spring / Go / Python」示例 chip（空态减负）。

原型数据新增 `mockProbeTargets`（12 条拨测目标，2 条异常演示「异常排前 + 标红」，3 条应用列留空演示可空语义）；`mockProbeSummary.abnormalCount` 同步 1→2 保持 mock 自洽。

**v1.5 同版本微调（2026-09-19 走查反馈，不提版）**：①L1 区块标题「按资源类型」→「采集覆盖」，旁注申明两类口径（进度条与子类 = 采集覆盖；右上角胶囊 = 当前未恢复告警）；②L2 卡片标题「按应用」→「应用覆盖」，排序说明并入旁注；③「告警状态」与「使用指引」同排等高（左 1.6 : 右 1，使用指引改纵向六步）。**第二轮（告警两点收口）**：④L1 / L2 去「未恢复」（胶囊与列整体删除，只体现采集覆盖）；⑤「最新告警」定为当前未恢复全量 8 条（按触发时间倒序，标题旁注明与当日 / 近 7 天历史累计口径不同）；⑥告警状态卡附口径关系「当前未恢复 = 通知中 + 已静默 + 已抑制」与按角色读法（业务经理看趋势 / 运维经理看通知压力 / 运维工程师看待办）；⑦mock 修齐：alertCount 字段移除、`unrecoveredTotal` 单一来源 `promFiring`、最新告警时间戳改近期且 status 锁 3/3/2、删除未归类告警附注。**第三轮（提示分区收口）**：⑧口径公式与按角色读法从页面主体移入评审说明区（新增 `ReviewNote` / `ReviewNoteSwitch` / `ReviewNotesContext`，右上角开关统一控制、默认折叠）；⑨四格与 L0 告警卡 ⓘ tooltip 用户语言化，「最新告警」旁注收敛为「当前未恢复 · 最新的排最前」；`package.json` 新增 `check:notes` 门禁。

## v1.4 变更说明（同步 PRD v1.6 → v1.7，决策 91 首页三层信息架构重构）

1. **页面改为五段由粗到细下钻**：L0 全局态势四卡 → L1 资源类型区（三列网格）→ L2 应用明细表 → 整宽告警状态卡 → 整宽使用指引一行。业务经理先看「有多少资源、覆盖到什么程度、现在有没有告警」，工程师再看「哪一类、哪个子类、哪个应用缺监控」。
2. **L0 由 6 张资产卡收敛为 4 张**：资源总数 / 已纳入监控 / 整体覆盖率 / **当前未恢复告警**。告警数字从「告警状态卡独占」改为**按层级表达**，L0 给全平台实时口径。
3. **L1 由整行通栏改为 3 列网格（5 张资源类型卡 + 1 张入口卡）**：单卡 200×228，卡内自上而下为类型名与右上角「未恢复 N」胶囊 → 已采数与总数 → 覆盖率进度条与未采数 → 采集类型子类明细行；第 6 格为虚线「按应用查看」入口卡，填满网格不留半行空白。
4. **采集类型子类只在大类卡内展开，不另起一层页面**：主机按操作系统类型、数据库按数据库类型、中间件按中间件类型、其他监控目标按端点类型；**应用服务不列子类**——平台不按语言 / 框架拆分采集类型，Java Spring / Go / Python 同归一类，卡内明示该口径。子类行可点击下钻资源清单。
5. **告警文案统一为「未恢复」**：卡片胶囊显示「未恢复 N」，零告警时显示「无未恢复」，避免与告警状态卡的「当日 / 近 7 天」历史累计口径混淆。
6. **新增 L2 应用明细表**：应用名称（含简称）/ 业务域 / 实例 / 已采 / 覆盖率 / 未恢复 / 操作，**按覆盖率升序**（缺口最大的排最前），未标注应用归属的实例聚合为「未归类应用」行并提供「去补填」入口。
7. **拨测（Blackbox）明确不入台账**：拨测目标数与异常数在入口卡下方单独附注，不计入资源总数与覆盖率分子分母；拨测产生的告警计入「当前未恢复」但不属于任一资源类型，另作一行附注——避免演示时出现「分项加不齐」的质疑。
8. **移除系统快速入口区与最近下发记录表**：功能页入口统一走左侧导航，下发记录仍在配置中心查阅。告警列表沿用「每页 5 行」，使用指引改为整宽一行横排。

原型数据全部来自 `src/mocks/module-05.ts`：`mockResourceTypes`（五类及子类）、`mockAppSummaries` + `mockUnclassifiedResource`（L2）、`mockProbeSummary` 与 `mockUnclassifiedAlertCount`（拨测与不属于台账对象的告警）为 v1.4 新增。
