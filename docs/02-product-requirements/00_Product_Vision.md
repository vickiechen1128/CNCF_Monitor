## 1. 产品定位

**MetricCenter** 是基于 Prometheus 开源生态构建的**企业级指标采集与查询中心**，采用**控制面（Control Plane）与数据面（Data Plane）分离**的架构：

- **控制面（MetricCenter）**：负责资源管理、采集规则下发、配置生命周期管理、门户化查询。
- **数据面（Prometheus 生态）**：Prometheus 负责抓取/存储/查询/告警求值，Blackbox Exporter 负责拨测，Alertmanager 负责告警收敛与通知。

> **核心原则**：不硬 Fork Prometheus，以 Prometheus 为数据面引擎，在其上构建企业级控制面。所有二次开发代码与上游源码隔离。

---

## 2. 核心价值

| 价值点 | 说明 |
|--------|------|
| **降低 Prometheus 使用门槛** | 通过门户化 UI 和预置模板，让非专家用户也能管理采集目标和查询指标 |
| **统一采集管理** | 集中管理主机、中间件、应用服务的采集配置与拨测 |
| **可演进架构** | 与 Prometheus 源码隔离，便于跟进上游版本升级；未来可对接外部 CMDB 和长期存储 |
| **数据面能力复用** | 充分利用 Prometheus、Blackbox Exporter、Alertmanager 的原生能力，避免重复造轮子 |

## 4. 产品边界

### 4.1 包含范围

- 三类资源管理：主机、中间件、应用服务
- 采集配置管理：采集 Job、标签模板、采集模板、拨测配置
- 配置生成与下发：`prometheus.yml` 生成、校验、reload
- 指标查询门户：PromQL 查询代理与结果展示
- 采集状态查看：Target 状态、拨测结果

### 4.2 不包含范围（MVP）

- 动态资源模型与自定义字段扩展
- 告警规则编辑 UI（MVP 手写 `rules.yml`）
- 告警收敛/静默/通知管理 UI（MVP 借助 Alertmanager 原生能力）
- 复杂 Dashboard 编辑器
- 多租户与权限控制
- 外部长期时序存储（Remote Write 仅做架构预留）
- 日志与链路追踪

## 6. 控制面与数据面分层

MetricCenter 在 Prometheus 生态之上构建控制面，详细架构见 [00_Global_Architecture.md](00_Global_Architecture.md)。

核心边界：

| 职责 | 控制面（MetricCenter） | 数据面（Prometheus 生态） |
|------|------------------------|---------------------------|
| 资源管理 | ✅ | ❌ |
| 采集规则下发 | ✅ | ❌ |
| 标签模板与字段映射 | ✅ | ❌ |
| 指标抓取 / 时序存储 / PromQL | ❌（可代理） | ✅ |
| 告警规则求值 | ❌（MVP 阶段） | ✅ |
| 拨测执行 | ❌（生成配置） | ✅（Blackbox Exporter） |
| 告警收敛 / 静默 / 通知 | ❌（MVP 阶段） | ✅（Alertmanager） |

## 7. 演进路径（摘要）

详细里程碑与技术演进见 [02_Product_Roadmap.md](02_Product_Roadmap.md)，实施难度分析见 [04_Implementation_Map.md](04_Implementation_Map.md)。

- **MVP**：三类资源管理 + 标签模板 + 采集 Job + 拨测 + 配置下发 + 指标查询
- **v0.3 ~ v0.4**：查询门户、告警状态查看、Open API、外部 CMDB 接入预研
- **v1.0 及以后**：告警规则 UI、Alertmanager 配置生成、多租户、长期存储
