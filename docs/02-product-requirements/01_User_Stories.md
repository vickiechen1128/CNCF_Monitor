## 1. 角色定义

| 角色 ID | 角色名 | 说明 |
|---------|--------|------|
| OPS | 运维工程师 | 日常监控、接入目标、查看指标 |
| ARCH | 运维架构师 | 平台规划、租户管理、数据策略 |
| AI-DEV | AI 应用开发工程师 | 消费指标数据、开发 AIOps 应用 |
| DEV | 业务研发工程师 | 查看自身服务指标、自助查询 |

## 4. 模块级用户故事扩展

> **编码规则（v1.24 固化，防跨模块冲突）**：产品级用户故事（OPS / ARCH / AI / DEV）由本文件统一维护；**模块 PRD 细化的用户故事使用模块命名空间编码 `Mxx-ROLE-NN`**（如 `M09-OPS-11`），**全局唯一**，禁止复用产品级编码但语义不同（历史上 Module_01 曾把 OPS-01 用作「选 Exporter 模板」、Module_02/08 把 OPS-07 用作「查看告警状态」，与产品级 OPS-01「查看采集目标状态」等冲突，已按本规则修正）。新故事必须先注册到本表，模块 PRD 第 2 章只引用编码 + 一句话摘要。

### 4.1 Module_01 监控策略与指标管理

| 故事 ID | 角色 | 我希望 | 以便于 |
|---------|------|--------|--------|
| M01-OPS-01 | 运维工程师 | 为指定 CI 类型（host / mysql / redis 等）维护默认采集配置（默认采集器 + 参数 + 安装指南预设，{v3.8} 入口在「采集 Job」页折叠区；原「Exporter 模板」） | 采集配置标准化 |
| M01-OPS-02 | 运维工程师 | 基于 CI 类型与默认采集器创建 ScrapeJob，选择归属网域并配置抓取参数（采集参数可手填覆盖） | 快速建立采集任务 |
| M01-OPS-03 | 运维工程师 | MVP 手动勾选需要纳入 ScrapeJob 的实例 | 精确控制采集范围 |
| M01-OPS-04 | 运维工程师 | 确认目标实例上 Exporter 已安装 / 已注册 | 避免生成大量 down 目标 |
| M01-OPS-05 | 运维工程师 | 查看并维护指标库（counter/gauge/histogram/summary、HELP、UNIT） | 为规则编写提供指标提示 |
| M01-OPS-06 | 运维工程师 | 使用类 YAML 表单编辑告警 / 记录规则，获得 PromQL 校验与指标实时预览（v0.3） | 降低规则编写门槛 |
| M01-OPS-07 | 运维工程师 | v0.2+ 通过服务发现（K8s / Nacos 等）自动接入动态实例（微服务扩缩容），无需手动勾选 | 动态实例自动纳入采集，实例漂移无感 |
| M01-BIZ-01 | 业务负责人 | 在业务指标库登记业务指标（名称 / 语义 / 阈值 / 所属业务域 / 负责人） | 把业务监控诉求明确传递给运维，避免职责断开 |
| M01-BIZ-02 | 业务负责人 | v0.2+ 按业务域查看业务指标健康度（成功率 / 交易量等，业务看板） | 业务侧自主掌握业务健康度，不依赖运维逐项解释 |
| M01-BIZ-03 | 运维工程师 | 接业务负责人工单后代登记业务指标（owner 必填指向业务负责人），代办后请业务负责人确认语义 | 业务人员不熟悉平台时由运维代录，语义所有权不丢失 |
| M01-ARCH-01 | 运维架构师 | 在 Module_07 资源列表按「未监控」筛选出未被任一 Job 采集的实例（`is_monitored` 由 M01 维护、M07 只读映射；候选人 offline 置灰不可选） | 快速发现未被采集的实例 |
| M01-ARCH-02 | 运维架构师 | v0.4+ 基于外部 CMDB 自动发现实例并推荐监控策略 | 减少人工配置 |
| M01-ARCH-03 | 运维架构师 | v1.0 与 ITIL 流程结合，在变更窗口中自动校验监控策略覆盖率 | 保障监控完整性 |
