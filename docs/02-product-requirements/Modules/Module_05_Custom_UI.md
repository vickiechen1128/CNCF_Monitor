## 1. 模块目标

> 决策依据：design-decisions.md（决策 72 / 72-1 / 72-2 / 72-3 / 73 / 91 / 93 / 100 / 102 / 103）

提供门户化的 Web 界面，替代原生 Prometheus UI，让非专家用户也能轻松使用指标查询与采集管理功能。本模块为前端页面组织与交互设计层，不重新定义后端能力边界，所有业务规则以后端模块 PRD 为准。

**核心职责**：

1. **首页概览**：平台默认落地页，总览资源分布、纳管完成率、采集健康、拨测态势与告警状态。
2. **资源与标签界面**：资源维护、Excel 导入、监控标签编辑与标签模板配置。
3. **采集配置界面**：CI 类型 ↔ 采集器映射、采集 Job、实例选择与拨测配置。
4. **下发与回滚界面**：配置预览、diff 对比、人工确认下发与版本回滚。
5. **查询与告警查看**：自定义表达式查询页、告警状态页。
6. **可视化大屏**：Grafana iframe 嵌入的监控大屏入口（{v0.3}）。

**MVP 边界**：

| 范围 | 内容 | 承接 |
|------|------|------|
| 做 | 首页概览：资源分布 / 纳管完成率 / 采集健康 / 拨测态势 / 告警状态 / 使用指引 | 本模块 |
| 做 | 资源管理、标签模板、CI-Exporter 映射、采集 Job、下发确认、查询页、告警状态页界面 | 本模块（业务规则由 M01 / M07 / M08 / M09 PRD 承载） |
| 不做 | Dashboard 面板编辑器、轻量实时图表、「进入可视化大屏」快捷入口 | {v0.3} 起 Grafana iframe 与概览升级承载 |
| 不做 | 后端业务规则与数据契约 | M01 / M02 / M07 / M08 等后端模块 PRD |

各页面布局、交互规则与状态处理统一见 §11；告警数据流见 §4.2。

## 4. 核心流程

### 4.1 首页开箱动线（六步引导流程）

平台落地页面向新用户的连续开箱动线：

登记网域 → 导入资源 → 建采集 Job → 下发配置 → 配置告警通知 → 查指标 / 看告警。

- 每步需配置深链与完成态标识。
- 第 5 步「配置告警通知」深链 `/alert-config`；第 6 步「查指标 / 看告警」深链 `/query` 自定义查询页或 `/alert-status`。
- 配套项：`QueryPage` 组件挂入 `/query` 路由并补齐最小 PromQL 查询能力（输入框 + 结果表格/JSON，调用 M02 `/api/v1/query` 代理，不复用 Prometheus UI）。

### 4.2 告警状态卡数据流与服务降级

首页告警数据来自三个只读接口：`/api/v1/alerts`（Prometheus 当前触发告警，承载「当前未恢复」计数与「最新告警」列表）、`/api/v2/platform/alertmanager/alerts`（AM 通知四态）与 `/api/v1/alerts/history`（M02 历史告警，当日 / 近 7 天计数与列表行 2 告警内容）。

- **当前未恢复计数**：取 `/api/v1/alerts` 中当前处于触发态的条目，总条数即「最新告警」列表的数据池总量（含已静默 / 已抑制）；无 `resource_category` 的条目（拨测目标、聚合规则、用户自写规则）并入总数。「最新告警」列表取同接口按触发时间倒序的全量 8 条。口径关系：**当前未恢复 = 通知中（AM `active`）+ 已静默 + 已抑制**——静默 / 抑制的告警仍处于触发态、只是暂缓通知，不等于恢复；当日 / 近 7 天为历史累计（含已恢复），两者时间范畴不同、并存不互替。
- **主数字（告警状态卡）**：当日告警 / 近 7 天告警（按 `fired_at` 计数，含已恢复；「近 7 天」取服务端返回的窗口总量，取数窗口为整 7 天、步长由服务端按窗口兜底并在响应回显）；AM 治理态「通知中」（`active`，红色语义）与「已静默 · 已抑制」为次级数字；Prom 求值态仅作 11px 灰字参考行（求值中），不作行动对象。
- **`unprocessed` 裁剪**：不计数、不进列表；仅当 N>0 时显示一行 11px 灰字「另有 N 条告警仍在计算通知状态」。
- **空态引导**：未挂载 AM 通知配置时 `alerting:` 段不生成，AM 数字恒为 0——此时卡片展示「尚未挂载通知配置，去配置 →」深链 `/alert-config`。
- **服务降级**：取数失败时对应数字显示 `-`（不显示 0）；AM / Prom / history 三条链路各自独立降级，单链路失败 warning 局部降级、双链路失败 error + 重试；当前未恢复链路失败时「最新告警」列表降级为 `-`（列表区展示「取数失败，暂无法展示最新告警」）。

### 4.3 导航层级与访问流

- **一级导航**：首页（默认落地页，第 1 位）、「可视化大屏」（第 2 位一级菜单）；其余功能模块按既定顺序排列。一级菜单名使用「可视化大屏」，自带「可视化」关键词、便于新用户发现。
- **首页子菜单**：仅保留「概览 Dashboard」（默认 Tab）与「使用引导」两个子页，不在首页下重复挂载「可视化大屏」。
- **首页 → 大屏快捷入口**：概览 Dashboard 顶部首屏视觉焦点提供「进入可视化大屏」大卡片 / 主按钮，作为一级菜单之外的第二入口（MVP 阶段不提供此快捷入口，v0.3 提供）。
- **大屏全屏动线**：进入可视化大屏后提供全屏 / 退出全屏按钮，适配投屏 / 电视墙场景；全屏模式隐藏门户侧边栏与顶部导航，iframe 铺满可视区域。

### 4.4 技术选型

- 前端框架：React 18 + TypeScript；构建工具：Vite；UI 组件库：Ant Design 5.x。
- 状态管理：React Query（服务端状态）+ Zustand（客户端状态）；HTTP 客户端：Fetch / Axios。
- 图表：MVP 阶段仅简单折线（ECharts 轻量版）；v0.3 起轻量实时图表用 ECharts / AntV（消费 Module_02 `query_range`）。
- 可视化大屏（v0.3）：Grafana iframe 嵌入，datasource / 预置模板经一体化交付包 provisioning 静态下发；门户仅承载入口、引导与深链。

## 5. 数据模型

### 5.1 首页概览数据模型（dashboard summary 响应字段）

首页各层级卡片与明细表由平台概览接口的**计数字段**与**分组聚合字段**共同驱动；分组聚合字段为门户侧新增（向后兼容，既有字段语义不变）。

| 字段 | 类型 | 必填 | UI 展示名 | 说明 |
|------|------|------|-----------|------|
| resource_count | int | ✅ | 资源总数 | M07 六类资源表行数之和（host / database / middleware / application / interface\_service / generic\_target；接口服务为拨测目标承载资源、随资源计入——F-29）；空库返回 0 |
| monitored_count | int | ✅ | 已纳入监控 | 被 ≥1 个 `enabled=true` 且 `draft_status='ready'` 且 `job_type=standard` 的采集 Job 覆盖的资源数（去重）；`monitored_count ≤ resource_count`，软删资源不计入 |
| scrape_job_count | int | ✅ | 采集 Job | 未软删 ScrapeJob 总数 |
| scrape_job_enabled_count | int | ✅ | 启用 Job | 其中 `enabled=true` 数 |
| domain_count | int | ✅ | 已纳管网域 | `is_monitored=true` 网域数 |
| pending_draft_count | int | ✅ | 待确认草稿 | `status=pending` 配置草稿数 |
| by_category | array | ✅ | 仅技术信息 | 按 `resource_category` 分组的资源分布，驱动纳管完成率卡的六行资源类型表；每项含 `resource_category` / `resource_count` / `monitored_count` / `coverage_rate`。**不含告警数**——本接口不承担任何告警计数 |
| by_category[].by_subtype | array | ✅ | 仅技术信息 | 类型内子类明细；每项含 `subtype` / `resource_count` / `monitored_count` / `coverage_rate`。子类键：主机取操作系统类型、数据库取 `database_type`、中间件取 `middleware_type`、其他监控目标取端点类型；**应用服务为空数组**。**首页当前不消费**（契约保留，供后续版本与大屏使用） |
| by_app | array | ✅ | 仅技术信息 | 按应用归属分组的资源分布；每项含 `app_code` / `app_name` / `biz_code` / `resource_count` / `monitored_count` / `coverage_rate`。**首页当前不消费**（契约保留）。**不含告警数** |
| by_platform_app | array | ❓ | 仅技术信息 | 平台 × 应用二维主机计数矩阵，驱动资源分布行右侧「平台与应用的主机分布」；每项含 `platform_code` / `platform_name`（字典缺条目回落为编码）/ `host_count` / `cells[]`（每格含 `app_code` / `app_name` / `host_count`）。**本期仅 host**；不变量 `sum(行) == sum(列) == by_category[host].resource_count`；行列排序与「其他 / 未指定平台」收口规则见 §11.3。**不含告警数**；缺失时前端渲染不可用态（绝不渲染全 0 矩阵） |
| collection_health | object | ❓ | 仅技术信息 | 首页采集健康面板三值：`dispatched_count`（分母＝已配置采集任务的资源数）/ `collecting_count`（采集中=5 分钟内 `up==1`）/ `down_count`（已下发未采到＝其余情形：`up==0`、待首次抓取、回传延迟等）；不变量 `dispatched_count === collecting_count + down_count`；「未监控」不在其中（归纳管完成率口径）。**不含告警数**；缺失时前端渲染「采集健康数据暂不可用」（不显示 0） |
| by_cloud | array | ✅ | 仅技术信息 | 按云归属分组的主机计数，驱动资源分布行左侧「不同云的主机数量」；每项含 `cloud_code` / `cloud_name` / `resource_count` / `monitored_count` / `coverage_rate`。**本期仅 host**——`cloud` 经资源所属网域 `cloud_code` 派生（网域 `cloud_code` 必填、零空洞，见 Module_06 §5.2）；其余四类资源暂不参与按云聚合。**不含告警数**（同上） |
| unclassified_resource_count | int | ✅ | 未归类实例 | 未标注应用归属的资源数。**首页当前不消费**（契约保留） |
| unclassified_monitored_count | int | ✅ | 未归类已采实例 | 上项中已被采集任务覆盖的资源数。**首页当前不消费**（契约保留） |
| probe_target_count | int | ✅ | 拨测目标数 | `job_type=blackbox` 采集 Job 的拨测目标总数；目标即所选 `interface_service` / `application` 资源实例（地址按派生 `target_field` 填充，F-29），随资源计入 `resource_count` 并计入已监控口径 |
| probe_target_abnormal_count | int | ✅ | 拨测异常数 | 当前探测失败的拨测目标数 |
| probe_targets | array | ✅ | 仅技术信息 | 拨测目标全量明细，驱动拨测单卡分区计数（接口服务 / 应用服务各 2×2 计数）；每项含 `url` / `status`（`up` / `down` / 无样本为未知）/ `network_domain_id` / `network_domain_name`（可空）/ `last_probe_at`。**目标来源（F-29）**：`url` 由 blackbox Job 所选资源类别派生字段填充（接口服务 `api_url` / 应用服务 `health_check_url`），非手工维护列表；业务域 / 应用归属随所选资源携带（业务资产口径），网域仍为拓扑主视图维度；首页当前仅消费聚合计数（`network_domain_id` 等明细字段不消费，后端契约不变） |

- **纳管完成率卡**消费 `by_category` 与 `resource_count` / `monitored_count`：整体纳管率分子分母为 `monitored_count` ÷ `resource_count`（资源总数与已监控口径按 M01 F-29 统一——拨测资源模式的选择计入已监控，接口服务资源计入资源总数）；六行资源类型表消费 `by_category` 各类计数；五类 `resource_count` 之和等于 `resource_count`。
- **资源分布行**消费 `by_cloud`（左窄列）与 `by_platform_app`（右矩阵），两者本期均仅 host 且各自不含告警数字；矩阵不变量与排序收口规则见 §11.3。
- **采集健康面板**消费 `collection_health` 三值；分母＝`dispatched_count`（已配置采集任务的资源数，与纳管完成率分子同口径）；不变量 `dispatched_count === collecting_count + down_count`；字段缺失渲染「采集健康数据暂不可用」而非 0。「未监控」资源归属纳管完成率面板（未配置采集列），不进采集健康面板；M01 采集 Job 列表 / 详情保留含状态上下文的四态口径（有 `change_status` 上下文），本两态仅约束首页采集健康面板。
- **拨测单卡**消费 `probe_targets` 聚合计数（拨测目标 / 正常 / 异常 / 未知；未知＝`status` 为空的中性色）；`last_probe_at` / `network_domain_name` 等明细字段首页当前不消费（后端契约不变）。全空态「暂无拨测目标」。
- **告警计数归属**：首页告警数字唯一收口在告警状态卡（由 `/api/v1/alerts` 条目数与 history 计数得到），首页其余区块不展示告警数字；`dashboard/summary` 的计数字段与分组字段**均不含告警字段**。
- **拨测计费边界**：拨测目标不属于 M07 资源台账对象——不计入资源总数与纳管完成率的分子分母、不在资源分布行占位；拨测目标的探测状态统计由拨测单卡承载（与标准采集的采集健康分列）；拨测告警并入告警状态卡「当日 / 近 7 天」等告警口径。

## 8. 数据模型状态机

### 8.1 首页概览数据加载状态（服务降级）

首页概览数据由多条链路聚合，单条链路失败仅局部降级、不阻塞整体页面。

```mermaid
stateDiagram-v2
    [*] --> loading: 进入首页
    loading --> success: 双链路数据就绪
    loading --> degraded: 单链路失败
    degraded --> success: 另一链路恢复 / 重试成功
    degraded --> error: 另一链路也失败
    loading --> error: 双链路失败
    error --> retrying: 手动重试
    retrying --> success: 重试成功
    retrying --> error: 仍失败
    success --> [*]
```

- success＝正常展示；degraded＝warning 局部降级（失败卡片显示 `-`，不显示 0）；error＝error + 重试。
- 点击各卡片 / 列表的「查看全部 →」从降级态可直达对应功能页。

| 未配置采集 | 尚未被任何标准采集任务覆盖的资源数（含「未采集 / 未监控」资源的统计归属）；文案正名自「未下发」 |
| 采集健康 | 首页两态面板：采集中（5 分钟内 `up==1`）/ 已下发未采到（`up==0`、待首次抓取、回传延迟等其余情形）；不变量 已下发 = 采集中 + 已下发未采到 |

| 当日告警 | 今日 0 点起触发过的告警条数（含已恢复），按历史告警接口的触发时间计数，告警状态卡主数字之一 |
| 近 7 天告警 | 近 7 天内触发过的告警条数（含已恢复），取服务端返回的窗口总量，告警状态卡主数字之一 |

- 一级导航第 1 位固定「首页」，第 2 位「可视化大屏」（v0.3）。

- 首页概览数据按多链路聚合加载，单链路失败仅局部降级；加载失败显示 `-` 并支持重试。
- 告警信息唯一收口在告警状态卡（当日 / 近 7 天 / 通知中 / 已静默·已抑制统计块 +「最新告警」明细），首页其余区块不展示告警数字。
- 提示分区（三受众人）：用户可见文案讲人话、不含「决策 X / PRD X.X / {vX.Y}」等实现层引用；口径公式、按角色读法、决策清单等**评审释义**统一收进原型评审说明区（ReviewNote，默认折叠，右上角开关统一控制显隐）；实现细节进代码注释与 PRD 技术层。
- 视觉 Token（默认皮肤「火山青」）：品牌青 `#0ECDEB` 仅用于主按钮 / 关键图标 / 链接；功能色（成功绿 / 告警红 / 警告橙）仅用于状态语义，不用于装饰性图标；告警红色语义收敛到告警状态卡统计块与「最新告警」列表，纳管率低于 70% 的行用橙色警示。客户专属配色由皮肤机制在运行时整体替换 token 承载，实现禁止在模块顶层快照色值；皮肤开关位于「系统与平台管理 · 外观设置」。
- 视觉规格：卡片圆角 8px（资源类型卡 12px）、默认阴影 `0 1px 2px rgba(0,0,0,0.06)`、hover 阴影 `0 4px 12px rgba(0,0,0,0.08)`；页面内边距 24px、卡片间距 16px；数字统一等宽字体；首页按自然文档流滚动，不强制压缩至单屏。
- 首页字号阶梯（6 级）：hero 24/600 仅用于纳管完成率与拨测正常率两处圆环中心；primary 20/600 用于告警统计四格主数字；title 16/600 用于卡标题、行级计数与空态标题；label 13/500；body 12/400（含表头）；note 11/400。数字一律 600 字重，700 字重仅用于「合计」一词；行级计数一律 16 号。

### 11.3 概览 Dashboard 页

**用户任务**：一屏看清纳入了多少监控资源、还有多少没配置采集、已配置的是否正常采到、拨测端点是否可用，以及告警状态如何；并按使用指引进入对应模块补齐缺口。

入口与路径：落地页 / 一级导航「首页」首屏；侧边栏子 Tab「概览 Dashboard」默认选中。

布局与列设计：自上而下五段首屏，层级由粗到细——
1. 页头行：左侧引导语，右侧「隐藏资源分布 / 显示资源分布」开关；隐藏时资源分布整行不渲染，偏好记忆在本地浏览器。
2. 资源分布行：左窄列「不同云的主机数量」紧凑统计卡（每云一行云名 + 台数右对齐，末行「合计」，本期仅主机）；右侧「平台与应用的主机分布」矩阵，行取主机数最多的 4 个平台单独成行，并列按平台编码字典序，落选平台合并为「其他」行（仅真的有落选时出现），「未指定平台」恒单独末行不占名额，输出序固定 Top4 → 其他 → 未指定平台。
3. 中段对分等高：左卡「纳管完成率」是全页唯一的纳管率呈现点——左侧百分比圆环（圆心下两行「整体纳管完成率」「已配置 N / 共 M」）+ 右侧资源类型六行表（资源类型 / 已配置采集 / 总数 / 纳管率 / 未配置采集），纳管率低于 70% 的行橙色警示，卡底脚注说明只反映配置进度、不代表数据已采到；右卡「告警状态」为左统计块（当日 / 近 7 天 / 通知中 / 已静默·已抑制四格纵排）+ 右「最新告警」明细列表两栏。
4. 同排填满：左卡「采集健康」只保留「采集中 / 已下发未采到」两态计数，分母为已配置采集任务的资源数，「未监控」的统计会出现在上方纳管完成率卡的未配置采集列；右卡「拨测态势」为单卡——正常率圆环（与纳管圆环同几何）+「接口服务拨测 / 应用服务拨测」两个子分区各 2×2 四格计数（拨测目标 / 正常 / 异常 / 未知）。
5. 使用指引：整宽六步横排，每步一句话与深链；页面不设「按应用查看」入口卡。

6. 移动端（≤767px）版式回落见 §11.3.1，桌面（≥768px）版式以上五段不变。

关键交互规则：
- 纳管完成率按「已配置采集任务的资源数 ÷ 资源总数」计算；六行表纳管率列只给百分数、无行内进度条；页面统一说「已配置采集 / 未配置采集」，不说「已下发」；拨测不计入资源总数与纳管完成率。
- 矩阵「其他」行与「未指定平台」行不可下钻、仅带角标提示聚合与补录；其余平台行头、应用列头与单元格点击进入资源清单页并携带平台 / 应用预筛；矩阵脚注补一句指向资源页的补录引导。
- 左窄列各云条目云名可点击进入资源清单页并按该云预筛选，「未指定云」条目不点击（空参与无参不可区分）。
- 「最新告警」数据池固定 8 条（最新的排最前；口径见 §4.2），每页 5 条两行制（行 1 级别 + 告警名 + 时间 + 状态，行 2 实例 · 内容）；统计块「查看全部 →」进入告警状态页；首页不出现「待处理」字样，计算中的告警 N>0 时灰字附注。
- 卡头深链：纳管完成率卡「查看采集任务 →」（预筛采集类 Job）、采集健康卡「查看资源明细 →」、拨测卡「查看异常拨测目标 →」（携带健康状态预筛，非法值忽略）与两个子分区「查看 XX 采集对象 →」。

状态与边界：任一接口失败对应区块显示「暂不可用」并支持重试，不回落样例数据；缺数据的圆环圆心仅显示「-」（只留轨道），绝不渲染 0%；六行表中 0 表示登记了该类但一个都没配置、「-」表示根本没这类对象，不可混用；资源分布与矩阵取数缺失时显示不可用态，绝不渲染全 0 矩阵；已配置采集数为 0 或无主机数据时展示「去导入 / 去配置采集」空态引导；拨测 0 目标时整卡替换为「暂无拨测目标 · 去配置拨测任务」引导态；告警空态展示成功色提示「当前没有需要处理的告警」并保留「去配置通知规则 →」引导。其余状态见 §11.1。

跨模块跳转：矩阵与各云条目跳转 [Module_07](Module_07_Monitoring_Object_Management.md) 资源清单（携带平台 / 应用 / 云筛选）；纳管与采集健康深链跳转 [Module_01](Module_01_Metric_Collection_Center.md) 采集 Job 列表与 [Module_07](Module_07_Monitoring_Object_Management.md) 资源管理；拨测深链跳转 [Module_02](Module_02_Query_Center.md) 目标状态页；告警统计块与「最新告警」跳转 [Module_08](Module_08_Alertmanager_Notification_Management.md) 告警状态页与通知配置页。

#### 11.3.1 移动端版式（手机竖屏 ≤767px）

桌面版式（五段首屏版式、资源分布行窄列 + 矩阵同排、纳管与告警对分、一级导航横排、Sider 用户偏好展开）在 ≥768px 下保持不变；≤767px 应用下列回落，全部区块以零横向滚动为目标（统一断点见 §11.2）。

| 区域 | 桌面（≥768px） | 手机竖屏（≤767px） |
|------|------|------|
| 页头行（引导语 + 资源分布开关） | 左右同排、基线对齐 | 纵向堆叠折行 |
| 资源分布行 | 左窄列「不同云的主机数量」+ 右矩阵同排 | 左列单卡一行纵排（云名 + 台数右对齐、末行合计）；矩阵保留自身横向滚动、固定首列，不卡片化 |
| 纳管完成率卡（与告警卡对分） | 圆环与六行表左右两栏 | 圆环与表格纵向堆叠，圆环块单独居中、不被裁切；表列宽合计 300px 零横向滚动；卡内边距收至 12px |
| 告警状态卡 | 左统计块（四格纵排）+ 右「最新告警」列表两栏 | 统计块与列表上下堆叠；四格统计条回落 2×2 两行两格 |
| 采集健康卡 + 拨测单卡 | 同排填满 | 各自整宽纵向堆叠 |
| 使用指引 | 整宽六步横排 | 六步横向滚动，不换行 |
| 一级模块导航 | 固定横排 | 横向滚动（不换行）、tab 字号 13px、品牌 16px、隐藏角色 Tag、内容区 padding 24→12px |
| 二级侧边栏（Sider） | 用户偏好决定展开 / 折叠 | 自动折叠为 56px 图标列；窄屏隐藏折叠开关、不写入用户偏好 |

取舍：移动端唯一允许横向滚动的是平台与应用的主机分布矩阵——二维可比性优先，保留自身横滚并固定首列，不卡片化；本轮同时修复的关键缺陷是纳管卡在窄屏纵排时圆环被裁切（容器纵向伸展、圆环单独居中）。明确不在本轮范围：其余业务页面未做移动适配、登录页 / 弹层未做窄屏优化、未引入手势 / PWA / 响应式图表。

### 11.4 可视化大屏页（v0.3）

**用户任务**：在大屏 / 投屏场景下查看监控看板，并能从大屏回到门户配置告警。

入口与路径：一级导航「可视化大屏」（第 2 位）；或首页概览顶部「进入可视化大屏」快捷入口（MVP 不提供）。

布局与列设计：页面 iframe 承载 Grafana；提供全屏 / 退出全屏与新窗口打开，全屏模式隐藏门户侧边栏与顶部导航、iframe 铺满可视区域，适配控制室电视墙 / 投屏。

关键交互规则：预置仪表盘模板随交付包 provisioning 下发为只读，用户「另存为 / 克隆」获得可自由编辑副本，平台升级覆盖模板不影响用户副本；不锁定 Grafana 原生能力，用户可新建 / 编辑自有看板；模板按治理标签组织下钻层级（网域 → 平台 → 应用 → 服务 → 资源实例，经看板变量实现，最细层稳定键为 `resource_id`）；页面提供「配置告警」深链回门户告警中心；告警规则与通知配置不在 Grafana 侧进行。

状态与边界：Grafana 数据源由交付包 provisioning 预置为 M02 查询代理，不可改指 Prometheus 直连（租户 / 网域注入红线）。其余状态见 §11.1。

跨模块跳转：「配置告警」深链回 [Module_08](Module_08_Alertmanager_Notification_Management.md) 告警中心；数据源依赖 [Module_02](Module_02_Query_Center.md) 查询代理；看板即代码治理（API 管看板 / 版本化 / 按租户分发）为 Module_11 预留，{v0.4+} 评估。

### 11.5 资源管理页

**用户任务**：维护主机 / 中间件 / 应用服务资源台账并管理其监控标签，判断一个资源是否已被监控。

入口与路径：一级导航「资源管理」；首页平台与应用矩阵单元格、各云条目与纳管完成率六行表「未配置采集」列均携带筛选进入；拨测子分区「查看 XX 采集对象 →」按资源类目预筛进入。

布局与列设计：资源列表展示可读名（实例名 / 主机名）与「已监控 / 未监控」badge；资源详情页含监控标签列表；支持 Excel 批量导入与批量编辑。

关键交互规则：标签按来源徽章区分——模板生成（system）、用户手动（user）、CMDB 同步（{v0.4+}）；模板与 CMDB 来源默认只读，用户可通过新增同名 key 的 user 标签覆盖（生效优先级 CMDB > user > system）。新增标签时即时校验 key：小写字母 / 数字 / 下划线，禁止双下划线开头、禁止与采集端内置标签同名；同名冲突时实时提示「该 key 将由 CMDB 覆盖，建议更换」或「将覆盖模板生成的标签」。

状态与边界：key 校验失败阻断提交并就地提示。其余状态见 §11.1。

跨模块跳转：资源数据与标签语义见 [Module_07](Module_07_Monitoring_Object_Management.md)；首页入口见 §11.3。

### 11.6 标签模板页

**用户任务**：为每类资源配置「资源字段 → 监控标签」的生成规则，让采集到的目标自带业务标识。

入口与路径：一级导航「标签模板」；资源管理页与 CI-Exporter 映射页引用模板结果。

布局与列设计：按资源类型分组；每个映射行展示目标标签、来源字段、转换规则与启用状态。

关键交互规则：来源字段四类——资源模型字段（MVP 主要来源）、组合字段（如「IP:端口 → 实例名」）、采集端内置字段、CMDB 字段（{v0.4+}，上线前置灰或隐藏）；映射规则保存后对新采集目标生效。

状态与边界：{v0.4+} 来源在字段上线前置灰不可选。其余状态见 §11.1。

跨模块跳转：模板与资源标签的派生关系见 [Module_07](Module_07_Monitoring_Object_Management.md)。

### 11.7 CI-Exporter 映射页

**用户任务**：为每类 CI 类型选择采集器模板并设定默认采集参数，不必逐个实例手写采集配置。

入口与路径：一级导航「采集配置」区；采集 Job 创建时引用映射结果。

布局与列设计：表格展示 CI 类型 ↔ 采集器模板绑定关系（采集器名称、默认端口、采集路径、协议、标签模板引用）。

关键交互规则：同一 CI 类型可绑定多个采集器模板（如 Linux 主机同时绑节点与进程采集器），仅一个为默认；新增 / 编辑绑定时自动填充该采集器的常用指标与默认采集参数。

状态与边界：暂无特殊状态。其余状态见 §11.1。

跨模块跳转：采集器模板库与采集参数语义见 [Module_01](Module_01_Metric_Collection_Center.md)。

### 11.8 状态映射字典配置页（P2）

**用户任务**：把外部系统的原始状态字样映射为平台统一状态，保证列表与告警口径一致。

入口与路径：系统设置 → 状态映射字典（P2，MVP 不做）。

布局与列设计：表格展示「来源状态 → 平台状态」规则，支持按资源类型过滤。

关键交互规则：提供「测试映射」——输入任意状态字符串即时返回映射结果；内置规则禁止删除但可禁用，自定义规则可增删改。

状态与边界：暂无特殊状态。其余状态见 §11.1。

跨模块跳转：状态字典语义见 [Module_04](Module_04_Custom_Discovery.md)。

### 11.9 CMDB 同步配置页（P2 / v0.4+）

**用户任务**：接入 CMDB 数据源并维护「CMDB 模型 → 平台资源类型」的映射，让资产数据自动进入平台。

入口与路径：系统设置 → CMDB 同步（P2 / {v0.4+}，MVP 不做）。

布局与列设计：三个区块——数据源接入配置（BlueKing / HTTP / Nacos 接入参数、轮询周期默认 15 分钟、事件订阅开关）；CI 类型映射表（CMDB 模型 → 平台资源类型，支持启用 / 禁用、按网域覆盖）；待分类 CI 队列。

关键交互规则：待分类队列展示未映射 / 已禁用 / 字段缺失的 CI，支持查看原始数据、映射到现有类型或忽略。

状态与边界：字段缺失的 CI 进入待分类队列，不阻塞其余数据同步。其余状态见 §11.1。

跨模块跳转：CMDB Provider 语义见 [Module_04](Module_04_Custom_Discovery.md)。
