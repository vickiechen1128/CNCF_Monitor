## 1. 文档目的

本文档用**便于人理解的语言**记录 M01 模块的业务需求、功能需求与非功能需求。它站在产品经理和运维工程师的视角，说明「监控对象类型如何与采集器绑定、采集 Job 如何配置、告警规则如何编写」，并为后续概要设计、详细设计、开发、测试提供依据。

本文档不直接定义 API 字段级别的技术契约（历史技术 PRD 已覆盖），而是回答：**在 M09 合并为「网域接入与查询中心」、取消配置变更确认/回滚、所有网域统一为采集节点域后，M01 必须具备哪些能力、做到什么程度算合格**。

## 2. 业务背景

### 2.1 M01 的定位

M01 是 MetricCenter 的**监控策略配置层**，回答三个问题：

- **采什么**：监控哪些监控对象类型（主机、MySQL、Redis、接口服务等）；
- **怎么采**：使用哪个采集器、什么参数、采集哪些实例；
- **怎么判**：告警规则与记录规则如何编写。

它只负责策略数据的创建与维护，不直接生成 `prometheus.yml` / `rules.yml`，也不负责下发与 reload。

### 2.2 基于 M09 变化的新假设

1. **配置变更确认/回滚取消**：M09 不再提供人工确认与回滚流程，改为自动配置同步。M01 保存/启用/禁用/删除后，M09 自动生成配置包供采集节点拉取。
2. **所有网域都是采集节点域**：不存在中心直连域/管理域。ScrapeJob 必须绑定一个已登记且已纳管的采集节点域。
3. **中心节点不直接采集**：所有抓取、拨测、配置同步由网域内采集节点完成。M01 只需保证策略数据正确，不关心下发通道。
4. **同步状态替代变更单状态**：M01 不再依赖 M09 的 `pending/confirmed/deployed` 变更单状态，而是展示更简单的「同步状态」（已同步 / 待同步 / 同步失败 / 草稿）。

### 2.3 一句话定位

> M01 回答的问题是：**「要监控什么对象、用什么采集器、采集哪些实例、告警规则怎么写」**。

## 3. 核心概念

### 3.1 监控对象类型（`monitor_type`）

- 由 M07 资源类别 + 子类型推导出的细粒度类型，例如 `host_linux`、`mysql`、`redis`、`npu`；
- 每种类型对应一套默认采集配置（采集器、默认参数、标签模板）。

### 3.2 默认采集配置（CITypeExporterMapping）

- 维护监控对象类型 ↔ 采集实现（ExporterTemplate）的绑定；
- 支持同一类型多个可选采集实现，其中一个标记为默认；
- 包含默认端口、采集路径、协议、采集间隔、超时、认证/TLS 模板、标签模板引用。

### 3.3 采集实现池（ExporterTemplate）

- 平台预置 + 用户登记的采集器集合；
- 包含来源标注（official / third_party / internal）、适用 OS/Arch、下载地址、安装指南；
- M01 负责维护，供默认采集配置引用。

### 3.4 采集 Job（ScrapeJob）

- 实际的采集任务；
- 字段包括名称、监控对象类型、所属网域、采集实现、参数快照、实例选择模式、已选实例、标签模板、启用状态、草稿状态；
- Job 类型：`standard`（标准采集）或 `blackbox`（拨测）。

### 3.5 监控规则（MonitoringRule）

- 告警规则与记录规则；
- MVP 支持 YAML 文件透传模式（`yaml_passthrough`）；
- v0.3 支持字段化编辑模式（`structured`），提供类 YAML 表单、PromQL 校验与指标预览。

### 3.6 配置同步状态

- M01 源数据保存后，M09 自动检测并生成配置包；
- M01 展示每个 Job/规则的同步状态：
  - `synced`：当前源数据与 M09 最新配置快照一致；
  - `syncing`：M09 正在生成或分发中；
  - `failed`：M09 校验或分发失败；
  - `draft`：源数据为草稿，未进入同步候选集。

### 3.7 与 M07 / M09 / M08 的边界

- **M07**：提供 Resource、ResourceType、LabelTemplate；M01 只读消费；
- **M09**：轮询消费 M01 策略数据生成配置包；M01 展示同步状态；
- **M08**：M01 提供告警/记录规则内容，M08 负责 Alertmanager 配置与通知状态。

## 4. 目标用户与使用场景

### 4.1 目标用户

| 用户角色 | 关注点 | 典型操作 |
|----------|--------|----------|
| 运维工程师 | 采集 Job 配置、实例选择 | 创建 Job、选择实例、查看同步状态 |
| 运维架构师 | 默认采集配置、采集实现池 | 维护 CITypeExporterMapping、登记新采集器 |
| SRE | 告警规则 | 编写/上传 rules.yml、查看规则生效状态 |
| 业务研发 | 业务指标语义 | 登记业务指标、查看埋点状态 |

### 4.2 典型使用场景

#### 场景 1：新监控对象类型接入

- **角色**：运维架构师
- **触发**：新类型资源需要监控，例如某型号 NPU
- **目标**：建立默认采集配置
- **成功标准**：
  - 登记或选择采集实现；
  - 创建 CITypeExporterMapping，绑定默认参数与标签模板；
  - 后续创建 ScrapeJob 时可自动带出。

#### 场景 2：创建采集 Job

- **角色**：运维工程师
- **触发**：一批 MySQL 实例需要纳入监控
- **目标**：创建 ScrapeJob 并选择实例
- **成功标准**：
  - 选择监控对象类型后自动带出默认采集配置；
  - 选择所属网域与实例；
  - 保存后状态变为 `ready`，M09 自动同步配置；
  - 同步成功后采集节点开始抓取。

#### 场景 3：配置告警规则

- **角色**：SRE
- **触发**：需要为 CPU 使用率配置告警
- **目标**：创建 MonitoringRule
- **成功标准**：
  - YAML 文件通过语法与 job 引用校验；
  - 保存后 M09 自动同步 rules.yml；
  - 规则在 Prometheus 中生效。

#### 场景 4：查看同步状态与排查失败

- **角色**：运维工程师
- **触发**：Job 保存后未生效
- **目标**：定位同步失败原因
- **成功标准**：
  - M01 列表展示同步状态与失败原因；
  - 可点击跳转 M09 配置同步详情或查看校验错误。

## 5. 功能需求

### 5.1 默认采集配置与采集实现池

#### FR-01：监控对象类型与采集实现映射

- 维护 `CITypeExporterMapping`：监控对象类型 ↔ 一个或多个采集实现；
- 支持设置默认实现；
- 包含默认端口、路径、协议、采集间隔、超时、认证/TLS 模板、标签模板引用。

#### FR-02：采集实现池管理

- 维护 `ExporterTemplate`：采集器名称、来源（official/third_party/internal）、适用 OS/Arch、下载地址、安装指南、主页；
- 支持预置模板与用户登记；
- 被默认采集配置引用时禁止删除。

#### FR-03：标签模板引导

- 创建/编辑默认采集配置时，检测是否已选择标签模板；
- 无标签模板时引导用户前往 M07 创建或选择；
- 列表展示标签模板名称、默认/自定义标记、类别与模板 ID。

#### FR-04：网域级参数覆盖（v0.2+）

- 支持按网域覆盖默认采集配置的端口、协议、路径等参数；
- 覆盖不影响全局默认值。

### 5.2 采集 Job 管理

#### FR-05：ScrapeJob CRUD

- 支持创建、编辑、启用、禁用、删除采集 Job；
- 字段包括名称、监控对象类型、资源类别、采集实现、所属网域、参数快照、认证/TLS、标签模板引用、启用状态、草稿状态。

#### FR-06：草稿与生效状态

- `draft_status` 分为 `draft`（草稿）与 `ready`（可同步）；
- `enabled` 与 `draft_status` 正交；
- 仅 `draft_status=ready` 且 `enabled=true` 的 Job 进入 M09 配置同步候选集；
- 草稿仅做基础校验，不参与同步。

#### FR-07：参数继承与覆盖

- ScrapeJob 创建时自动继承默认采集配置参数；
- 用户可在 Job 级覆盖参数，并标记哪些字段被覆盖；
- 支持「同步映射默认值」一键恢复为默认配置。

#### FR-08：端口四级解析

- 生效端口按以下优先级解析：
  1. Resource 级 `scrape_port`；
  2. 网域级参数覆盖；
  3. 默认采集配置端口；
  4. 业务端口兜底（仅数据库/中间件）。
- 不提供 Job 级端口映射表。

#### FR-09：实例选择

- MVP 支持手动勾选实例；
- 候选实例按 `monitor_type` + 所属网域收敛；
- `offline` 实例显示但置灰不可选；
- v0.2 支持 `filter` 条件筛选实例，新增资源自动纳入。

#### FR-10：NPU 监控类型

- `monitor_type` 枚举包含 `npu`；
- NPU Job 的候选主机全集，不按 OS/型号过滤。

#### FR-11：Blackbox 拨测 Job

- `job_type=blackbox` 时，`resource_type` 仅限 `interface_service` / `application`；
- 从同网域资源中勾选目标，持久化到 `selected_instance_ids`；
- `target_field` 按类别只读派生：接口服务为 `api_url`，应用服务为 `health_check_url`；
- 手填 `blackbox_targets` 已禁用，请求非空返回 400。

#### FR-12：同步状态展示

- Job 列表展示同步状态：`synced` / `syncing` / `failed` / `draft`；
- 同步失败时展示失败原因与跳转入口；
- 保存/启用/禁用/删除后提示用户配置将由 M09 自动同步。

#### FR-13：采集状态回显

- Job 详情/编辑抽屉展示实例级采集状态：待采集 / up / stale（回传延迟中）/ down / unknown；
- 数据来自 M02 `/api/v1/targets` 代理或 M09 边缘 target 快照；
- 外层汇总「在线 X / 总数 Y · 待采集 Z」。

### 5.3 监控规则管理

#### FR-14：规则文件挂载模式（MVP）

- 支持上传/粘贴完整 `rules.yml`；
- 「检查 → 提交」两段式：先校验，后落库；
- 校验包括 YAML 语法、`groups` 结构、组名唯一性、`job` 引用分级校验。

#### FR-15：`job` 引用分级校验

- 规则表达式引用的采集 Job 不在本网域生效 Job 列表中：
  - 存活类规则（`up`/`absent(up)`）不匹配 → error 阻断提交；
  - 其他规则不匹配 → warning 允许提交但高亮提示。
- 提供逃生门覆盖 error 级不匹配（明确记录覆盖原因）。

#### FR-16：规则同步状态

- 规则保存并校验通过后进入 `ready`；
- M09 自动同步 `rules.yml`；
- 列表展示同步状态与失败原因。

#### FR-17：字段化规则编辑（v0.3+）

- 提供类 YAML 表单编辑告警/记录规则；
- 支持 PromQL 表达式校验与指标实时预览（调用 M02）；
- 字段包括 expr、for、labels、annotations。

### 5.4 指标库

#### FR-18：技术指标库

- 按监控对象类型组织指标元数据；
- 字段包括指标名、类型（counter/gauge/histogram/summary）、HELP、UNIT；
- 支持同名不同义区分与多来源标注。

#### FR-19：业务指标库

- 维护业务语义契约：指标名、业务语义、阈值、业务域、负责人；
- 状态机：`pending → instrumented → online`。

### 5.5 安装登记（可选）

#### FR-20：Exporter 安装确认

- 在 `resource_id × scrape_job_id` 维度登记 Exporter 安装状态、实际监听端口、备注；
- 仅作为运维记录，不作为 target 生成前置条件。

## 6. 非功能需求

### 6.1 架构约束

#### NFR-01：M01 只维护策略数据

- M01 不生成 `prometheus.yml` / `rules.yml`，不触发 reload，不直接连接采集目标；
- 配置生成与下发由 M09 负责。

#### NFR-02：所有 Job 必须绑定采集节点域

- `network_domain_id` 必填，且必须是 M06 已登记、M09 已纳管的采集节点域；
- 不允许选择中心直连域/管理域；不存在 `default` 管理域特殊处理。

#### NFR-03：源数据变更自动触发同步

- M01 写库后维护 `updated_at`；
- M09 以 pull 模式轮询感知变化并自动生成配置包；
- M01 不主动通知 M09，也不假设保存即生效。

#### NFR-04：同步失败不锁死源数据

- 当 M09 校验失败且归因为 `user_config` 时，M01 源数据不被长期锁定；
- 用户可直接编辑修正后重新保存，新保存会再次触发同步。

### 6.2 数据一致性

#### NFR-05：选中关系一致性

- M07 删除资源时，M01 各 Job 的 `selected_instance_ids` 同步回收；
- 资源转 `offline` 后，M09 下一配置生成周期自动从 targets 中移除。

#### NFR-06：参数快照稳定性

- ScrapeJob 保存时快照当前默认采集配置参数；
- 后续默认配置变更不影响已存在 Job，除非用户主动同步。

### 6.3 安全与隔离

#### NFR-07：网域作用域校验

- 实例候选必须与 Job 所属网域一致；
- 规则 `job` 引用校验仅在同一网域生效 Job 集合中进行。

#### NFR-08：权限控制

- Job/规则/默认配置/采集实现的写操作需要相应管理权限；
- 普通用户只读或仅操作自己负责的 Job。

### 6.4 可用性

#### NFR-09：用户语言一致性

- 用户界面统一使用「监控对象类型 / 采集实现 / 采集 Job / 拨测 / 监控规则 / 同步状态」等业务语言；
- 技术术语（`scrape_interval`、`blackbox_module`、`inhibit_rules` 等）仅出现在折叠区、代码注释或接口文档。

#### NFR-10：错误提示可执行

- 同步失败、`job` 引用不匹配、实例越网等错误须给出下一步操作指引。

## 7. 数据模型概述

### 7.1 核心实体

| 实体 | 说明 | 关键属性 |
|------|------|----------|
| CITypeExporterMapping | 默认采集配置 | 监控对象类型、采集实现、默认参数、标签模板、是否默认 |
| ExporterTemplate | 采集实现池 | 名称、来源、OS/Arch、下载地址、安装指南 |
| ScrapeJob | 采集任务 | 名称、类型、网域、采集实现、参数快照、实例选择、标签模板、状态 |
| MonitoringRule | 监控规则 | 名称、类型（yaml_passthrough/structured）、内容、启用状态、同步状态 |
| ExporterMetricLibrary | 技术指标库 | 指标名、类型、HELP、UNIT、监控对象类型 |
| BusinessMetric | 业务指标库 | 指标名、业务语义、阈值、业务域、负责人、状态 |
| ExporterInstallationConfirmation | 安装登记 | resource_id、scrape_job_id、状态、端口、备注 |

### 7.2 核心关系

- **CITypeExporterMapping → ExporterTemplate**：多对一或一对多（一个类型可绑定多个实现）；
- **ScrapeJob → CITypeExporterMapping**：创建时继承默认参数；
- **ScrapeJob → Resource**：通过 `selected_instance_ids` 多对多；
- **MonitoringRule → ScrapeJob**：规则表达式引用校验；
- **ExporterMetricLibrary → monitor_type**：多对多；
- **M01 → M09**：M09 轮询消费 ScrapeJob/MonitoringRule 生成配置包。

## 8. 关键流程

### 8.1 创建 ScrapeJob 流程

1. 用户选择监控对象类型；
2. 系统自动带出默认采集配置（采集实现、参数、标签模板）；
3. 用户选择所属网域；
4. 系统按 `monitor_type` + 网域收敛候选实例；
5. 用户选择实例并覆盖必要参数；
6. 保存后 `draft_status=ready`；
7. M09 轮询检测到变化，自动生成配置包；
8. 采集节点拉取配置并开始采集；
9. M01 展示同步状态与采集状态。

### 8.2 保存 MonitoringRule 流程

1. 用户上传/粘贴 YAML 或填写字段化规则；
2. 后端执行 YAML 语法、`groups` 结构、组名唯一性、`job` 引用分级校验；
3. 校验失败返回行级错误，不入库；
4. 校验通过后落库 `MonitoringRule`，`draft_status=ready`；
5. M09 自动生成 `rules.yml`；
6. Prometheus 加载新规则。

### 8.3 Blackbox 拨测 Job 流程

1. 用户选择 `job_type=blackbox`；
2. 选择 `resource_type`（`interface_service` / `application`）；
3. 系统按网域收敛候选资源；
4. 用户勾选目标，`target_field` 只读派生地址；
5. 保存后 M09 生成 blackbox 配置。

### 8.4 配置同步状态流程

1. M01 源数据保存/启用/禁用/删除；
2. M09 计算源数据版本并生成配置包；
3. M09 返回同步结果与校验和；
4. M01 将同步状态回写到 Job/规则；
5. 同步失败时 M01 展示失败原因并允许用户修正。

### 8.5 资源删除清理流程

1. M07 删除某 Resource；
2. M01 收到通知或依赖外键/触发器；
3. M01 从所有 Job 的 `selected_instance_ids` 中移除该资源；
4. M09 下一周期生成配置时该 target 自动移除。

## 9. 验收标准

### 9.1 功能验收

- [ ] 支持维护监控对象类型 ↔ 采集实现的默认采集配置，支持多实现与默认标记。
- [ ] 支持采集实现池管理，包含来源、OS/Arch、下载地址、安装指南。
- [ ] 创建 ScrapeJob 时自动继承默认采集配置参数，支持 Job 级覆盖与同步默认值。
- [ ] ScrapeJob 必须绑定一个已登记且已纳管的采集节点域，不允许选择中心直连域。
- [ ] 仅 `draft_status=ready` 且 `enabled=true` 的 Job 进入 M09 配置同步候选集。
- [ ] 支持手动实例选择，候选按 `monitor_type` + 网域收敛，`offline` 实例置灰不可选。
- [ ] 支持 NPU 监控类型，候选主机全集，不按 OS/型号过滤。
- [ ] 支持 Blackbox 拨测 Job，目标从 `interface_service` / `application` 资源选择，`target_field` 只读派生。
- [ ] 支持监控规则 YAML 文件透传模式，提供「检查 → 提交」两段式与 `job` 引用分级校验。
- [ ] 规则校验失败时返回行级错误；error 级不匹配可逃生门覆盖。
- [ ] Job/规则列表展示同步状态（已同步 / 待同步 / 同步失败 / 草稿）与失败原因。
- [ ] Job 详情/编辑抽屉展示实例级采集状态（待采集 / up / stale / down / unknown）。
- [ ] 支持技术指标库与业务指标库管理。
- [ ] M07 删除资源时，M01 同步回收各 Job 的选中关系。

### 9.2 非功能验收

- [ ] M01 不直接生成 Prometheus 配置或触发 reload。
- [ ] 所有 ScrapeJob 必须绑定采集节点域，无中心直连域特殊逻辑。
- [ ] M09 以 pull 模式轮询 M01 源数据变化，M01 不主动通知。
- [ ] 同步失败时源数据不被长期锁定，用户可编辑后重新触发同步。
- [ ] 实例候选与 `job` 引用校验严格限制在 Job 所属网域范围内。
- [ ] 用户界面统一使用业务语言，错误提示给出可执行指引。

### 10.2 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| M09 自动同步失败导致用户误以为保存未生效 | 体验差 | M01 列表实时展示同步状态与失败原因 |
| 所有网域都是采集节点域后，MVP 最小部署需先完成网域纳管 | 上手门槛提高 | 首页使用指引引导用户先登记网域、部署采集节点 |

| 规则 `job` 引用校验范围变为仅本网域 | 跨网域引用被误报 | 校验逻辑按 Job 所属网域过滤生效 Job 列表 |
| 历史 `change_status` pending/confirmed/deployed 代码残留 | 状态不一致 | 重写 SRS 后同步清理 M01 状态机，替换为同步状态 |
