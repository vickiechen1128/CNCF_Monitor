## 1. 引言

### 1.1 目的

本文档用**业务语言**记录 M01 的业务目标、用户场景、功能需求、非功能需求与验收口径。它回答：**M01 为什么存在、为谁解决什么问题、必须具备哪些能力、做到什么程度算合格**。

本文档**不定义**接口路径与字段、数据表结构、算法、状态机、页面组件与部署参数；这些内容见配套《概要设计》、接口契约与关键设计专题。场景与设计、演示、验收的对应关系见 [Scenario Link](../../../07-design/Module_01_Scenario_Link.md)。

### 1.2 范围

**本期范围（In Scope）**

- 采集模板配置化（模板 = 采集实现 + 参数集 + 标签模板）、采集实现池；
- 采集任务（单域 Job 与跨域任务组）的创建 / 编辑 / 启停 / 删除、选择器筛选实例与安装登记；
- 监控规则文件透传编辑、「检查 → 提交」门禁与同步状态；
- 技术指标库（内置只读 + 管理员用户扩展）、业务指标库（API 能力，前端页面后续版本）；
- 资源删除后的 M01 周期对账回收。

**不在本期范围（Out of Scope）**

- 指标查询与配置下发（M09）、资源台账与标签模板维护（M07）、告警通知（M08）；
- 指标批量导入（CSV/JSON 或 `/metrics` 文本）与规则表达式指标存在性校验（后续版本）；
- 规则字段化编辑（v0.3+）、规则标签 / 注解实时预览（v3 暂缺，见概要设计 §10）；
- 细粒度权限点（M03）。本期只区分「登录用户」与「平台管理员」。
- 网域级参数覆盖（原 FR-04）。域级差异通过域专用模板 + 按 `network_domain_id` 筛选，或实例级 `scrape_port` 表达，不引入同一模板的隐式分叉。

## 2. 业务背景

### 2.1 M01 的定位

M01 是 MetricCenter 的**监控策略配置层**，回答三个问题：

- **采什么**：用哪套采集模板、按什么条件筛出采集对象（主机、MySQL、Redis、接口服务等）；
- **怎么采**：使用哪个采集器、什么参数、怎么打标签（由「采集模板」承载）；
- **怎么判**：告警规则与记录规则如何编写。

它只负责策略数据的创建与维护，不直接生成 `prometheus.yml` / `rules.yml`，也不负责下发与 reload。

### 2.2 基于 M09 变化的新假设

1. **配置变更确认/回滚取消**：M09 不再提供人工确认与回滚流程，改为自动配置同步。M01 保存/启用/禁用/删除后，M09 自动生成配置包供采集节点拉取。
2. **所有网域都是采集节点域**：不存在中心直连域/管理域。ScrapeJob 必须绑定一个已登记且已纳管的采集节点域。
3. **中心节点不直接采集**：所有抓取、拨测、配置同步由网域内采集节点完成。M01 只需保证策略数据正确，不关心下发通道。
4. **同步状态替代变更单状态**：M01 不再依赖 M09 的 `pending/confirmed/deployed` 变更单状态，而是展示更简单的「同步状态」（已同步 / 待同步 / 同步失败 / 草稿）。

### 2.3 一句话定位

> M01 回答的问题是：**「要监控什么对象、用什么采集器、采集哪些实例、告警规则怎么写」**。

## 3. 核心概念

### 3.1 采集模板（`collection_template`）

- **平台可配置的「采集配方」元数据**，回答「这类对象怎么采」，不再是代码枚举。管理员可新增、编辑、启用 / 停用；**新增一种采集模板不需要修改代码、不需要发版**。
- 一个模板恰好绑定 **一个** 采集实现（ExporterTemplate）+ 一套参数（默认端口、采集路径、协议、采集间隔、超时、认证 / TLS）+ **一个** 标签模板；模板归属一个 M07 资源类别（`host` / `database` / `middleware` / `application` / `generic_target` / `interface_service`），类别决定它能被哪些采集任务引用。
- **模板不描述「采哪些对象」**：采集范围由采集任务的「选择器」决定（§3.3），模板只回答「采什么、用什么采、怎么打标签」。
- 模板不复制资源数据、不把任何模板标识回写到 M07；M07 仍是资源事实的唯一来源。

#### 3.1.1 模板的组成

| 属性 | 说明 |
| --- | --- |
| 编码 `code` | 全局唯一、创建后不可变，如 `host_linux`、`host_npu`、`mysql` |
| 展示名 `name` | 用户界面显示的名称，如「Linux 主机采集」「NPU 主机采集」 |
| 资源类别 `resource_category` | 该模板适用的 M07 资源类别，决定可选择的对象范围 |
| 采集实现 | 恰好一个采集器（如 node-exporter、mysqld-exporter）；需要第二套采集器或参数即新增一条模板 |
| 参数集 | 默认端口、采集路径、协议、采集间隔、超时、认证 / TLS 模板 |
| 标签模板 | 该模板产出的时序使用哪个标签模板（由 M07 维护，模板是唯一引用点） |
| 指标锚点 | 技术指标库中挂接在该模板下的指标集合 |
| 启用状态 / 内置标记 | 停用后不可用于新建任务；内置模板不可删除，仅可停用 |

#### 3.1.2 一个 CI 支持多个采集器

- 同一批资源可以被**多条采集任务**以**不同采集模板**分别采集，各自使用不同采集实现与参数；
- 典型例子：一台带 NPU 芯片的 Linux 主机，同时被「Linux 主机采集」（node-exporter）与「NPU 主机采集」（npu-exporter）两条任务采集；两条任务的筛选条件、参数、启停、同步状态彼此独立；
- 因此「一个 CI 多个采集器」**不是把多个采集实现塞进同一个 Job**，而是「一个资源被多条任务引用」。Job 仍保持「一个采集模板 + 一个采集实现 + 一个网域」的单采集面语义，与 M09 按域生成配置包的下发模型保持一致；
- 资源维度的采集覆盖视图按「**资源 × 任务**」展开，不假设「一个资源只对应一个采集器」。

### 3.2 采集实现池（ExporterTemplate）

- 平台预置 + 用户登记的采集器集合；
- 包含来源标注（official / third_party / internal）、适用 OS/Arch、下载地址、安装指南、默认端口；
- M01 负责维护，供采集模板引用；
- 采集实现是「软件目录」，不承载参数与范围；同一采集器可被多个模板复用。

### 3.3 采集任务与选择器（ScrapeJob）

- 实际要下发的采集任务，字段包括名称、采集模板、所属网域、参数快照、**选择器**、已选实例、启用状态、草稿状态；
- **选择器**（selector）回答「采哪些对象」：`资源类别 + 条件列表 + all/any 组合方式`。条件字段来自 M07 字段字典（内置字段 + 自定义字段），由服务端做 key → 取数列的受控映射；
- 选择器是**筛选**语义，不是分类语义：它只决定候选实例集合，不改写、不标注资源本身；保存时把命中的实例固化为已选实例快照；
- Job 类型：`standard`（标准采集）或 `blackbox`（拨测）。

### 3.4 监控规则（MonitoringRule）

- 告警规则与记录规则；
- MVP 支持 YAML 文件透传模式（`yaml_passthrough`）；
- v0.3 支持字段化编辑模式（`structured`），提供类 YAML 表单、PromQL 校验与指标预览。

### 3.5 配置同步状态

- M01 源数据保存后，M09 自动检测并生成配置包；
- M01 展示每个 Job/规则的同步状态：
  - `synced`：当前源数据与 M09 最新配置快照一致；
  - `syncing`：M09 正在生成或分发中；
  - `failed`：M09 校验或分发失败；
  - `draft`：源数据为草稿，未进入同步候选集。

### 3.6 与 M07 / M09 / M08 的边界

- **M07**：提供 Resource、资源类别、LabelTemplate 与 CI 模型字段字典（内置字段 + 自定义字段）；**M07 是资源事实的唯一来源，不感知也不存储采集模板与选择器**；M01 只读消费资源与字段字典；
- **M01**：拥有采集模板与任务选择器（策略数据），负责按选择器条件把 M07 资源收敛成候选实例，并把选中的实例固化为任务快照；
- **M09**：轮询消费 M01 策略数据生成配置包；M01 展示同步状态；
- **M08**：M01 提供告警/记录规则内容，M08 负责 Alertmanager 配置与通知状态。

## 4. 目标用户与使用场景

### 4.1 目标用户

| 用户角色 | 关注点 | 典型操作 |
|----------|--------|----------|
| 运维工程师 | 采集 Job 配置、实例选择 | 创建 Job、选择实例、查看同步状态 |
| 运维架构师 | 采集模板、采集实现池 | 维护采集模板（采集器 + 参数 + 标签模板）、登记新采集器；维护内置模板仅管理员可做 |
| 运维工程师 | 采集任务与选择器 | 建任务、按条件筛选实例；可按需新建自定义采集模板 |
| SRE | 告警规则 | 编写/上传 rules.yml、查看规则生效状态 |
| 业务研发 | 业务指标语义 | 登记业务指标、查看埋点状态 |

### 4.2 典型使用场景

> 场景是需求第一公民。每个场景必须可演示、可验收；场景与设计、演示、验收的唯一链接见 [Scenario Link](../../../07-design/Module_01_Scenario_Link.md)。

#### SCN-01：新增一种采集能力（NPU）

- **谁**：运维架构师
- **情境**：一批 Linux 主机新增了 NPU 芯片，平台原先只有 Linux 主机采集模板，需要在不改代码的前提下同时采集 OS 指标与 NPU 指标
- **任务**：新增 NPU 采集模板，并创建引用该模板、按硬件能力筛选实例的采集任务
- **成功标准**：新增模板后立即可用于新建任务；`has_npu 等于 true` 能实时预览命中主机；原有 Linux 主机采集不受影响；同一台主机可同时被两条任务采集
- **前置条件**：M07 已登记主机且字段字典包含 `has_npu`；NPU/GPU 采集实现已登记；对应标签模板已存在
- **操作步骤**：
  1. 进入「采集策略 → 采集模板」，新增模板：资源类别 `host`、采集实现 `npu-exporter`、填写端口与采集间隔、绑定标签模板；
  2. 进入「采集任务」，选择该模板；
  3. 在「采哪些对象」中添加条件 `has_npu 等于 true`，查看命中数与分域预览；
  4. 确认实例并保存；
  5. 查看同步状态与实例采集状态。

#### SCN-02：创建跨网域采集任务（对象优先）

- **谁**：运维工程师
- **情境**：一批 MySQL 实例分布在多个已授权网域，需要一次性纳入监控
- **任务**：从一个入口创建采集任务，按条件跨域筛选实例，保存后按实例所属网域自动拆分下发
- **成功标准**：网域不是表单的第一个必填项；筛选条件可组合并实时显示命中数与分域分布；保存后生成一个任务视图与多条单域子任务；列表以单一视图展示覆盖网域
- **前置条件**：相关网域已在 M06 登记并在 M09 纳管；MySQL 资源已在 M07 登记；MySQL 采集模板与标签模板可用
- **操作步骤**：
  1. 进入「采集任务」，点击「新建采集任务」；
  2. 选择任务类型（采集）与 MySQL 采集模板；
  3. 添加筛选条件，查看总命中数与各网域命中数；
  4. 确认或排除实例，保存；
  5. 在列表查看覆盖网域、组级同步状态与逐域子任务。

#### SCN-03：配置并检查告警规则

- **谁**：SRE
- **情境**：需要为 CPU 使用率配置告警规则，并确保规则引用的采集任务真实存在
- **任务**：通过 YAML 文件透传方式编写告警规则，完成「检查 → 提交」并确认规则在中心生效
- **成功标准**：检查阶段能定位到具体组/规则的问题；`job` 引用分级校验结果可见；检查通过后才能提交；保存后同步状态可见，规则由中心 Prometheus 集中求值
- **前置条件**：相关采集任务已处于可同步状态；`promtool` 可用（不可用时明确展示「未执行」而非假装通过）
- **操作步骤**：
  1. 进入「规则编辑」，粘贴或上传 `rules.yml`；
  2. 点击「检查」，查看组数、规则数与 PromQL 校验状态；
  3. 修正 error 级问题后重新检查；如确需放行 warning/逃生门，明确确认并留痕；
  4. 点击「提交」保存；
  5. 查看规则同步状态与失败原因。

#### SCN-04：排查同步失败与采集异常

- **谁**：运维工程师
- **情境**：任务保存后长时间未生效，或部分实例没有数据
- **任务**：判断问题出在配置校验、同步通道、采集端还是实例本身，并找到下一步动作
- **成功标准**：列表能区分草稿/待同步/同步中/同步失败/已同步；失败原因可读并可跳转定位；实例级采集状态能区分待采集、在线、回传延迟、离线、未知；资源被删除后选中关系自动回收
- **前置条件**：存在至少一条已保存任务；可访问 M09 配置产物与目标状态
- **操作步骤**：
  1. 在任务列表查看同步状态与失败原因；
  2. 跳转配置产物/校验详情，确认是用户配置问题还是平台故障；
  3. 修正配置后重新保存，观察状态变化；
  4. 在任务详情查看实例级采集状态；
  5. 删除一个已选资源，等待对账周期后确认该实例已从任务中回收。

#### SCN-05：采集模板治理与变更影响

- **谁**：运维架构师 / 平台管理员
- **情境**：采集模板需要停用、调整参数或删除，但已被多条任务引用
- **任务**：安全地完成模板生命周期变更，并让受影响任务可预期
- **成功标准**：停用后不可用于新建任务，存量任务保留并提示；改参数不影响存量任务快照，需用户主动同步；删除有引用的模板被拒绝并回传引用清单；内置模板只可停用不可删除
- **前置条件**：存在被任务/指标锚点引用的采集模板
- **操作步骤**：
  1. 在采集模板列表查看引用数与影响面；
  2. 停用模板，尝试新建任务确认不可选；
  3. 修改模板参数，检查存量任务参数是否保持；
  4. 在存量任务中执行「同步模板默认值」；
  5. 尝试删除仍有引用的模板，查看拒绝原因与引用清单。

#### SCN-06：维护技术指标库

- **谁**：平台管理员 / 运维工程师
- **情境**：新增采集模板后需要补齐其指标语义，或修正一条用户扩展指标
- **任务**：在技术指标库中查看、挂接或修正指标元数据
- **成功标准**：内置指标只读；管理员可新增/编辑/删除用户扩展指标；指标可挂接到指定采集模板；同名同锚点重复登记被拒绝；指标库的模板筛选项随模板变化即时可用
- **前置条件**：目标采集模板已存在；操作者具备管理员权限（写操作）
- **操作步骤**：
  1. 进入「指标库」，按资源类别/采集模板/指标类型筛选；
  2. 查看内置指标，确认不可编辑；
  3. 新增一条用户扩展指标并挂接目标模板；
  4. 重复登记同名同锚点指标，确认被拒绝；
  5. 在指标库筛选中选择新模板，确认可筛。

### 5.1 采集模板与采集实现池

#### FR-01：采集模板构成

- 定义 `CollectionTemplate` 的数据构成：编码、展示名、资源类别、**一个**采集实现、参数集（默认端口 / 路径 / 协议 / 间隔 / 超时 / 认证 / TLS）、**一个**标签模板；
- 同一资源类别可有多条模板（如 `host_linux` 与 `host_npu`），同一采集实现也可被多条模板复用；
- 模板不承载筛选条件：**适用哪些资源由任务的选择器决定**（见 FR-09 / FR-22）；
- 本节只定义“模板由什么组成”；生命周期、权限、启停/删除与变更影响见 FR-21 / FR-24，不在此重复。

#### FR-02：采集实现池管理

- 维护 `ExporterTemplate`：采集器名称、来源（official/third_party/internal）、适用 OS/Arch、下载地址、安装指南、主页、默认端口；
- 支持预置模板与用户登记；
- 被采集模板引用时禁止删除，并回传引用清单。

#### FR-03：标签模板绑定与引导

- 创建 / 编辑采集模板时必须绑定一个标签模板（按资源类别校验可用性）；
- 未绑定或该类别无可用标签模板时，引导用户前往 M07 创建；
- 标签模板只在采集模板上设置一次，采集任务只读展示、不重复持有。

### 5.2 采集 Job 管理

#### FR-05：ScrapeJob CRUD

- 支持创建、编辑、启用、禁用、删除采集 Job；
- 字段包括名称、采集模板、选择器（资源类别 + 条件）、所属网域、参数快照、已选实例、启用状态、草稿状态。

#### FR-06：草稿与生效状态

- `draft_status` 分为 `draft`（草稿）与 `ready`（可同步）；
- `enabled` 与 `draft_status` 正交；
- 仅 `draft_status=ready` 且 `enabled=true` 的 Job 进入 M09 配置同步候选集；
- 草稿仅做基础校验，不参与同步。

#### FR-07：参数继承与覆盖

- ScrapeJob 创建时自动继承所属采集模板的参数（间隔、超时、认证 / TLS、采集路径等），落为 Job 参数快照；
- 用户可在 Job 级覆盖上述参数，并标记哪些字段被覆盖；
- 端口不进入 Job 参数快照，按 FR-08 的端口链在每次预览 / 生成时实时求值；
- 支持「同步模板默认值」一键恢复为模板默认配置（端口链实时求值，不受此操作影响）。

#### FR-08：端口解析链（三级）

- 本期（MVP）生效端口按以下优先级解析：
  1. Resource 级 `scrape_port`；
  2. 采集模板默认端口；
  3. 类别兜底：数据库 / 中间件回退业务端口；主机回退采集实现默认端口（node-exporter 默认 9100）。
- 旁路：`application` 直接使用资源自身端口；`generic_target` 使用资源自身端口，缺失时按 scheme 回落 443/80；两者不参与上述兜底链。
- 端口在每次预览 / 生成时实时求值，不写入 Job 参数快照；
- 不提供 Job 级端口映射表。

#### FR-09：选择器与实例选择

- 采集任务通过**选择器**确定候选实例：`资源类别（继承自采集模板）+ 条件列表 + all / any 组合方式`；
- 条件字段来自 M07 字段字典（内置字段 + 自定义字段），操作符至少支持 `等于` / `包含` / `属于集合` / `正则匹配` / `恒真`；字段名不接受自由输入，取数层使用服务端固定映射，杜绝列名拼接；
- 编辑条件时实时回显「当前命中资源数」与分域命中数；命中为空时给出「检查筛选条件」引导入口；
- 保存时把命中实例固化为「已选实例」快照，并支持在快照上手动排除个别实例；
- 选择器变更**不自动改写存量任务的已选实例**，只影响后续候选查询；
- `offline` 实例显示但置灰不可选；
- {v0.2} 支持动态选例（新增资源自动纳入），本期为静态快照。

#### FR-10：硬件能力类采集（NPU / GPU / DPU）

- NPU **不再作为代码里的特例枚举**，而是由「一条普通筛选条件（如 `has_npu 等于 true`）+ 一条 NPU 采集模板」表达；
- 该任务的候选池为「资源类别 = 主机、且满足筛选条件」的主机；不按 OS / 型号过滤，因此 Linux 与 Windows 主机都可被选中；
- NPU 任务与 Linux / Windows 主机任务**正交共存**：同一台主机可同时被 OS 采集任务与 NPU 采集任务引用，分别由 node-exporter 与 npu-exporter 采集；
- GPU、DPU 等后续硬件能力沿用同一模式：新建模板 + 增加筛选条件即可接入，不改代码。

#### FR-11：Blackbox 拨测 Job

- `job_type=blackbox` 时，`resource_category` 仅限 `interface_service` / `application`；
- 从同网域资源中勾选目标，持久化到 `selected_instance_ids`；
- `target_field` 按类别只读派生：接口服务为 `api_url`，应用服务为 `health_check_url`；
- 手填 `blackbox_targets` 已禁用，请求非空返回 400。

#### FR-12：同步状态展示

- Job 列表展示同步状态：`synced` / `syncing` / `failed` / `draft`；
- 同步失败时展示失败原因与跳转入口；
- 保存/启用/禁用/删除后提示用户配置将由 M09 自动同步。

#### FR-13：采集状态回显

- Job 详情/编辑抽屉展示实例级采集状态：待采集 / up / stale（回传延迟中）/ down / unknown；
- 数据来自 M09 `/api/v1/targets` 融合接口（中心 targets + 边缘 target 快照）；
- 外层汇总「在线 X / 总数 Y · 待采集 Z」。

### 5.3 监控规则管理

#### FR-14：规则文件挂载模式（MVP）

- 支持上传/粘贴完整 `rules.yml`；
- 「检查 → 提交」两段式：先校验，后落库；
- 校验包括 YAML 语法、`groups` 结构、组名唯一性、`job` 引用分级校验。

#### FR-15：`job` 引用分级校验

- 规则表达式引用的采集 Job 不在**全平台**生效 Job 并集（`ready` 且 `enabled`）中：
  - 存活类规则（`up`/`absent(up)`）不匹配 → error 阻断提交；
  - 其他规则不匹配 → warning 允许提交但高亮提示。
- 提供逃生门覆盖 error 级不匹配（明确记录覆盖原因）。
- 规则为平台级全局对象、由中心 Prometheus 集中求值，允许跨网域引用（决策 D35/D36）。

#### FR-16：规则同步状态

- 规则保存并校验通过后进入 `ready`；
- M09 自动同步 `rules.yml`；
- 列表展示同步状态与失败原因。

#### FR-17：字段化规则编辑（v0.3+）

- 提供类 YAML 表单编辑告警/记录规则；
- 支持 PromQL 表达式校验与指标实时预览（调用 M09 查询面代理）；
- 字段包括 expr、for、labels、annotations。

### 5.4 指标库

#### FR-18：技术指标库（含用户扩展）

- 按采集模板组织指标元数据；字段包括指标名、类型（counter/gauge/histogram/summary）、HELP、UNIT、标签键、语义域，以及锚点（采集模板 + 来源采集器）；
- 支持同名不同义区分（`source_exporter`）与多锚点：同一指标可同时归属多个采集模板；
- 筛选维度：资源类别 / 采集模板 / 指标类型 / 关键字；「采集模板」选项随模板列表同步，手动新增模板无需刷新页面即可选到；
- **内置指标只读**：平台预置指标不可编辑、删除或禁用；
- **用户扩展**：管理员可新增 / 编辑 / 删除 `is_builtin=false` 指标，并挂接到任意启用模板；新建采集模板保存后可立即为其挂接指标；
- 校验：指标名符合 Prometheus 命名 `^[a-zA-Z_:][a-zA-Z0-9_:]*$`、标签键合法；同一指标名与任一相同锚点重复登记返回 409（内置行与用户行一起判重）；
- 本期不做：批量导入与规则表达式的指标存在性校验（见 §1.2）。

#### FR-19：业务指标库

- 维护业务语义契约：指标名、业务语义、阈值、业务域、负责人；
- 状态机：`pending → instrumented → online`。

### 5.5 安装登记（可选）

#### FR-20：Exporter 安装确认

- 在 `resource_id × scrape_job_id` 维度登记 Exporter 安装状态、实际监听端口、备注；
- 仅作为运维记录，不作为 target 生成前置条件。

### 5.6 采集模板与选择器管理

> **本节的定位**：M01 只有两个可配置面——**采集模板**（怎么采）与**任务选择器**（采哪些）。二者都不依赖改代码与发版；平台不再维护「监控对象类型」这一中间概念，避免"资源是什么"出现第二个事实源。

**字段字典（选择器的输入）**：选择器可用的字段由 M07 提供，M01 只读消费：

- 内置字段（如主机 `os_type` / `os_version` / `hostname` / `has_npu` / `has_gpu`，数据库 `database_type`，中间件 `middleware_type`，应用 `service_name` / `protocol`，接口服务 `api_name`，通用目标 `target_name` / `exporter_type`，以及跨类别的 `app_code` / `biz_code` / `platform_code` / `env` / `cluster` / `owner` / `status`）；
- 自定义字段（M07「CI 模型配置」登记的字段，按 `资源 × key × value` 存储）；
- M01 只持有「字段 key → 取数列 / 子查询」的服务端映射，**不暴露物理列名**；新增自定义字段不需要 M01 改代码即可参与筛选。

> **本节边界**：只定义模板与选择器的**治理语义**（谁能改、如何校验、变更影响）。模板由什么组成见 FR-01，选择器的求值、预览与实例快照见 FR-09，本节不重复。

#### FR-21：采集模板生命周期与权限

- 支持在「采集模板」页新增、编辑、启用 / 停用、删除模板；模板必须满足 FR-01 的构成约束；
- 模板编码全局唯一、创建后不可变（避免存量任务与指标锚点引用失效）；
- 系统内置模板（如 `host_linux`、`host_windows`、`host_npu`、`mysql`、`redis`）以种子数据形式预置，**不可删除、仅可停用**，且只有平台管理员可编辑；用户新建的模板登录用户可维护，无引用时可删除；
- 模板保存后，**立即**出现在「新建采集任务」的模板下拉中，无需重启服务或发版；
- 启停与删除的影响面、引用保护见 FR-24。

#### FR-22：任务选择器配置校验

- 每条采集任务持有一个选择器；选择器的结构、求值、命中预览与实例快照见 FR-09；
- 条件字段必须从字段字典中选择，不接受自由文本字段名；保存时校验字段存在、对该资源类别可用、操作符与字段值类型匹配；
- 选择器只影响候选集合与后续新建任务，**不自动改写存量任务的已选实例**；
- 选择器是**筛选**语义，不产生任何资源标注或分类字段，也不回写 M07。

#### FR-23：一个 CI 支持多个采集器

- 同一资源可被多条采集任务选中，并因任务绑定的模板不同而使用不同采集实现（如 node-exporter 与 npu-exporter）、不同参数、不同标签模板；
- 任务与资源是多对多关系，系统**不限制**一个资源被多少条任务引用；重复选中同一资源不报错，由 M09 按各自任务生成独立 target；
- 资源视角提供「已被哪些任务 / 采集实现覆盖」的只读汇总，方便判断某台主机是否已具备多种采集能力；
- M01 不得假设「一个资源只有一种采集器」，也不得把多采集器压成单一模板字段。

#### FR-24：模板停用、引用保护与变更影响

- 停用模板后，新建任务的下拉中不再出现该模板；存量任务保留并标记「采集模板已停用」提示，允许查看、编辑选择器与停用，但不允许以此模板新建任务；
- 修改模板参数（路径 / 间隔 / 认证等）不影响存量任务已快照的参数，需用户主动「同步模板默认值」；模板默认端口按 FR-08 端口链实时求值，变更在下次预览 / 生成时生效，不改写 Job 快照；
- 删除模板前校验引用：存在采集任务 / 指标锚点引用时拒绝删除并回传引用清单；
- 模板的每次变更落只读修改快照（操作人、时间、旧值、新值）。

### 5.7 采集任务组与「对象优先」动线（并入基线）

> 完整需求（含组合筛选、分域预览、授权域收敛等细节）见 [增量 SRS](Module_01_Job_Group_and_Object_First_SRS.md)；本节为基线收口摘要，二者冲突时以增量文件细节为准并回填本节。

#### FR-25：对象优先创建

- 只有一个「新建采集任务」入口：先选任务类型（采集 / 拨测）与采集模板，再按可组合条件跨已授权网域筛选实例；
- 保存时按实例所属网域自动拆分为多条单域子 Job，并生成一个任务组；网域不是表单的第一个必填项。

#### FR-26：任务组与子 Job 的职责边界

- 任务组是用户看到的维护与展示单位；子 Job 保持单域语义（参数快照 + 网域），是 M09 的实际下发单元；
- 公共参数、凭据、标签模板与启用状态**归组管理**；子 Job 只允许修改实例选择与排障类动作，接口层校验并拒绝越权修改；
- `job_name` 唯一性按「网域 + 任务名」判定（跨域子 Job 共用同一任务名）。

#### FR-27：组级状态与整组启停

- 组级同步状态由子 Job 派生（全同步 / 部分失败 / 全失败 / 待同步 / 草稿），不落库、不双写；
- 支持整组启用 / 停用：停用后各域子 Job 不进入 M09 下发候选（行保留、可再启用）；启用前校验每个子任务至少保留一个实例；
- 域被禁用或退纳管时，组内子 Job 自动停用并保留，便于域恢复后人工重新启用。

#### FR-28：列表与候选查询

- 任务列表为单视图：跨域任务展示「覆盖网域」聚合，展开为逐域子任务；用户界面不出现「任务组 / 子任务 / `job_group_id`」等内部概念；
- 实例候选支持 schema 驱动的可组合筛选（AND）、分域汇总与全选（上限 2000），并按授权网域 fail-closed 收敛。

### 5.8 写操作边界

#### FR-29：写权限边界

- **内置采集模板**与指标库的写操作仅平台管理员可用（与 M05/M06/M09 的管理写接口口径一致）；读接口对所有登录用户开放；
- **自定义采集模板**与采集任务同权：登录用户可新建、编辑、删除自己创建的非内置模板；
- 非管理员前端隐藏内置模板与指标库的写入口与启用开关；服务端强制校验，非管理员返回 403；
- 采集实现池、采集任务的写操作本期仍对登录用户开放，后续由 M03 权限点细化。

## 6. 非功能需求

### 6.1 架构约束

#### NFR-01：M01 只维护策略数据

- M01 不生成 `prometheus.yml` / `rules.yml`，不触发 reload，不直接连接采集目标；
- 配置生成与下发由 M09 负责。

#### NFR-02：所有 Job 必须绑定采集节点域

- `network_domain_id` 必填，且必须是 M06 已登记、M09 已纳管的采集节点域；
- 不允许选择中心直连域/管理域；不存在 `default` 管理域特殊处理。

#### NFR-03：源数据变更自动触发同步

- M01 写库后维护 `updated_at`；
- M09 以 pull 模式轮询感知变化并自动生成配置包；
- M01 不主动通知 M09，也不假设保存即生效。

#### NFR-04：同步失败不锁死源数据

- 当 M09 校验失败且归因为 `user_config` 时，M01 源数据不被长期锁定；
- 用户可直接编辑修正后重新保存，新保存会再次触发同步。

### 6.2 数据一致性

#### NFR-05：选中关系一致性

- M07 删除资源时，M01 各 Job 的 `selected_instance_ids` 同步回收；
- 资源转 `offline` 后，M09 下一配置生成周期自动从 targets 中移除。

#### NFR-06：参数快照稳定性

- ScrapeJob 保存时快照当前采集模板参数；
- 后续默认配置变更不影响已存在 Job，除非用户主动同步。

### 6.3 安全与隔离

#### NFR-07：网域作用域校验

- 实例候选必须与 Job 所属网域一致；
- 规则 `job` 引用校验基于全平台生效 Job 并集（规则由中心集中求值，允许跨网域引用）。

#### NFR-08：权限控制

- 内置采集模板与指标库的写接口（POST/PUT/DELETE）**仅平台管理员**可用，其余登录用户只读；前端隐藏写入口，服务端 `RequireAdmin` 兜底返回 403；
- 自定义采集模板与采集任务同权，登录用户可写；采集实现池的写操作本期对登录用户开放；细粒度权限点由 M03 落地后补充；
- 安装确认、实例选择等运维动作沿用登录态，不允许匿名访问。

### 6.4 可用性

#### NFR-09：用户语言一致性

- 用户界面统一使用「采集模板 / 采集实现 / 采集任务 / 筛选条件 / 拨测 / 监控规则 / 同步状态」等业务语言；
- 技术术语（`scrape_interval`、`blackbox_module`、`inhibit_rules` 等）仅出现在折叠区、代码注释或接口文档。

#### NFR-10：错误提示可执行

- 同步失败、`job` 引用不匹配、实例越网等错误须给出下一步操作指引。

### 6.5 可扩展性

#### NFR-11：模板与选择器扩展不依赖代码变更

- 新增采集模板、调整任务选择器条件、绑定新的采集实现，均通过配置完成，**不修改后端代码、不重新打包发版**；
- 采集模板在读取侧可用内存缓存，写操作后失效缓存即可，不因查库引入明显延迟；
- 选择器条件的解释必须基于受控字段字典与固定映射，用户输入（字段名、值）只能作为参数绑定，禁止拼接进 SQL；
- 字段字典来自 M07：内置字段走 M01 固定映射（随版本扩展），自定义字段通过 `资源 × key × value` 通用匹配，**M07 新增自定义字段后无需 M01 发版即可参与筛选**；
- 模板与字段字典的内置种子数据须幂等：存量环境升级后自动补齐内置模板，且不覆盖用户已修改的配置。

## 7. 数据需求（概念级）

### 7.1 核心实体

| 实体 | 说明 | 关键属性 |
|------|------|----------|
| CollectionTemplate | 采集模板 | 编码、展示名、资源类别、采集实现、参数集、标签模板、启用状态、内置标记 |
| ExporterTemplate | 采集实现池 | 名称、来源、OS/Arch、下载地址、安装指南、默认端口 |
| ScrapeJob | 采集任务（单域） | 名称、类型、采集模板、网域、选择器、参数快照、已选实例、状态；`job_group_id` 关联任务组 |
| JobGroup | 采集任务组（监控意图） | 名称、公共参数 / 凭据、启用状态；按实例所属网域扇出子 Job |
| MonitoringRule | 监控规则 | 名称、类型（yaml_passthrough/structured）、内容、启用状态、同步状态 |
| ExporterMetricLibrary | 技术指标库 | 指标名、类型、HELP、UNIT、采集模板锚点 |
| BusinessMetric | 业务指标库 | 指标名、业务语义、阈值、业务域、负责人、状态 |
| ExporterInstallationConfirmation | 安装登记 | resource_id、scrape_job_id、状态、端口、备注 |

### 7.2 核心关系

- **CollectionTemplate → ExporterTemplate**：多对一（一个模板恰好一个采集实现；同一实现可被多个模板复用）；
- **CollectionTemplate → LabelTemplate（M07）**：一对一引用（模板是标签模板的唯一引用点）；
- **ScrapeJob → CollectionTemplate**：多对一（创建时继承模板参数并快照；端口不落快照，按 FR-08 实时求值）；
- **ScrapeJob → Resource（M07）**：通过选择器**隐式筛选** + `selected_instance_ids` 显式快照，语义上为多对多——一个资源可被多条任务引用，且不向 M07 回写任何字段；**一个 CI 可被多条任务引用，即一个 CI 可有多个采集器**；
- **JobGroup → ScrapeJob**：一对多（一个任务组按实例所属网域拆成多条单域子 Job；公共参数、凭据与启停状态归组管理）；
- **MonitoringRule → ScrapeJob**：规则表达式引用校验；
- **ExporterMetricLibrary → CollectionTemplate**：多对多；
- **M01 → M09**：M09 轮询消费 ScrapeJob/MonitoringRule 生成配置包。

## 8. 关键流程

### 8.1 创建 ScrapeJob 流程

1. 用户选择采集模板；
2. 系统自动带出模板参数（采集实现、路径 / 间隔 / 超时、标签模板）；端口不进 Job 快照，按 FR-08 端口链实时求值；
3. 用户设定筛选条件（资源类别继承自模板，条件行来自字段字典），系统实时回显命中资源数；
4. 用户选择所属网域，跨域时按域分组预览命中数；
5. 用户确认实例（默认全选、可排除）并覆盖必要参数（端口除外，端口由端口链决定）；
6. 保存后 `draft_status=ready`；
7. M09 轮询检测到变化，自动生成配置包；
8. 采集节点拉取配置并开始采集；
9. M01 展示同步状态与采集状态。

### 8.2 保存 MonitoringRule 流程

1. 用户上传/粘贴 YAML 或填写字段化规则；
2. 后端执行 YAML 语法、`groups` 结构、组名唯一性、`job` 引用分级校验；
3. 校验失败返回行级错误，不入库；
4. 校验通过后落库 `MonitoringRule`，`draft_status=ready`；
5. M09 在中心侧生成 rules 产物并 reload 中心 Prometheus；
6. 中心 Prometheus 加载新规则。

### 8.3 Blackbox 拨测 Job 流程

1. 用户选择 `job_type=blackbox`；
2. 选择 `resource_type`（`interface_service` / `application`）；
3. 系统按网域收敛候选资源；
4. 用户勾选目标，`target_field` 只读派生地址；
5. 保存后 M09 生成 blackbox 配置。

### 8.4 配置同步状态流程

1. M01 源数据保存/启用/禁用/删除；
2. M09 计算源数据版本并生成配置包；
3. M09 返回同步结果与校验和；
4. M01 将同步状态回写到 Job/规则；
5. 同步失败时 M01 展示失败原因并允许用户修正。

### 8.5 资源删除清理流程

1. M07 删除某 Resource；
2. M01 内置对账循环（pull 模式，默认 60s、可配置）发现已选中实例已不存在，自动从所有 Job 的 `selected_instance_ids` 中回收该资源（D40；M07 不反向依赖 M01，无跨模块同步调用、不引入外键/触发器）；
3. Job 保存与 targets 生成时仍对实例存在性做强校验兜底；
4. M09 下一周期生成配置时该 target 自动移除。

### 8.6 新增采集模板并建任务流程

1. 运维架构师进入「采集模板」页，点击「新增模板」；
2. 填写模板编码、展示名，选择归属的资源类别（如 `host`）；
3. 选择采集实现（如 npu-exporter）、填写参数集（端口 / 路径 / 协议 / 间隔 / 超时）、绑定标签模板；
4. 保存后模板即刻可用于新建任务；
5. 新建采集任务时选择该模板，在「采哪些对象」中添加条件（从字段字典选字段，如 `has_npu`、操作符 `等于`、值 `true`），需要多条条件时设置组合方式 `all` / `any`；
6. 系统校验字段合法性、操作符与值类型匹配，并实时展示「当前命中资源数」与分域预览；
7. 确认实例后保存；若这批资源已被其他任务采集（如既有 Linux 主机又带 NPU），无需迁移或重复登记资源，新建第二条任务指向同批实例即可实现「一个 CI 多个采集器」。

## 9. 验收标准

> 本节是「验收意图」的唯一权威；§4 的「成功标准」与 §5 的 FR 是需求描述，最终验收以本节为准。每个 SCN 的演示脚本见 `docs/05-execution-records/module-01/scenario-walkthrough.md`，走查反馈与验收结论记录在 [Scenario Link](../../../07-design/Module_01_Scenario_Link.md)，不在本文重复。

### 9.1 场景验收（需求方语言）

| SCN | 可观察结果 |
|-----|------------|
| SCN-01 新增一种采集能力（NPU） | 新增模板即可用于建任务；条件命中可见；同主机双任务并存；全程无代码变更 |
| SCN-02 创建跨网域采集任务 | 跨域筛选与分域预览可见；保存后逐域子任务生成；整组启停生效 |
| SCN-03 配置并检查告警规则 | 检查能定位组/规则；error 阻断、warning 高亮；保存后中心生效 |
| SCN-04 排查同步失败与采集异常 | 同步状态与失败原因可读；实例采集状态可区分；删除资源后自动回收 |
| SCN-05 采集模板治理与变更影响 | 停用/改参/删除的影响面可预期；存量任务不被静默改变 |
| SCN-06 维护技术指标库 | 内置只读、用户可扩展、锚点挂模板、重复登记被拒 |

### 9.2 功能验收明细

- [ ] 支持维护采集模板（编码 / 展示名 / 资源类别 / 采集实现 / 参数集 / 标签模板），一个模板恰好绑定一个采集实现。
- [ ] 支持采集实现池管理，包含来源、OS/Arch、下载地址、安装指南、默认端口。
- [ ] 创建 ScrapeJob 时自动继承采集模板参数，支持 Job 级覆盖与同步模板默认值。
- [ ] ScrapeJob 必须绑定一个已登记且已纳管的采集节点域，不允许选择中心直连域。
- [ ] 仅 `draft_status=ready` 且 `enabled=true` 的 Job 进入 M09 配置同步候选集。
- [ ] 支持通过选择器（资源类别 + 条件 + `all` / `any`）筛选实例，实时展示命中数与分域预览，`offline` 实例置灰不可选。
- [ ] 支持在「采集模板」新增 / 编辑 / 启停模板，保存后立即可用于新建任务，无需改代码或发版。
- [ ] 选择器字段必须来自 M07 字段字典（内置字段 + 自定义字段），用户输入不得拼接进 SQL。
- [ ] 一个资源可被多条采集任务引用（一个 CI 多个采集器），任务之间互不影响。
- [ ] NPU 主机由 `has_npu 等于 true` 条件 + NPU 采集模板采集，可与 Linux 主机任务同时生效。
- [ ] 端口按「实例 `scrape_port` → 采集模板默认端口 → 类别兜底（数据库 / 中间件回退业务端口，主机回退采集实现默认端口）」三级链解析，不做网域级覆盖。
- [ ] 停用模板后不可用于新建任务，存量任务保留并显示「采集模板已停用」提示；删除有引用的模板被拒绝并回传引用清单。
- [ ] 内置采集模板仅平台管理员可编辑，自定义采集模板登录用户可新建。
- [ ] 支持 Blackbox 拨测 Job，目标从 `interface_service` / `application` 资源选择，`target_field` 只读派生。
- [ ] 支持监控规则 YAML 文件透传模式，提供「检查 → 提交」两段式与 `job` 引用分级校验。
- [ ] 规则校验失败时返回行级错误；error 级不匹配可逃生门覆盖。
- [ ] Job/规则列表展示同步状态（已同步 / 待同步 / 同步失败 / 草稿）与失败原因。
- [ ] Job 详情/编辑抽屉展示实例级采集状态（待采集 / up / stale / down / unknown）。
- [ ] 支持技术指标库与业务指标库管理。
- [ ] 管理员可在「采集模板」新增模板后，立即在「指标库」为用户扩展指标挂接该模板；非管理员看不到内置模板与指标库写入口，直调写接口返回 403。
- [ ] 内置指标只读；用户扩展指标可编辑 / 删除；同名指标 + 任一相同锚点重复登记返回 409；指标名与标签键按 Prometheus 规则校验。
- [ ] 采集任务支持整组启用 / 停用：停用后各域子任务不再进入下发候选，重新启用回到「待同步」；启用前校验至少保留一个实例。
- [ ] 规则「检查」通过时展示「N 个组 / M 条规则 · PromQL 校验通过 / 未执行」；失败时给出可定位到组 / 规则的原因。
- [ ] 指标库筛选的「采集模板」选项随模板列表同步（手动新增模板无需刷新页面即可选到）。
- [ ] M07 删除资源时，M01 同步回收各 Job 的选中关系。

### 9.3 非功能验收

- [ ] M01 不直接生成 Prometheus 配置或触发 reload。
- [ ] 所有 ScrapeJob 必须绑定采集节点域，无中心直连域特殊逻辑。
- [ ] M09 以 pull 模式轮询 M01 源数据变化，M01 不主动通知。
- [ ] 同步失败时源数据不被长期锁定，用户可编辑后重新触发同步。
- [ ] 实例候选与 `job` 引用校验严格限制在 Job 所属网域范围内（规则 job 引用按全平台生效 Job 并集）。
- [ ] 内置采集模板与指标库的写操作在服务端强制校验管理员身份（非管理员 403），不依赖前端隐藏。
- [ ] 用户界面统一使用业务语言，错误提示给出可执行指引。
- [ ] 新增采集模板 / 调整选择器条件全程不修改代码、不重新打包发版，仅通过界面配置完成。
- [ ] M07 新增自定义字段后，无需 M01 发版即可作为选择器条件使用。
- [ ] 内置模板种子数据幂等：存量环境升级后自动补齐，且不覆盖用户已修改的配置。

## 10. 依赖与风险

### 10.1 模块依赖

| 依赖方 | 依赖内容 | 说明 |
|--------|----------|------|
| Module 06 | 网域行政与授权 | Job 必须选择 M06 已登记网域 |
| Module 07 | 资源、资源类别、标签模板、CI 模型字段字典（内置字段 + 自定义字段） | M01 只读消费候选实例、标签模板与字段字典；按任务选择器筛选资源，不向 M07 回写任何策略或分类字段 |
| Module 09 | 配置同步与目标状态查询 | M09 轮询生成配置包并集中求值规则，M01 展示同步状态；Job 采集状态回显数据来源（原 M02 查询面已并入 M09） |
| Module 08 | Alertmanager 配置 | M01 提供规则内容，M08 负责通知收敛 |

### 10.2 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| M09 自动同步失败导致用户误以为保存未生效 | 体验差 | M01 列表实时展示同步状态与失败原因 |
| 所有网域都是采集节点域后，MVP 最小部署需先完成网域纳管 | 上手门槛提高 | 首页使用指引引导用户先登记网域、部署采集节点 |
| 取消变更确认后，错误配置可能直接下发 | 监控断点或误告警 | 加强 M01 自身校验（`amtool`、job 引用、实例存在性）；M09 校验失败不覆盖当前配置 |
| 历史 `change_status` pending/confirmed/deployed 代码残留 | 状态不一致 | 重写 SRS 后同步清理 M01 状态机，替换为同步状态 |
| 选择器条件配置错误（字段选错、值不匹配）导致候选实例为空 | 用户以为没资源可选 | 条件编辑时实时展示「当前命中资源数」；命中为空给出「检查筛选条件」引导入口；条件变更不自动改写存量任务 |
| 一个模板被多条任务复用后，修改模板参数影响面扩大 | 多条任务同时受影响 | 参数变更不影响存量任务快照，需用户主动「同步模板默认值」；删除模板前校验引用并回传清单 |
| M07 移出某字段后，M01 侧已有选择器条件失效 | 候选查询命中异常 | M01 只读字段字典；字段失效时把条件标记为「字段已失效」并在任务编辑处提示修正 |
| 内置类型种子与用户配置冲突 | 升级覆盖用户改动 | 种子写入按「不存在才插入」幂等执行，不覆盖已有记录 |
| 指标锚点为 JSON 数组，数据库无法建 `(metric_name, template_code)` 唯一索引 | 并发写入可能产生重复行 | 服务层判重并返回 409；后续可拆锚点子表加唯一索引 |
| 规则 PromQL 语义校验依赖外部 `promtool` | 不可用时校验降级为「未执行」，无效表达式可能被保存 | 部署保证 `promtool` 在 PATH（Makefile 已处理）；检查结果明确展示「未执行」 |
| 管理员写权限依赖全局角色（admin / user） | M03 权限点落地前粒度较粗 | 本期仅收口内置采集模板与指标库；M03 落地后统一切换权限点 |

## 附录 A 文档关系与需求追溯

本文档是面向业务方和产研团队的**需求规格说明书**，强调「为什么做」和「做成什么样」。历史文档已移除（2026-11-20），Git 历史可追溯；实现细节以概要设计、接口契约与代码为准。两者关系如下：

- 本文档用于**需求评审、范围确认、验收依据**。
- 概要设计、接口契约与代码用于**开发实现、接口对接、测试用例设计**。
- 若本文档与概要设计/接口契约存在冲突（尤其是 M09 变更确认/回滚取消、所有网域统一为采集节点域、同步状态替代变更单状态），以本文档的当前业务口径为准，由产品负责人决定是否反向修订概要设计/接口契约。
