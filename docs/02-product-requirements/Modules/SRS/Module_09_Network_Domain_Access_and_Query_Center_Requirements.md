## 1. 文档目的

本文档用**便于人理解的语言**记录合并后的 M09 模块的业务需求、功能需求与非功能需求。它站在产品经理和运维架构师的视角，说明「采集节点如何接入中心」「接入后如何观测目标与查询指标」，并为后续概要设计、详细设计、开发、测试提供依据。

本文档不直接定义 API 字段级别的技术契约（历史技术 PRD 已覆盖），而是回答：**在新的中心-采集节点架构下，这个模块为什么存在、必须具备哪些能力、做到什么程度算合格**。

## 2. 业务背景

### 2.1 从三个模块到一个模块

在原有模块划分中：

- **Module 09** 负责配置生成、变更确认、下发与回滚（配置面）；
- **Module 11** 负责网域纳管、采集节点生命周期与 edge 协议（接入面）；
- **Module 02** 负责指标查询与目标状态展示（查询面）。

这三者在实际业务中围绕同一个对象——**网域**——工作：先让网域接入，再让采集节点拉配置、出数据，最后让用户查目标与指标。将三者合并后，可以形成一个从「接入」到「观测」的完整闭环，减少跨模块协调成本。

### 2.2 配置同步去确认化

原 M09 的「配置变更确认 / 回滚」流程虽然提供了风控卡点，但在当前业务阶段被明确判定为**不需要**。因此，本模块将配置生成降级为**后台自动同步服务**：

- M01 / M07 源数据变化后，自动生成当前网域配置包；
- 通过校验后直接作为当前版本供采集节点拉取；
- 保留最近 3~5 份只读历史用于排障，但**不支持回滚**。

### 2.3 中心网域也需要采集节点

在新的扁平化架构下，**中心节点只负责管理与存储**，即使是中心节点所在的网域，其监控目标的抓取、拨测、配置同步也由部署在该网域内的一台采集节点完成。中心节点本身不直接发起 scrape/probe。

这意味着：

- 不存在「中心直连域」或「管理域」的特殊类型；
- 所有网域（包括中心所在网域）都是采集节点域；
- 每个网域都需要完成「纳管 → 安装采集节点 → 心跳上线」的相同流程。

### 2.4 一句话定位

> M09 回答的问题是：**「采集节点如何接入中心，以及接入后用户如何查看目标状态和查询指标」**。

## 3. 核心概念

### 3.1 网域接入与查询中心

- **业务含义**：负责网域监控纳管、采集节点生命周期、配置同步、目标状态查询、实时指标查询的统一模块。
- **与 M06 的边界**：M06 是网域的**行政 Owner**（名称、云归属、网络分区、授权租户、启用/禁用）；本模块是网域的**接入与查询 Owner**（Token、通道、纳管状态、运行态、配置包、查询代理）。
- **与 M01/M07 的边界**：M01 / M07 是源数据 Owner；本模块只读消费其数据生成配置包，不修改源数据。

### 3.2 采集节点域（唯一网域类型）

- 所有网域均为采集节点域，用户侧统一称为「网域」；
- 下发通道统一为 `agent_pull`（采集节点主动拉取配置包）；
- 不再存在 `management` / `local` / 中心直连域等概念；
- 系统**不再预置 `default` 管理域**；如需一个与中心同区域的网域，也必须在 M06 登记并按采集节点域纳管。

### 3.3 采集节点 / Edge Sync Agent

- 部署在具体网域内的监控执行单元；
- 职责：心跳上报、拉取配置包、对本域目标执行抓取/拨测、通过 remote write 回传指标；
- 用户侧统一称为「采集节点」，技术文档中可使用 Edge Sync Agent。

### 3.4 配置同步服务（简化版）

- 后台监听 M01 / M07 源数据变化，按网域生成配置产物；
- 边缘配置包产物形态：Prometheus 主配置（scrape_configs + file_sd 引用）、targets 文件、拨测文件等；**不含规则文件**——告警/记录规则统一在中心 Prometheus 集中求值（D35），由本模块在中心侧生成 rules 产物并 reload；
- 通过边缘协议供采集节点拉取；
- 保留当前版本与最近 3~5 份只读历史，不支持人工确认与回滚；
- 生成失败时不覆盖当前生效版本，避免配置断点。

### 3.5 目标状态与指标查询

- **目标状态**：通过 `/api/v1/targets` 展示采集目标健康状态，数据来源包括 Prometheus 中心 targets 与边缘 target 快照的融合；
- **指标查询**：通过 `/api/v1/query*` 等接口代理 Prometheus 原生查询能力；服务端按当前租户解析被授权网域集，并自动按网域过滤实现数据隔离（不注入 `tenant` 标签，写入侧数据面无此标签）。

## 4. 目标用户与使用场景

### 4.1 目标用户

| 用户角色 | 关注点 | 典型操作 |
|----------|--------|----------|
| 运维架构师 | 网域规划、采集节点部署 | 登记并纳管网域、下载离线包 |
| 运维工程师 | 采集节点健康、目标状态 | 查看节点状态、重置 Token、查看目标状态 |
| SRE / 值班工程师 | 指标排查 | 执行 PromQL 查询、查看告警状态 |
| AI 应用开发者 | 稳定的数据接口 | 通过 API 查询指标 |

### 4.2 典型使用场景

#### 场景 1：新网域接入监控

- **角色**：运维架构师
- **触发**：新增一片网络域，需要纳入监控
- **目标**：完成从行政登记到采集节点上线的闭环
- **成功标准**：
  - 在 M06 完成网域登记；
  - 在本模块完成网域纳管并获取 Token；
  - 下载离线包并在目标网域部署采集节点；
  - 采集节点心跳上线，配置同步成功。

#### 场景 2：排查采集节点离线

- **角色**：运维工程师
- **触发**：某网域采集节点显示离线
- **目标**：快速定位节点状态
- **成功标准**：
  - 节点列表展示最后心跳、回传积压、配置版本；
  - 可查看组件运行态与 crash-loop 状态；
  - 可远程触发重启采集进程或清空回传积压。

#### 场景 3：查看监控目标状态

- **角色**：运维工程师
- **触发**：怀疑某 Job 的目标没有采到数据
- **目标**：查看目标健康状态
- **成功标准**：
  - `/api/v1/targets` 融合展示中心与边缘目标；
  - 可按网域、Job、健康状态筛选；
  - 下线/离线目标高亮提示。

#### 场景 4：实时指标查询

- **角色**：SRE
- **触发**：排查故障需要查看 CPU / 内存 / 请求量趋势
- **目标**：在安全隔离的前提下查询指标
- **成功标准**：
  - 支持 PromQL instant / range 查询；
  - 自动按被授权网域过滤（授权网域集由服务端按当前租户解析），越权返回空；
  - 响应 envelope 展示数据来源与新鲜度。

## 5. 功能需求

### 5.1 网域纳管

#### FR-01：已登记网域的监控纳管

- 本模块只消费 M06 已登记且处于 `enabled` 状态的网域；
- 纳管时填写监控参数（回传地址等），系统自动签发接入 Token；
- 纳管后网域进入 `monitored` 状态；
- 一个网域在同一时刻只对应一个生效 Token。

#### FR-02：Token 生命周期管理

- 支持 Token 生成、重置、废止；
- Token 在 UI 中**完全脱敏**，完整值仅通过「复制」按钮在弹窗内单次获取；
- 重置 Token 后旧 Token 立即失效，旧采集节点心跳鉴权失败后自然离线；
- 删除/退纳管网域时废止 Token。

#### FR-03：安装指引与离线包下载

- 提供统一的采集节点安装指引，不再区分中心直连域/采集节点域；
- 安装指引包含：下载离线包 → 解压部署 → 配置 `CENTER_ENDPOINT` 与 Token → 启动 Agent → 心跳回连；
- 提供一体化离线安装包下载，附带 sha256 校验和。

#### FR-04：纳管状态机

- 纳管状态包括：`created`（未纳管）、`monitored`（已纳管）；
- {v0.2+} 支持退纳管：废止 Token → 停止配置下发 → 状态归位 `created`；
- M06 删除网域时，本模块在同一次请求内完成级联清退（废止 Token / 停止下发 / EdgeAgent 标 `retired`）。

### 5.2 采集节点状态

#### FR-05：EdgeAgent 记录与自动注册

- 采集节点首次携带有效 Token 心跳时自动注册；
- 记录字段包括：所属网域、主机名、IP、Agent 版本、组件清单等。

#### FR-06：心跳接收与在线/离线判定

- 心跳接口接收节点状态、组件状态、targets 快照、回传指标等；
- 按最后心跳时间与阈值判定 `online` / `offline`；
- 心跳历史保留 7 天（可调），并定期清理防止表无限增长。

#### FR-07：配置同步状态展示

- 节点列表展示每个节点当前拉取的配置版本/校验和；
- 当中心配置更新但节点尚未拉取时，展示「待同步」；
- 同步失败时展示失败原因。

#### FR-08：组件运行态与 crash-loop 观测

- 展示采集器（vmagent）、拨测器等组件的运行状态；
- 展示重启次数与 crash-loop 熔断状态；
- crash-loop 节点高亮提示。

#### FR-09：远程指令（outbound-only）

- 支持通过心跳响应向节点透传两条指令：
  - 重启采集进程（`vmagent_restart_seq`）
  - 清空回传积压（`flush_backlog_seq`）
- 中心不主动入站连接节点，指令由节点拉取执行，seq 机制保证幂等。

### 5.3 配置同步（简化版）

#### FR-10：自动配置生成

- 监听 M01（ScrapeJobs / Rules）与 M07（Resources / LabelTemplates）数据变化；
- 按网域生成 Prometheus 配置产物（主配置、targets、拨测文件等）；规则不下发到边缘，统一由中心 Prometheus 集中求值（D35）：本模块在中心侧生成 rules 产物，经 promtool 校验后原子写入并触发中心 Prometheus reload（`/-/reload`），失败不覆盖当前生效版本；
- 生成失败时保留当前生效版本，避免监控断点。

#### FR-11：配置包供采集节点拉取

- 配置产物打包后通过边缘协议接口供采集节点心跳拉取；
- 心跳响应中包含 `config_changed` 标志与配置包下载地址/校验和；
- 配置包含凭据明文，仅校验 Token 后返回。

#### FR-12：下发前校验

- 对生成的配置产物做语法与结构校验（promtool、blackbox 模块、targets JSON 等）；
- 校验失败时标记当前版本为失败状态，记录失败原因，不对外发布；
- 区分「用户配置问题」与「平台故障」归因。

#### FR-13：只读历史版本

- 保留最近 **3~5 份**配置历史，用于排障与审计；
- 历史版本只读展示，**不支持回滚**；
- 超出保留数量的旧版本自动清理。

#### FR-14：M08 告警配置同步

- M08 通过 `AlertmanagerSnapshotSink` 端口将生效的 `alertmanager.yml` 快照写入本模块，仅用于统一配置视图与版本留痕，**不扇出到任何网域配置包**（D31）；
- 本模块不为 M08 单独维护变更确认流程。

### 5.4 目标状态查询

#### FR-15：目标状态融合查询

- 提供 `/api/v1/targets` 接口，融合以下数据源：
  - 中心 Prometheus `/api/v1/targets`（保留兼容；按 NFR-01 中心不发起 scrape，正常为空）；
  - 边缘采集节点心跳上报的 target 快照。
- 返回字段包括：job、instance、network_domain、health、lastScrape、lastError、instance_name 等。

#### FR-16：采集覆盖率查询

- 提供 `/api/v1/health/coverage` 接口，返回采集状态三态（采集中 / 已下发未采到 / 未监控）；
- 供 M07 资源列表 badge 消费。

#### FR-17：目标状态筛选

- 支持按网域、Job、健康状态（up/down/unknown）、关键字筛选；
- 分页返回，避免大数据量拖慢页面。

### 5.5 实时指标查询

#### FR-18：Prometheus 查询代理

> API 版本口径（D38）：下列为 Prometheus 原生语义子路径，实施期统一挂载在 `/api/v3/platform/*` 前缀下，权威路径以 api-contract-snapshot-v3 为准。

- 提供以下接口，代理到中心 Prometheus：
  - `POST /api/v1/query`
  - `POST /api/v1/query_range`
  - `GET /api/v1/labels`
  - `GET /api/v1/label/:name/values`
  - `GET /api/v1/series`
  - `GET /api/v1/alerts*`

#### FR-19：统一响应 envelope

- 响应包含 `status`、`data` 以及 `meta` 字段：
  - `data_source`：数据来源
  - `freshness_at`：数据新鲜度时间
  - `network_domains`：本次查询覆盖的网域

#### FR-20：网域上下文注入

- 查询转发前，服务端按当前租户解析被授权网域集（M06 D17），并在 PromQL/匹配器中注入 `network_domain_id` 标签约束；
- 不注入 `tenant` 标签——写入侧 `external_labels` 仅含 `network_domain_id`，数据面无 `tenant` 标签；
- 任何用户（含 `platform_admin`）不具备 bypass 能力；
- 无权限网域或未带网域标签的数据不可见（返回空，不报错）。

### 5.6 离线包与版本管理

#### FR-21：离线包版本管理

- 维护中心发布的 Edge Sync Agent 版本列表；
- 节点状态页展示节点当前版本与中心最新版本差异；
- 提供升级指引与离线包下载。

## 6. 非功能需求

### 6.1 架构约束

#### NFR-01：中心节点不直接采集

- 中心节点不直接发起 scrape/probe；所有面向监控目标的采集行为由网域内采集节点执行。

#### NFR-02：所有网域均为采集节点域

- 不再存在中心直连域/管理域；`domain_type` 不再包含 `management`；
- 下发通道统一为 `agent_pull`；
- 中心节点所在网域也需部署采集节点。

#### NFR-03：Outbound-only 安全边界

- 中心不主动入站连接采集节点；
- 所有指令（重启、清空积压）通过心跳响应由节点拉取执行。

### 6.2 数据一致性与可靠性

#### NFR-04：配置同步原子性

- 配置生成、校验、标记为当前版本应为原子或幂等操作；
- 生成失败不得覆盖当前生效版本。

#### NFR-05：配置历史只读

- 历史版本仅用于排障与审计，禁止通过接口恢复为当前版本。

#### NFR-06：心跳与快照清理

- 心跳历史保留策略可配置（默认 7 天），并自动清理；
- target 快照在资源删除/Job 清空/退纳管/网域删除时同步清理，避免残留。

### 6.3 安全性

#### NFR-07：Token 安全

- Token 使用高强度随机字符串；
- 数据库**仅存哈希**（SHA-256），明文仅在纳管成功/重置时完整展示一次，任何接口/日志不返回明文（D39）；
- Token 重置/废止立即生效。

#### NFR-08：数据隔离

- 查询与目标状态按网域隔离：服务端按当前租户解析被授权网域集，查询时注入 `network_domain_id` 标签约束（不注入 `tenant`，写入侧数据面无此标签），越权不可见；
- 目标状态接口只返回用户被授权网域的数据。

### 6.4 性能与可用性

#### NFR-09：查询性能

- `/api/v1/query*` 代理响应时间接近原生 Prometheus，附加注入与过滤开销 ≤ 50ms（P95）；
- `/api/v1/targets` 禁止逐行查询时序数据，依赖预聚合或快照。

#### NFR-10：用户语言一致性

- 用户界面统一使用「网域 / 采集节点 / 目标状态 / 指标查询」等业务语言；
- 技术术语（`agent_pull`、`Edge Sync Agent` 等）仅出现在折叠区、代码注释或接口文档。

#### NFR-11：错误提示可执行

- 配置校验失败、节点离线、查询越权等错误须给出下一步操作指引。

## 7. 数据模型概述

### 7.1 核心实体

| 实体 | 说明 | 关键属性 |
|------|------|----------|
| NetworkDomain（纳管字段） | 网域接入属性 | `channel`、`token`、`remote_write_url`、`center_endpoint`、`registration_status`、运行态 |
| EdgeAgent | 采集节点记录 | 所属网域、状态、版本、配置版本、组件状态、重启次数、crash-loop、最后心跳 |
| EdgeHeartbeat | 心跳原始记录 | 节点 ID、时间、状态、targets 快照、回传指标、指令 seq |
| DomainConfigSnapshot | 网域配置快照 | 网域 ID、配置内容/校验和、生成时间、校验状态、是否当前版本 |
| EdgeTargetSnapshot | 边缘目标快照 | 节点 ID、job、labels、target_url、last_scrape、state |

### 7.2 核心关系

- **网域（M06） → 本模块**：M06 维护行政字段，本模块维护纳管/运行态字段；
- **网域 → EdgeAgent**：一个网域可有多个采集节点（MVP 通常为 1 个，v0.4+ 支持多节点）；
- **EdgeAgent → EdgeHeartbeat**：一对多；
- **EdgeAgent → EdgeTargetSnapshot**：一对多；
- **网域 → DomainConfigSnapshot**：一个网域当前仅一个生效版本，保留 3~5 份历史。

## 8. 关键流程

### 8.1 网域纳管流程

1. 用户在 M06 登记网域（名称、云归属、网络分区等）。
2. 进入本模块「网域纳管」页，选择已登记网域。
3. 系统填写默认监控参数，用户确认后自动签发 Token。
4. 用户复制 Token，下载离线安装包。
5. 在目标网域部署采集节点，配置 `CENTER_ENDPOINT` 与 Token。
6. 采集节点首次心跳自动注册，状态变为 online。

### 8.2 采集节点上线流程

1. 采集节点启动后按固定周期向中心发送心跳。
2. 中心校验 Token，若该节点未注册则自动创建 EdgeAgent 记录。
3. 心跳响应携带 `config_changed` 与配置包下载信息。
4. 节点检测到配置变化后拉取最新配置包并应用。
5. 节点开始对本域目标执行抓取/拨测，并通过 remote write 回传指标。

### 8.3 配置同步流程

1. M01 / M07 源数据变化后更新 `updated_at`。
2. 配置同步服务轮询或接收即时触发，按网域生成配置产物。
3. 对产物执行语法/结构校验。
4. 校验通过后保存为新的 `DomainConfigSnapshot`，并标记为当前版本。
5. 旧当前版本移入历史，超出 3~5 份时删除最旧版本。
6. 采集节点下次心跳拉取新配置。

### 8.4 目标状态查询流程

1. 用户请求 `/api/v1/targets`，携带当前租户上下文。
2. 后端按授权网域过滤：
   - 读取中心 Prometheus targets（如有）；
   - 读取边缘 `EdgeTargetSnapshot`；
3. 合并去重，补充 `instance_name` 等展示字段。
4. 返回融合后的目标状态列表。

### 8.5 指标查询流程

1. 用户请求 `/api/v1/query*`。
2. 后端校验用户身份与授权网域。
3. 在 PromQL 中自动注入 `network_domain_id` 标签约束（授权网域集由服务端按当前租户解析，不注入 `tenant`）。
4. 代理到中心 Prometheus 执行查询。
5. 包装统一 envelope 后返回。

### 8.6 Token 重置与网域退纳管/删除流程

1. **Token 重置**：用户点击重置 → 生成新 Token → 旧 Token 立即失效 → 使用旧 Token 的节点心跳鉴权失败转 offline。
2. **退纳管**（v0.2+）：废止 Token → 停止配置下发 → 纳管状态归位 `created`。
3. **网域删除**（由 M06 触发）：M06 软删网域 + 本模块废止 Token / 停止下发 / EdgeAgent 标 `retired`；任一环节失败整体回滚。

## 9. 验收标准

### 9.1 功能验收

- [ ] 系统不再预置 `default` 管理域；所有网域均需在 M06 登记并按采集节点域纳管。
- [ ] 网域纳管支持选择 M06 已登记网域、自动签发 Token、提供安装指引与离线包下载。
- [ ] Token 在 UI 中脱敏展示，完整值仅单次复制获取；重置后旧 Token 立即失效。
- [ ] 采集节点首次有效心跳自动注册，后续心跳更新状态、回传 targets 快照与组件状态。
- [ ] 节点列表展示在线/离线状态、最后心跳、配置同步状态、回传积压、组件运行态、crash-loop 状态。
- [ ] 支持通过心跳响应透传「重启采集进程」与「清空回传积压」指令，seq 机制保证幂等。
- [ ] 配置同步监听 M01/M07 变化，自动生成配置包并通过边缘协议供节点拉取。
- [ ] 配置产物通过 promtool/blackbox/targets schema 校验；失败不覆盖当前版本。
- [ ] 保留最近 3~5 份只读配置历史，不支持回滚。
- [ ] `/api/v1/targets` 融合中心 targets 与边缘 target 快照，按授权网域过滤。
- [ ] `/api/v1/health/coverage` 返回采集覆盖率三态，供 M07 消费。
- [ ] `/api/v1/query*` 代理 Prometheus 原生接口，自动注入 `network_domain_id` 网域标签（不注入 `tenant`），返回统一 envelope。
- [ ] M08 生效的 `alertmanager.yml` 快照同步到本模块留痕，不进入任何网域配置包。

### 9.2 非功能验收

- [ ] 中心节点不直接发起 scrape/probe；所有采集行为由网域内采集节点执行。
- [ ] 不存在 `management` / 中心直连域概念；下发通道统一为 `agent_pull`。
- [ ] 中心不主动入站连接节点；指令通过心跳响应由节点拉取。
- [ ] Token 安全存储，接口/日志不泄露明文。
- [ ] 查询与目标状态按网域隔离（服务端按租户解析授权网域集 + 注入 `network_domain_id` 标签，不注入 `tenant`），越权不可见。
- [ ] 心跳历史按保留策略自动清理；target 快照在删除/退纳管时同步清理。
- [ ] `/api/v1/query*` 代理开销 ≤ 50ms（P95）。
- [ ] 用户界面统一使用业务语言，错误提示给出可执行指引。

## 10. 依赖与风险

### 10.1 模块依赖

| 依赖方 | 依赖内容 | 说明 |
|--------|----------|------|
| Module 06 | 网域行政数据 | 本模块只消费已登记网域，不创建/编辑行政字段 |
| Module 01 | 采集策略与规则 | 本模块监听 M01 数据变化生成配置包 |
| Module 07 | 监控对象与标签模板 | 本模块监听 M07 数据变化生成 targets 与标签 |
| Module 08 | 告警收敛配置 | M08 通过 `AlertmanagerSnapshotSink` 写入生效配置快照，仅留痕不扇出边缘（D31） |
| Module 06 | 租户与授权 | 查询与目标状态接口按当前租户解析被授权网域集（D28/D33） |

### 10.2 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 取消配置确认/回滚后，错误配置可能直接上线 | 监控断点或误告警 | 加强生成期校验；失败不覆盖当前版本；保留历史用于快速定位 |
| 中心节点所在网域也必须部署采集节点 | MVP 最小部署成本增加 | 在中心网域默认安装一个采集节点，可与中心进程同机或同段部署 |
| M08 alertmanager.yml 同步口径 | 告警通知链路中断 | 按 D31：M08 通过 `AlertmanagerSnapshotSink` 端口写入快照留痕，不扇出边缘 |
| 历史 `default` / `local` 通道数据迁移 | 升级后状态不一致 | 提供迁移脚本：将原 default 域转为采集节点域，或退役后重建 |
| 边缘 target 快照与中心 targets 口径不一致 | 目标状态显示错误 | 定义融合优先级与去重键；快照缺失时降级展示 |
