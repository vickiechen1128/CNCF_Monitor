## 1. 引言

### 1.1 目的

本文档用业务语言记录「配置与查询中心」的业务目标、用户场景、功能需求、非功能需求与验收口径。它回答：**这个模块为什么存在、为谁解决什么问题、必须具备哪些能力、做到什么程度算合格**。

本文档**不定义**接口路径与字段、数据表结构、算法、状态机、页面组件、部署参数等技术实现细节；这些内容统一放在配套的《概要设计》与关键设计专题中。需求与设计的对应关系见附录 A。

### 1.2 范围

**本期范围（In Scope）**

- 网域监控纳管：消费 M06 已登记网域，签发与维护接入凭据，提供安装指引与离线包。
- 采集节点状态：节点注册、心跳、在线/离线判定、配置同步状态、组件运行态、远程指令。
- 配置同步与配置产物：监听 M01/M07 源数据，自动生成、校验、发布网域配置与中心规则；提供只读配置产物历史、内容预览与导出。
- 目标状态查询：展示边缘采集节点上报的目标快照（中心侧目标信息作为兼容来源保留），提供目标健康状态与采集覆盖率查询。
- 指标查询：提供与 Prometheus 兼容的查询能力、网域数据隔离，以及面向工程师的指标查询页面（时序图 + 结果明细）。
- 离线包与版本管理：采集节点离线包版本列表、差异提示与下载。

**不在本期范围（Out of Scope）**

- 配置变更的人工确认、回滚、恢复为当前版本。
- 中心节点直接对监控目标发起 scrape/probe。
- 动态选例（按云/条件自动跟随新增资源）；本期 Job 仍为保存时的静态实例列表。
- 自研复杂仪表盘/面板编排；指标查询只提供轻量探索与排障视图。
- 替代 Prometheus/Alertmanager 的查询、存储、告警求值能力。

**定制边界（反定制）**

- 客户/项目差异通过配置、模板、策略或扩展点表达，不进入核心代码分支。
- 本模块不为单个项目新增专用字段/专用页面/专用流程；无法配置化的差异登记为定制债务，注明 owner、原因与复审时间。
- 新增能力优先复用现有平台能力；新建能力需在 HLD 中说明为什么不能复用/扩展。

## 2. 业务背景

### 2.1 从三个工程模块到一个业务域

原有工程模块划分中：Module 09 负责配置生成与下发（配置面），Module 11 负责网域纳管与采集节点生命周期（接入面），Module 02 负责指标查询与目标状态（查询面）。这些是**历史工程索引**，不是本业务域的需求划分维度。

三者围绕同一个对象——**网域**——工作：先让网域接入，再让采集节点拉配置、出数据，最后让用户查目标与指标。合并后形成从「接入」到「观测」的闭环，减少跨模块协调成本，并让「配置」与「查询」共享同一套网域上下文与权限口径。

### 2.2 配置同步去确认化

原「配置变更确认/回滚」在当前业务阶段被判定为不必要。本模块将配置生成降级为**后台自动同步**：

- M01/M07 源数据变化后，自动生成当前网域配置包；
- 通过校验后直接作为当前版本供采集节点拉取；
- 保留最近 30 个自然日、每日最多一份成功版本的只读历史用于排障，但**不支持回滚**；
- 失败尝试不写入历史，失败状态与原因回写源侧并记录日志。

历史快照仍是排障与灾备刚需。本期在不引入回滚的前提下补齐「配置产物历史」：网域采集配置、中心规则、告警配置三类产物统一只读展示，详情内可预览内容，并可导出为**可直接落盘**的文件/配置包；控制面不可用时，运维可凭导出件恢复数据面。

### 2.3 中心网域也需要采集节点

在新的扁平化架构下，**中心节点只负责管理与存储**。即使是中心节点所在的网域，其监控目标的抓取、拨测、配置同步也由部署在该网域内的一台采集节点完成。中心节点本身不直接发起 scrape/probe。

这意味着：不存在「中心直连域」或「管理域」的特殊类型；所有网域都是采集节点域；每个网域都需要完成「纳管 → 安装采集节点 → 心跳上线」的相同流程。

### 2.4 一句话定位

> 配置与查询中心回答的问题是：**「采集节点如何接入中心，以及接入后用户如何查看目标状态、查询指标并追溯配置」**。

## 3. 核心概念

### 3.1 配置与查询中心

- **业务含义**：负责网域监控纳管、采集节点生命周期、配置同步与配置产物、目标状态查询、指标查询的统一模块。
- **对外名称**：一级模块统一称「配置与查询中心」（原名「网域与边缘配置中心」；SRS 历史名「网域接入与查询中心」）。
- **与 M06 的边界**：M06 是网域的**行政 Owner**（名称、云归属、授权租户、启用/禁用）；本模块是网域的**接入与查询 Owner**（纳管状态、凭据、通道、运行态、配置产物、查询代理）。
- **与 M01/M07 的边界**：M01/M07 是源数据 Owner；本模块只读消费其数据生成配置产物，不修改源数据。
- **与 M08 的边界**：M08 是告警配置的内容 Owner 与生成/校验/应用方；本模块只读引用其快照，不做二次写入。

### 3.2 网域（采集节点域）

- 所有网域均为采集节点域，用户侧统一称为「网域」；
- 配置由采集节点主动拉取，中心不主动入站连接节点；
- 不再存在「管理域 / 中心直连域 / 本地下发」等特殊类型；
- 系统不预置默认管理域；与中心同区域的网域也必须在 M06 登记并按采集节点域纳管。

### 3.3 采集节点

- 部署在具体网域内的监控执行单元；
- 职责：心跳上报、拉取配置包、对本域目标执行抓取/拨测、回传指标与目标快照；
- 用户侧统一称为「采集节点」。

### 3.4 配置同步与配置产物

- 后台监听 M01/M07 源数据变化，按网域生成配置产物；源数据保存成功后支持 best-effort 即时触发，并有周期性兜底；
- 网域配置包包含监控主配置、采集目标清单、拨测配置等；**不含规则文件**——告警/记录规则统一在中心 Prometheus 集中求值，由本模块在中心侧生成规则产物并触发生效；
- 配置产物通过采集节点主动拉取的通道供节点获取；
- **统一配置产物历史**：网域采集配置、中心规则、告警配置三类产物在同一只读视图中按类型/网域筛选展示；网域采集配置与中心规则按自然日保留最近 30 天、每天最多一份成功版本（可配置），告警配置沿用 M08 的 20 份版本策略；不支持人工确认与回滚；
- 详情内可按文件预览内容，无需先下载；管理员可导出可直接落盘的配置包/配置文件；
- 生成失败时不覆盖当前生效版本，避免配置断点。

### 3.5 目标状态

- 展示采集目标（job + instance）的健康状态、最近抓取时间、最近错误、采集耗时、实例名等；
- 数据来源为边缘采集节点上报的目标快照；中心侧目标信息作为兼容来源保留（中心不直接采集，通常为空）；
- 只返回用户被授权网域的数据；可按网域、Job、健康状态、关键字筛选。

### 3.6 指标查询

- 提供与 Prometheus 兼容的即时查询、区间查询、标签/序列枚举、告警查询能力；
- 服务端按当前租户解析被授权网域集，并自动按网域过滤，实现数据隔离；
- 查询结果携带数据来源、数据新鲜度、覆盖网域等元信息；
- 提供面向工程师的查询页面：PromQL/指标输入、时间范围、时序图、结果明细、查询元信息、排障深链；
- 指标查询是**探索与排障**能力，不承担复杂仪表盘编排。

### 3.7 信息架构与导航

一级模块「配置与查询中心」下平铺 5 个二级菜单，顺序按「接入 → 观测 → 追溯」组织：

| 顺序 | 二级菜单 | 解决的问题 |
|------|----------|------------|
| 1 | 网域纳管 | 网域如何接入监控 |
| 2 | 采集节点状态 | 采集节点是否在线、配置是否同步、组件是否正常 |
| 3 | 监控目标状态 | 某个 Job/实例是否采到数据 |
| 4 | 指标查询 | 指标趋势如何、故障窗口内发生了什么 |
| 5 | 配置产物历史 | 当时的配置是什么、能否导出恢复 |

> 导航归属理由：指标查询与目标状态、配置产物同属「排障追溯」动线，且查询依赖本模块的网域上下文与权限口径；将其放在本模块可避免跨模块重复建设同一套查询代理与隔离逻辑。

## 4. 目标用户与使用场景

### 4.1 目标用户

| 用户角色 | 关注点 | 典型操作 |
|----------|--------|----------|
| 运维架构师 | 网域规划、采集节点部署 | 登记并纳管网域、下载离线包 |
| 运维工程师 | 采集节点健康、目标状态 | 查看节点状态、重置凭据、查看目标状态 |
| SRE / 值班工程师 | 指标排查与故障定位 | 查询指标、查看时序图、对照目标状态与告警 |
| AI 应用开发者 | 稳定的数据接口 | 通过查询接口取指标 |
| 平台管理员 | 配置产物追溯与恢复 | 预览/导出配置产物、导出恢复包 |

### 4.2 典型使用场景

#### SCN-01：新网域接入监控

- **角色**：运维架构师
- **触发**：新增一片网络域，需要纳入监控
- **目标**：完成从行政登记到采集节点上线的闭环
- **成功标准**：在系统与平台管理中完成网域登记 → 在本模块完成纳管并获取接入凭据 → 下载离线包并部署采集节点 → 节点心跳上线、配置同步成功。

#### SCN-02：排查采集节点离线

- **角色**：运维工程师
- **触发**：某网域采集节点显示离线
- **目标**：快速定位节点状态
- **成功标准**：节点列表展示最后心跳、回传积压、配置版本；可查看组件运行态与 crash-loop 状态；可远程触发重启采集进程或清空回传积压。

#### SCN-03：查看监控目标状态

- **角色**：运维工程师
- **触发**：怀疑某 Job 的目标没有采到数据
- **目标**：查看目标健康状态
- **成功标准**：目标状态展示边缘采集节点上报的快照（兼容中心侧来源）；可按网域、Job、健康状态筛选；离线/异常目标高亮提示。

#### SCN-04：实时指标查询

- **角色**：SRE
- **触发**：排查故障需要查看 CPU / 内存 / 请求量趋势
- **目标**：在安全隔离的前提下查询指标并查看趋势
- **成功标准**：支持 PromQL 即时/区间查询；自动按被授权网域过滤，越权返回空；时序图可读、断点可辨；结果附带数据来源与新鲜度。

#### SCN-05：指标中断与采集失败排障

- **角色**：SRE / 值班工程师
- **触发**：告警提示「node exporter 采集目标抓取失败」，同时观察到该主机 CPU 升至 80%、指标数据中断约 40 分钟后恢复，期间有应用在跑定时任务
- **目标**：判断是采集端、网络、目标进程还是负载导致的中断，并还原中断窗口
- **成功标准**：
  - 能从告警/目标状态一键进入指标查询，并自动带上 Job/实例与时间范围；
  - 时序图能看出「抓取失败窗口」与「指标缺失窗口」的区别（0 值与无数据要可区分）；
  - 能对照目标状态的最近错误、采集耗时、采集样本数，判断失败类型；
  - 能查看中断前后的 CPU 趋势，确认负载与中断的先后关系；
  - 能通过 URL 分享或刷新复现同一视图，便于交接与复盘。

### 5.1 网域纳管

#### FR-01：已登记网域的监控纳管（P0）

- 本模块只消费 M06 已登记且处于启用状态的网域；
- 纳管时填写监控参数（如回传地址、中心地址等），系统自动签发接入凭据；
- 纳管后网域进入「已纳管」状态；
- 一个网域在同一时刻只对应一个生效凭据。

#### FR-02：接入凭据生命周期管理（P0）

- 支持凭据生成、重置、废止；
- 凭据在界面上完全脱敏，完整值仅通过「复制」按钮在弹窗内单次获取；
- 重置后旧凭据立即失效，使用旧凭据的采集节点心跳鉴权失败后自然离线；
- 删除或退纳管网域时废止凭据；
- 凭据不得以明文形式持久化或出现在接口/日志中。

#### FR-03：安装指引与离线包下载（P0）

- 提供统一的采集节点安装指引，不再区分中心直连域/采集节点域；
- 安装指引包含：下载离线包 → 解压部署 → 配置中心地址与接入凭据 → 启动采集节点 → 心跳回连；
- 提供一体化离线安装包下载，并附带完整性校验值。

#### FR-04：纳管状态管理（P0）

- 纳管状态包括：未纳管、已纳管；后续版本支持退纳管；
- 退纳管：废止凭据 → 停止配置下发 → 状态回到未纳管；
- M06 删除网域时，本模块在同一次请求内完成级联清退（废止凭据、停止下发、采集节点标记退役）。

### 5.2 采集节点状态

#### FR-05：采集节点自动注册（P0）

- 采集节点首次携带有效凭据心跳时自动注册；
- 记录信息包括：所属网域、主机名、IP、采集节点版本、组件清单等；
- 同一网域内主机名相同的在线节点不重复注册。

#### FR-06：心跳接收与在线/离线判定（P0）

- 心跳接收节点状态、组件状态、目标快照、回传积压与错误信息；
- 按最后心跳时间与阈值判定在线/离线；
- 心跳历史保留 7 天（可调），并定期清理，避免表无限增长；
- 节点列表与详情展示最后心跳、在线状态、配置同步状态、回传积压。

#### FR-07：配置同步状态展示（P0）

- 节点列表展示每个节点当前拉取的配置版本/校验和；
- 当中心配置更新但节点尚未拉取时，展示「待同步」；
- 同步失败时展示失败原因；
- 能区分「节点未拉取」「拉取后应用失败」「版本一致」等状态。

#### FR-08：组件运行态与 crash-loop 观测（P0）

- 展示采集器、拨测器等组件的运行状态；
- 展示重启次数与 crash-loop 熔断状态；
- crash-loop 节点高亮提示。

#### FR-09：远程指令（P0）

- 支持通过心跳响应向节点透传「重启采集进程」「清空回传积压」两条指令；
- 中心不主动入站连接节点，指令由节点拉取执行；
- 指令具备幂等机制，重复下发不会导致重复执行。

### 5.3 配置同步与配置产物历史

#### FR-10：自动配置生成（P0）

- 监听 M01（采集策略/规则）与 M07（资源/标签模板）数据变化；
- 源数据保存成功后 best-effort 触发一次配置重算，并有周期性兜底；
- M07 变更应先触发 M01 对账回收失效选例，再触发本模块生成；
- 按网域生成配置产物；规则不下发到边缘，统一由中心 Prometheus 集中求值，本模块在中心侧生成规则产物并触发生效；
- 生成失败时保留当前生效版本，避免监控断点；
- **选例边界**：现有 Job 保存的是保存时的静态实例列表；新增资源不会自动加入已有 Job。按云/条件动态全量选择不在本期范围。

#### FR-11：配置包供采集节点拉取（P0）

- 配置产物打包后，由采集节点在心跳/拉取时获取；
- 心跳响应中告知配置是否变化、配置包下载位置与校验和；
- 配置包含凭据等敏感信息，仅在校验节点凭据后返回。

#### FR-12：下发前校验（P0）

- 对生成的配置产物做语法与结构校验（主配置、拨测模块、采集目标清单等）；
- 校验失败时不生成/不更新当前配置，失败状态与原因回写源侧并记录日志，不对外发布；
- 区分「用户配置问题」与「平台故障」归因，便于用户与运维各自处理。

#### FR-13：只读配置产物历史（P0）

- 覆盖三类配置产物：网域采集配置、中心规则、告警配置；
- **网域采集配置 / 中心规则按自然日保留**：默认保留最近 30 天，每天最多一份成功版本；同一天多次成功变更只保留当日最后一份，当前生效版本始终保留；超出天数自动清理；
- 告警配置仍由 M08 管理，沿用其 20 份版本保留策略；
- 保留天数与日切时区可配置；
- 历史内容必须持久化，不能只存元数据，否则无法预览与导出；历史内容与版本记录一一对应；
- 历史版本只读展示，**不支持回滚、恢复为当前版本、人工确认**；
- **失败尝试不写入历史**；失败状态与原因仅用于排障，不对外发布；
- 审计诉求由操作留痕与配置生效日志承载，不依赖配置快照条数。

#### FR-13.1：统一历史视图与内容预览（P0）

- 三类产物在同一「配置产物历史」页展示，支持按产物类型、网域、配置日期、校验状态、版本/校验和筛选；
- 列表展示产物类型、网域（或「中心」）、配置日期、生成时间、版本、校验状态与归因、生成来源、是否当前版本；
- 详情展示元数据、校验明细与内容预览；内容按文件分栏，无需先下载；
- 预览不改变当前版本、不触发生效、不写回源数据；
- 内容预览与下载仅管理员可见；非管理员不展示入口；产物含凭据明文，接口/日志不得输出内容明文。

#### FR-13.2：配置产物导出（P0）

- **网域采集配置**：导出可直接落盘的配置包（主配置、采集目标清单、拨测配置、规则（如有）、元数据）；
- **中心规则**：导出规则文件；
- **告警配置**：导出告警配置文件；
- **中心一体化恢复包**：导出中心侧当前生效的主配置、规则、告警配置与采集目标清单，并附版本/校验清单；用于控制面不可用时凭开源数据面直接恢复；中心侧无采集目标时清单可为空；告警配置不可用时省略并标注；
- 导出件与版本记录一致，校验值可复核；
- 导出动作不改变当前版本、不触发生效。

#### FR-14：M08 告警配置纳入统一历史（P0）

- M08 仍是告警配置的内容 Owner 与生成、校验、应用方；
- 本模块以只读方式引用 M08 的告警配置快照，不复制到网域范围、不二次落库、不改写、不触发生效；
- 告警配置在统一历史中作为独立类型展示，支持内容预览与导出；
- 告警配置不扇出到任何网域配置包、不参与回滚；中心一体化恢复包按只读引用纳入；
- M08 不可用或未配置时，统一历史隐藏告警配置类型并给出提示，不影响其他类型。

### 5.4 目标状态查询

#### FR-15：目标状态融合查询（P0）

- 目标状态以边缘采集节点上报的目标快照为主；中心侧目标信息作为兼容来源保留（中心不直接采集，通常为空）；
- 返回字段满足排障需要：Job、实例、所属网域、健康状态、最近抓取时间、最近错误、采集耗时、可读实例名等；
- 只返回用户被授权网域的数据。

#### FR-16：采集覆盖率查询（P0）

- 返回采集状态四态：采集中 / 部分采集中 / 已下发未采到 / 未监控；
- 供 M07 资源列表等消费方展示采集覆盖情况。

#### FR-17：目标状态筛选与分页（P0）

- 支持按网域、Job、健康状态（在线/离线/未知）、关键字筛选；
- 支持分页，避免大数据量拖慢页面；
- 关键字可匹配实例名与实例 IP。

### 5.5 指标查询

#### FR-18：Prometheus 兼容查询能力（P0）

- 提供与 Prometheus 兼容的查询能力，至少覆盖：即时查询、区间查询、标签枚举、标签值枚举、序列查询、告警查询；
- 查询语义与 Prometheus 原生接口保持一致，便于工程师复用已有 PromQL 经验；
- 查询为只读操作，不修改任何数据。

#### FR-19：查询结果元信息（P0）

- 查询结果需携带数据来源、数据新鲜度、本次查询覆盖的网域等元信息；
- 元信息用于前端提示「数据来自哪里、是否新鲜、能看到哪些网域」，不作为指标数据本身。

#### FR-20：网域上下文与数据隔离（P0）

- 查询转发前，服务端按当前租户解析被授权网域集，并自动追加网域约束；
- 不依赖用户手工在 PromQL 中书写网域过滤；
- 任何用户（含平台管理员）不具备绕过隔离的能力；
- 无权限网域或未带网域标识的数据不可见，返回空结果而非报错；
- 目标状态查询遵循同一隔离口径。

#### FR-22：指标查询页面（P0）

> v1.9 新增。作为「配置与查询中心」二级菜单「指标查询」的落地页面，补齐此前只有查询代理、没有查询界面的缺口。

- **入口**：一级导航「配置与查询中心」→ 二级菜单「指标查询」；同时支持从监控目标状态、告警、指标库带参进入；
- **查询输入**：支持直接输入 PromQL；提供指标名/标签辅助选择（至少支持指标名检索与 Job/实例筛选）；
- **时间范围**：提供常用快捷范围（如 15 分钟、1 小时、6 小时、24 小时、7 天、30 天）与自定义起止时间；
- **执行与取消**：支持执行、取消、重新执行；执行中展示加载态，避免旧结果覆盖新结果；
- **时序图**：
  - 以折线图展示一条或多条时间序列；
  - **无数据区间必须显示为断点/空档，不得跨缺口连线**；
  - **0 值与无数据必须可区分**；
  - 支持图例、悬浮提示、缩放；图例可控制序列显隐；
- **结果明细**：展示序列标签、最新值、最小/最大/平均值等摘要，便于快速判断量级；
- **查询元信息**：展示时间范围、步长、序列数、耗时、覆盖网域、数据新鲜度；
- **排障深链**：从目标状态行的「查看指标」进入时，自动带 Job/实例与时间范围；从指标库进入时预填指标名；从告警进入时带告警相关标签与时间窗（具体可用性以数据面标签为准）；
- **预设模板**：提供「采集健康」「CPU 使用率」等诊断模板，降低非 PromQL 用户的起步成本；
- **可分享/可复现**：查询表达式、时间范围、步长等状态体现在 URL 中，刷新与分享后可复现同一视图；
- **状态完整**：加载中、空结果、查询错误、上游不可达均有明确提示；空结果提示当前可见网域，错误提示给出下一步操作建议；
- **查询历史（P1）**：本地保留最近若干次查询，便于回看与重跑。

### 5.6 离线包与版本管理

#### FR-21：离线包版本管理（P1）

- 维护中心发布的采集节点版本列表；
- 节点状态页展示节点当前版本与中心最新版本差异；
- 提供升级指引与离线包下载。

### 5.7 功能优先级汇总

| 优先级 | 功能 |
|--------|------|
| P0 | FR-01 ~ FR-20、FR-22 |
| P1 | FR-21、FR-22 中的查询历史 |
| P2 | 多查询对比、告警窗口叠加、保存/分享查询、导出图表等增强 |

## 6. 非功能需求

### 6.1 架构约束

#### NFR-01：中心节点不直接采集（P0）

- 中心节点不直接发起 scrape/probe；所有面向监控目标的采集行为由网域内采集节点执行。

#### NFR-02：所有网域均为采集节点域（P0）

- 不存在中心直连域/管理域；中心节点所在网域也需部署采集节点；
- 配置由采集节点主动拉取，中心不主动入站连接节点。

#### NFR-03：Outbound-only 安全边界（P0）

- 中心不主动入站连接采集节点；
- 所有指令通过心跳响应由节点拉取执行。

### 6.2 数据一致性与可靠性

#### NFR-04：配置同步原子性（P0）

- 配置生成、校验、标记为当前版本应为原子或幂等操作；
- 生成失败不得覆盖当前生效版本。

#### NFR-05：配置历史只读（P0）

- 历史版本仅用于排障与审计，禁止通过接口恢复为当前版本。

#### NFR-06：心跳与快照清理（P0）

- 心跳历史保留策略可配置（默认 7 天），并自动清理；
- 目标快照在资源删除/Job 清空/退纳管/网域删除时同步清理，避免残留。

### 6.3 安全性

#### NFR-07：接入凭据安全（P0）

- 凭据使用高强度随机字符串；
- 仅存不可逆哈希，明文仅在纳管成功/重置时完整展示一次，任何接口/日志不返回明文；
- 凭据重置/废止立即生效。

#### NFR-08：数据隔离（P0）

- 查询与目标状态按网域隔离：服务端按当前租户解析被授权网域集，自动追加网域约束，越权不可见；
- 隔离不可被用户参数绕过，平台管理员也不例外。

#### NFR-09：配置产物内容保护（P0）

- 配置产物含凭据等敏感信息，内容预览/下载仅管理员可见；
- 接口与日志不得输出内容明文。

### 6.4 性能与可用性

#### NFR-10：查询性能（P0）

- 指标查询代理的附加开销（鉴权、网域解析、注入）应显著小于 Prometheus 查询本身，目标为 P95 ≤ 50ms；
- 目标状态查询禁止逐行查询时序数据，应依赖预聚合或快照。

#### NFR-11：查询规模与护栏（P0）

- 单次查询的时间范围、返回点数、执行超时必须有上限；
- 超出上限时返回可执行的提示（建议缩小时间范围/增大步长），不得导致 Prometheus 或控制面不可用；
- 查询页面在常用范围（如 6 小时、1 天）下应保持可交互，不因大结果集卡死。

#### NFR-12：指标查询页性能（P0）

- 在 1000 个时间点 × 20 条序列的典型负载下，首屏图表渲染应在 1 秒级完成（普通办公终端）；
- 页面按路由懒加载，不显著增加平台首屏体积；
- 重复查询/缩放不应造成明显卡顿。

#### NFR-13：用户语言一致性与错误可执行（P0）

- 用户界面统一使用「网域 / 采集节点 / 目标状态 / 指标查询」等业务语言；
- 技术术语仅出现在折叠区、代码注释或接口文档；
- 配置校验失败、节点离线、查询越权/超限等错误须给出下一步操作指引。

## 7. 数据需求（概念级）

> 本节只描述业务对象与生命周期规则；字段、表结构、索引、迁移见概要设计 §5 与 migration。

### 7.1 核心业务对象

| 业务对象 | 说明 | 数据 Owner |
|----------|------|------------|
| 网域接入状态 | 网域的纳管状态、凭据、回传参数、最近心跳、当前配置版本 | 本模块（行政字段归 M06） |
| 采集节点 | 节点身份、状态、版本、组件、配置同步状态、远程指令序号 | 本模块 |
| 心跳记录 | 节点每次心跳的状态、积压、组件、目标快照 | 本模块 |
| 目标快照 | 每个（网域、Job、实例）的最新健康状态与错误 | 本模块 |
| 配置产物 | 三类配置产物的版本、校验和、校验结果、内容 | 本模块（告警配置归 M08） |
| 告警配置引用 | M08 告警配置快照的只读引用 | M08 |

### 7.2 保留与生命周期

- 心跳历史：默认保留 7 天，可配置，自动清理；
- 网域采集配置 / 中心规则：自然日维度保留最近 30 天，每天最多一份成功版本；当前生效版本始终保留；保留天数与时区可配置；
- 告警配置：沿用 M08 的 20 份版本策略；
- 失败尝试不进入配置产物历史；
- 目标快照随资源/Job/网域生命周期同步清理。

### 7.3 数据归属与一致性

- 网域行政数据以 M06 为准；本模块不创建/编辑行政字段；
- 采集策略与规则以 M01 为准；资源与标签模板以 M07 为准；
- 告警配置以 M08 为准；本模块只读引用；
- 配置产物由本模块生成并持久化；失败不得覆盖当前版本。

## 8. 约束、假设与依赖

### 8.1 架构约束

- 中心节点不直接采集，所有采集由网域内采集节点执行；
- 所有网域均为采集节点域，配置由节点主动拉取；
- 中心不主动入站连接节点；
- 指标查询依赖中心 Prometheus，目标状态依赖中心侧目标信息与边缘快照。

### 8.2 假设

- 中心 Prometheus/Alertmanager 可用，并允许本模块触发生效；
- 采集节点版本支持当前 edge 协议；
- M06 已登记且启用的网域才可纳管；
- 生产环境具备可持久化的数据与日志目录。

### 8.3 模块依赖

| 依赖方 | 依赖内容 | 说明 |
|--------|----------|------|
| Module 06 | 网域行政数据、租户与授权 | 本模块只消费已登记网域，不创建/编辑行政字段；查询按租户解析授权网域集 |
| Module 01 | 采集策略与规则 | 本模块监听 M01 数据变化生成配置产物 |
| Module 07 | 监控对象与标签模板 | 本模块监听 M07 数据变化生成采集目标清单与标签 |
| Module 08 | 告警配置 | M08 生产并持久化告警配置快照；本模块统一历史只读引用，不复制、不二次落库 |
| Prometheus / Alertmanager | 查询、存储、告警求值、配置加载 | 本模块不替代其能力 |

### 8.4 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 取消配置确认/回滚后，错误配置可能直接上线 | 监控断点或误告警 | 加强生成期校验；失败不覆盖当前版本；保留历史用于快速定位 |
| 中心节点所在网域也必须部署采集节点 | MVP 最小部署成本增加 | 在中心网域默认安装一个采集节点，可与中心进程同机或同段部署 |
| M08 告警配置同步口径不一致 | 告警通知链路中断 | M08 生产并持久化快照，本模块只读引用；M08 不可用时统一历史降级隐藏该类型 |
| 历史内容缺失导致无法导出 | 控制面故障时无法恢复数据面 | 历史内容随版本持久化；保留策略可配置；导出件校验值可复核 |
| 导出件路径/依赖不完整 | 解压后无法直接启动 | 导出包内文件路径与开源组件约定一致；以开源校验工具为准 |
| 边缘目标快照与中心侧目标信息口径不一致 | 目标状态显示错误 | 定义融合优先级与去重键；快照缺失时降级展示 |
| 指标查询范围过大 | Prometheus/控制面过载 | 时间范围、点数、超时护栏；超限给出可执行提示 |

## 9. 验收标准

> 本节是「验收意图」的唯一权威；§4 的「成功标准」与 §5 的 FR 是需求描述，最终验收以本节为准。每个 SCN 的演示脚本见 `docs/05-execution-records/module-09/scenario-walkthrough.md`，走查反馈与验收结论记录在 [Scenario Link](../../../07-design/Module_09_Scenario_Link.md)，不在本文重复。

### 9.1 功能验收

- [ ] 系统不再预置默认管理域；所有网域均需在 M06 登记并按采集节点域纳管。
- [ ] 网域纳管支持选择 M06 已登记网域、自动签发接入凭据、提供安装指引与离线包下载。
- [ ] 接入凭据在界面中脱敏展示，完整值仅单次复制获取；重置后旧凭据立即失效。
- [ ] 采集节点首次有效心跳自动注册，后续心跳更新状态、回传目标快照与组件状态。
- [ ] 节点列表展示在线/离线状态、最后心跳、配置同步状态、回传积压、组件运行态、crash-loop 状态。
- [ ] 支持通过心跳响应透传「重启采集进程」与「清空回传积压」指令，重复下发不重复执行。
- [ ] 配置同步监听 M01/M07 变化，自动生成配置包并通过采集节点主动拉取通道下发。
- [ ] 配置产物通过语法/结构校验；失败不覆盖当前版本。
- [ ] 「配置产物历史」统一展示网域采集配置、中心规则、告警配置三类产物，支持按类型/网域/校验状态/版本筛选。
- [ ] 详情可直接预览配置内容（按文件分栏），无需先下载；预览与下载仅管理员可见。
- [ ] 网域采集配置与中心规则保留当前版本 + 最近 30 天每日一份成功版本（可配置），告警配置沿用 20 份策略；失败尝试不写历史；不支持回滚、恢复为当前版本或人工确认。
- [ ] 网域采集配置可导出为可直接落盘的配置包；中心规则可导出规则文件；告警配置可导出告警配置文件。
- [ ] 中心一体化恢复包可导出（主配置 + 规则 + 告警配置 + 采集目标清单），含版本/校验清单，控制面停机后可凭此恢复。
- [ ] 目标状态展示边缘采集节点上报的目标快照（兼容中心侧目标来源），按授权网域过滤；支持网域/Job/健康状态/关键字筛选与分页。
- [ ] 采集覆盖率返回「采集中 / 部分采集中 / 已下发未采到 / 未监控」四态，供 M07 消费。
- [ ] 指标查询提供 Prometheus 兼容的即时/区间/标签/序列/告警查询能力，返回统一元信息。
- [ ] 查询自动按授权网域隔离，平台管理员也不能绕过；越权返回空。
- [ ] 一级导航为「配置与查询中心」，二级菜单包含「指标查询」；点击可直达查询页面。
- [ ] 指标查询页面支持 PromQL 输入、时间范围选择、执行/取消、时序图、结果明细与查询元信息。
- [ ] 时序图对无数据区间显示断点、不跨缺口连线；0 值与无数据可区分。
- [ ] 从监控目标状态、指标库、告警可带参进入指标查询，并自动预填表达式/时间范围。
- [ ] 查询状态可通过 URL 分享与刷新复现；空结果提示可见网域，错误提示可执行建议。
- [ ] M08 生效的告警配置快照以只读方式纳入统一历史，不重复落库、不进入任何网域配置包。

### 9.2 非功能验收

- [ ] 中心节点不直接发起 scrape/probe；所有采集行为由网域内采集节点执行。
- [ ] 不存在管理域/中心直连域概念；配置统一由采集节点主动拉取。
- [ ] 中心不主动入站连接节点；指令通过心跳响应由节点拉取。
- [ ] 接入凭据安全存储，接口/日志不泄露明文。
- [ ] 查询与目标状态按网域隔离，越权不可见。
- [ ] 配置内容预览/下载仅管理员；接口与日志不输出内容明文。
- [ ] 心跳历史按保留策略自动清理；目标快照在删除/退纳管时同步清理。
- [ ] 历史内容随版本持久化；预览/导出不改变当前版本、不触发生效、不写回源数据。
- [ ] 导出件与版本记录校验值可复核；网域配置包与中心恢复包解压后可直接被开源 Prometheus/Alertmanager 加载。
- [ ] 指标查询代理附加开销 P95 ≤ 50ms。
- [ ] 查询时间范围/点数/超时有上限，超限返回可执行提示；不导致数据面或控制面不可用。
- [ ] 指标查询页在 1000 点 × 20 序列下首屏渲染 1 秒级完成，路由懒加载。
- [ ] 用户界面统一使用业务语言，错误提示给出可执行指引。
