## 1. 文档目的

回答一个问题：**当用户的心智是"我要监控这批主机"，而这批主机横跨多个网域时，M01 应该怎样承载，才能既不把平台约束（每域一份配置包）泄漏给用户，也不用破坏现有单域同步链路？**

本增量定义：

- 新的**对象优先**创建动线（先筛对象、后按域归组）；
- 承载它的数据实体「**Job 组**（`job_group`）」与子 Job 的关系；
- 组级同步状态的聚合口径；
- 与既有单域 Job、M09 契约、M07 资源的边界与迁移方案。

## 2. 业务背景

### 2.1 问题：现有动线是"网域优先"，与用户心智相反

现状（基线 v1.2 FR-05 / FR-09）：创建 ScrapeJob 必须先选**所属网域**（单选），再在该网域内挑选实例。这带来三个后果：

1. **用户要先想网域，再想对象**。用户对"主机/Middleware/接口服务"有明确认知，对"这片主机属于哪个网域"往往没概念——网域是平台为实现"每域一个采集节点"引入的**结果属性**，不是用户的输入条件。
2. **同一套采集配置被复制 N 份**。一朵云环境下同样配置要覆盖多个网域时，用户只能手工建 N 个 Job，后续改间隔/模板要改 N 次。
3. **跨域视图缺失**。列表按域组织，用户看不到"我这次要采的 300 台主机"整体状态。

### 2.2 技术现实：下发层必须保持单域

M09 的物理约束不变：

- 每个网域一个采集节点，拉取**本域**一份配置包（`prometheus.yml` + targets）；
- M09 按 `network_domain_id` 取 Job 生成配置（现状实现）；
- 同步结果按「域 + Job 名」回写 M01 的 `sync_*` 列。

因此**不能**把 Job 直接做成"多域实体"：那会同时改动 M01 状态契约、M09 生成逻辑、删除/改域语义，并把一个域失败的影响扩散到整条 Job 记录。

### 2.3 结论：多域只存在于"意图层"

引入 **Job 组** 作为"一张监控意图"：组持有公共参数与成员关系，**每个域仍是一条独立的子 Job**。用户看到的是"一个组、多域覆盖、逐域状态"；平台看到的是"N 条单域 Job"，M09 链路零改动。

## 3. 核心概念

| 概念 | 定义 |
|---|---|
| **采集任务 / Job（用户唯一概念）** | 用户在界面上看到的、创建与维护的唯一对象：一类监控对象 + 一种任务类型（采集 / 拨测）+ 一套采集参数 + 一组实例。**跨域是任务的属性，不是另一种任务**。 |
| **域级子任务（内部实现）** | 任务在某个网域内的落地行（`m01_scrape_jobs.job_group_id` 关联），保持单域语义与参数快照，是 M09 的实际下发单元。**前端不出现「子任务 / 任务组」等词**。 |
| **`job_group_id`（内部字段）** | 仅用于把一次任务落成多份域级配置；**不是用户概念**，不进入表单、列表、详情文案。 |
| **对象优先动线** | 先按对象属性筛选/多选实例（可跨域），保存时按实例所属网域自动归组，再落成子 Job。 |
| **分域预览** | 保存前展示"本次将生成哪些域的子 Job、每域多少实例、哪些域为 0 不生成"。 |
| **组级同步状态** | 由子 Job 的 `sync_status` **派生**的聚合视图（不落库、不双写）：全同步 / 部分失败 / 全失败 / 待同步。 |
| **单域 Job（兼容）** | 不归属任何组的传统 Job，行为与基线完全一致；`job_group_id` 为空。 |

### 3.1 术语约定（用户可见）

- 用户界面统一称「**监控任务**」或「Job」，组在界面上呈现为任务行 + 「覆盖 N 个网域」；不出现 `job_group_id`、`selected_instance_ids` 等字段名。
- 网域在任务表单中**不是第一个必填项**，而是实例选择的结果（可在筛选条件里收窄）。

## 4. 目标用户与使用场景

### 4.1 目标用户

| 角色 | 关注点 | 本次增量带来的变化 |
|---|---|---|
| 运维工程师 | 按对象批量配置采集 | 一次勾选即可覆盖多域，不必逐域建 Job |
| 运维架构师 | 网域规划、采集覆盖完整性 | 能看到某个对象集合在各域的覆盖与同步情况 |
| 值班/SRE | 失败定位 | 组级状态一眼看出哪个域失败，下钻到该域明细 |

### 4.2 典型场景

#### 场景 1：一朵云的主机批量采集（核心场景）

- 云 A 下有三片网域（生产 / 测试 / DMZ），同构主机共 300 台。
- 用户选「主机」→ 过滤云=A → 多选 300 台 → 保存。
- 系统按域自动归组：生产 200 / 测试 80 / DMZ 20，生成 1 个组 + 3 条子 Job，参数一致。

#### 场景 2：只有一个域失败

- 组内 DMZ 子 Job 因 targets 校验失败 → 组状态「部分失败（1/3）」，其余两域照常同步。
- 用户点击失败域 → 直达该域子 Job 的失败原因与修复入口，无需在三个 Job 间切换排查。

#### 场景 3：统一调参

- 采集间隔需从 15s 调整到 30s。
- 用户在组上改一次，系统扇出到组内全部子 Job；内容未变的域不产生新快照（M09 checksum 去重）。

#### 场景 4：单域用户不受影响

- 只监控一个域的用户仍可直接建单域 Job；组是可选能力，不是强制包装。

## 5. 功能需求

### 5.1 对象优先创建动线

#### FR-JG-01：单一创建入口 + 跨域对象筛选

- **只有一个「新建采集任务」入口**（不再区分"新建任务组 / 新建单域任务"）：
  第一步选任务类型（**采集 / 拨测**，即 `job_type`，语义与基线一致），再选监控对象类型；
- 实例候选由**可自由组合的筛选条件**驱动（详见 FR-JG-11），不再固定为「先选网域」的下拉；
- 候选集**默认跨已授权网域**，不要求先选网域；
- `offline` 实例仍显示但置灰不可选（沿用基线 FR-09）；
- 表格必须展示「所属网域」列，支持按网域排序，让用户在勾选时就能看到跨域事实。

#### FR-JG-02：保存前「覆盖网域」预览与自动归组

- 勾选完成后展示「覆盖网域」预览：`域A 12 台 / 域B 7 台 / 域C 0 台（不生成）`；
  列表与详情统一用「覆盖网域」表达，不使用"组"的概念；
- 归组规则以**实例所属资源的 `network_domain_id`** 为准，不由用户手填；
- 若某域实例数为 0，该域**不生成子 Job**（不产生空 Job）；
- 若勾选实例全部属于同一个域，行为等价于建一条单域 Job（组仍可创建，也允许用户选择"不建组，直接建单域 Job"）。

#### FR-JG-03：任务与域级子任务的事务化创建（内部派生）

- 一次保存在一个事务内创建 1 个组 + N 条子 Job；任一条失败整体回滚，不出现"建了一半"；
- 子 Job 继承组的公共参数快照（与基线一致：参数快照落在 Job 上，保证历史可追溯）；
- 同一组内所有子 Job 使用**同一 `job_name`**（便于跨域用同一 `job` 标签查询）；
- `job_name` 唯一性口径调整为「**同一网域内唯一**」（见 §6.1 的数据约束变更），跨域同名合法；
- 组名（用户可见名）全局唯一，重名返回 409 并提示。

#### FR-JG-04：任务编辑（含单域→多域晋升）

- **改公共参数**（间隔 / 超时 / metrics_path / scheme / 标签模板 / blackbox 模块 / 认证）：一次提交，扇出到组内全部子 Job；
- **改实例**：
  - 新增实例 → 按其所属域归入对应子 Job；该域原本无子 Job 时新建一条；
  - 取消实例 → 从对应子 Job 移除；某域实例清零时删除该域子 Job；
- 编辑必须给出**变更影响预览**（涉及 N 个域、M 条子 Job），保存后提示「配置将由 M09 自动同步」；
- 不允许把域级子任务"移动到另一个域"——跨域变更一律表达为"某域移除 + 另一域新增"，避免隐式重建。
- **晋升（新增）**：编辑一个**尚未跨域**的任务时，若新勾选的实例跨多个网域，后端在**同一事务**内
  为该任务建立内部承载（`job_group_id` 关联）：原任务行沿用原 `id` 作为其所属域的子任务，
  其余网域各生成一条子任务；用户侧仍是"同一个任务"，无任何额外操作或概念。
- 反向：编辑后实例回落到单一网域时，任务仍可保留内部承载（1 条子任务），用户无感知。

#### FR-JG-05：任务级同步状态聚合（逐域明细）

- 组列表行展示派生状态：
  - **已同步**：全部子 Job `synced`；
  - **部分失败**：存在失败且存在成功（如 2/3）；
  - **同步失败**：全部失败；
  - **待同步**：存在 `pending`/`syncing` 且无失败；
  - **草稿**：组内全部子 Job 均为草稿。
- 行内提供「覆盖 N 个网域」与失败域计数；展开/详情显示逐域状态（网域、子 Job 名、状态、失败原因、最近同步时间）；
- 组级状态**不落库**，完全由子 Job 派生，避免双写不一致。

#### FR-JG-06：任务删除与停用语义

- 删除任务 → 级联删除其域级子任务（软删）；M09 下次同步自动回收对应 targets（现有机制），无需额外接口；
- 停用任务 → 其全部域级子任务停用，任务状态显示已停用；
- 支持「组内单域退出」：从组中移除某域全部实例 → 删除该域子 Job，组继续存在（成员数减一）；
- 组内只剩 1 个子 Job 时，允许用户选择「解散组，保留为单域 Job」（`job_group_id` 置空）。

#### FR-JG-07：网域状态变化

- 网域被 M06 禁用或退纳管 → 该域子 Job 自动置为停用并在组详情标注「网域不可用」，**不自动删除**（保留证据，便于恢复）；
- 网域恢复可用 → 提供「重新启用该域子 Job」动作，不自动拉起（避免意外恢复采集）。

#### FR-JG-08：存量单域 Job 一等公民（「未分组」概念取消）

- **取消「未分组 / 组内」二分**：存量单域 Job 与新任务在列表、详情、编辑中**表现形式完全一致**，
  只是「覆盖网域」为该单域；
- 存量单域 Job 的全部能力（CRUD、草稿、参数继承、同步状态、采集状态回显）保持不变；
- 存量单域 Job 被编辑为跨域时，按 FR-JG-04 晋升；用户无需先"加入组"。

### 5.2 列表与导航

#### FR-JG-09：统一任务列表（单视图）

- **只有一个列表**：一行 = 一个采集任务；**没有「按组 / 按 Job」切换，也没有「所属任务组」「未分组」列**；
- 列：任务名 / 类型（采集·拨测）/ **覆盖网域** / 监控类型 / 已选实例 / 实例采集状态（聚合）/ 间隔 /
  启用状态 / 同步状态（聚合）/ 参数同步 / 操作；
- 展开行 = 逐域子任务明细（所属域、实例数、采集状态、同步状态、失败原因）；
- 筛选：关键字（任务名/域名）、任务类型、监控类型、同步状态；**不提供"组"维度筛选**。

#### FR-JG-10：组详情页/抽屉

- 展示组公共参数（只读摘要）+ 逐域子 Job 表格（域名、实例数、同步状态、失败原因、最近同步时间）+ 组级操作（编辑、停用、删除、解散）；
- 任一子 Job 可下钻到现有 Job 详情抽屉，保持现有排障动线。

### 5.3 跨域组合筛选与批量选择

> 背景：用户的心智是「我要按某维度批量圈一批对象」，维度可能是网域、运行状态、应用、业务、环境等，且在
> 一次操作里组合出现（例：`应用=订单服务` **且** `网域∈{生产,DMZ}` **且** `状态=运行中`）。
> 固定 3~4 个下拉无法覆盖，故引入 **schema 驱动的条件构建器**。

#### FR-JG-11：可组合筛选条件（schema 驱动）

- 服务端下发**可筛选字段清单**（key / 展示名 / 类型 / 操作符 / 取值来源 / 默认值），前端按清单渲染条件行；
  新增可筛字段**不得要求前端改代码**；
- 条件模型：`{field, op, values[]}`，多条条件按 **AND** 组合；
  同一字段出现多次按 AND 合并（`in` 取交集），**不做静默覆盖**；
- 操作符：P0 支持 `in`（多值枚举）、`eq`（文本精确）、`contains`（文本包含）；P1 增加 `not_in`；
- P0 可筛选字段（按监控类型裁剪，字段名对用户不可见）：

  | 字段（内部 key） | 展示名 | 类型 | 取值来源 |
  |---|---|---|---|
  | `network_domain_id` | 网域 | multi_enum | 已授权且已纳管网域 |
  | `status` | 运行状态 | multi_enum | 运行中 / 已停止 / 维护中（默认「运行中 + 已停止」） |
  | `app_code` | 应用 | multi_enum | 应用字典 |
  | `biz_code` | 业务 | multi_enum | 业务字典 |
  | `platform_code` | 平台 | multi_enum | 平台字典 |
  | `env` | 环境 | multi_enum | OPS / PRD / UAT |
  | `cluster` | 集群 | text | 资源字段（`eq` / `contains`） |
  | `owner` | 负责人 | text | 资源字段（`contains`） |

- **云 / 可用区不单独建字段**：资源表没有云字段，云归属挂在网域上（M06 `cloud_code`），
  P0 的做法是在**网域选项标签**里附带归属信息（如 `域A（阿里云）`），用户选域即等于选云；
  P1 再评估是否引入 `cloud_code` 的 join 过滤或「选云 → 自动填入该云下的网域」的快捷组合器。

- `monitor_type` 是**范围选择器**而非筛选条件：候选集分类与子类型仍由它决定（**自 M01 SRS v1.3 起，该「决定」由可配置的推导规则完成，不再是代码里写死的类别/子类型映射**；规则维护见 M01 SRS §5.6）。同一资源可同时落在多个 `monitor_type` 的候选范围内，这正是「一个 CI 多个采集器」的来源，不做互斥；
- **网域条件的定位（红线）**：`network_domain_id` 只用于**收窄本次可选实例**，
  不得被理解为「本次任务绑定/下发到这些域」。子 Job 的网域分布由**所选资源自身的
  `network_domain_id`** 在保存时派生（与筛选条件无关）；界面必须在网域条件处标注这一点，
  并以保存前的分域预览作为唯一可信的「将下发到哪些域」来源。
- 默认条件只有 `status ∈ {online, offline}`（与既有候选接口「排除维护中」一致）；
  **网域不默认出现、不置顶、不可设为必填**（避免把用户心智拉回「网域优先」）；
  网域作为「+ 添加条件」中的可选项参与组合；
- 条件变化即重查，不要求点「查询」；前端对条件序列做稳定排序 + 短防抖，避免重复请求；
- 0 命中时给出可执行提示（放宽条件 / 检查是否被授权网域范围限制）。

#### FR-JG-12：分域汇总与「全选筛选结果」

- 候选查询响应携带**分域计数**（网域 + 命中数），直接用于保存前的分域预览，避免前端二次聚合；
- 支持「全选当前筛选结果」：服务端按同一条件返回匹配实例 ID（上限 **2000**），
  超限返回 `truncated=true` 并提示收窄条件，**不允许静默截断**；
- 不允许前端逐页拉取拼装 ID；手动跨页勾选必须保留（翻页不丢选择）。
- **筛选变化与已选集合**：筛选条件变化时**不清空**已选，但必须显式标注
  「已选 N 台，其中 M 台不在当前筛选结果内」，并提供「清理不在筛选内的已选」动作；
  保存以「实际已选」为准，禁止因筛选变化静默丢弃用户已勾选的实例。

#### FR-JG-13：授权域收敛（安全红线）

- 候选查询（含老 GET 接口）必须以**当前用户授权网域集合**为上限（fail-closed），与前端条件取交集；
- 请求中出现未授权网域 → `400`，提示「无该网域访问权限」；
- 该约束不得依赖前端不传某字段来"自然规避"。

#### FR-JG-14：条件契约与错误

- 复杂条件使用 `POST` 查询（条件体不适合塞 URL）；既有 `GET` 接口保留兼容，逐步收敛；
- 服务端维护**字段 → 列白名单**，禁止把前端传入的列名拼进 SQL；
- 未知字段 / 非法操作符 / 非法枚举值 / 超长取值 → `400`，错误信息点名具体字段与合法取值；
- 条件只影响"选哪些实例"，不改变组的建模：保存时仍是显式 `selected_instance_ids`。

## 6. 非功能需求

### 6.1 数据一致性

- **NFR-JG-01**：组创建/编辑/删除必须事务化；部分成功视为失败并回滚。
- **NFR-JG-02**：唯一性口径调整——删除全局唯一索引 `uq_m01_scrape_jobs_name`，改为 `(network_domain_id, job_name)` 唯一（`deleted_at IS NULL` 条件保留）；组名单独全局唯一。存量数据（原本全局唯一）天然满足新约束，无需数据修复。
- **NFR-JG-03**：组级状态为派生值，任何时刻以子 Job 的 `sync_*` 列为唯一事实来源。

### 6.2 性能

- **NFR-JG-04**：单次创建/编辑涉及 ≤ 200 个子 Job 时，接口 P95 ≤ 2s（不含前端渲染）。
- **NFR-JG-05**：扇出调用 M09 不新增同步接口——M09 仍由 30s watcher 感知 `updated_at` 变化；组编辑后无需等待前端触发。
- **NFR-JG-06**：组列表聚合状态查询禁止逐组 N 次查库（一次聚合查询 + 内存分组）。

### 6.3 安全与权限

- **NFR-JG-07**：组操作沿用 Job 现有权限位；跨租户/未授权网域的实例不允许被勾选或写入。
- **NFR-JG-08**：组的创建/编辑/删除记入操作审计（操作人、组名、域数、子 Job 数）。

### 6.4 术语与体验

- **NFR-JG-09**：用户界面不出现 `job_group_id`、`selected_instance_ids`、`network_domain_id` 等字段名，
  也**不出现「任务组 / 组内 / 未分组 / 子任务」等概念词**；网域以业务名展示，跨域统一表达为「覆盖网域」。
- **NFR-JG-10**：跨域提交后必须给出「生成了 N 个域的任务，最长 30s 生效」的确定性反馈（对齐 M09 自动同步节奏）。

### 6.5 筛选查询

- **NFR-JG-11**：单次候选查询（列表 + count + 分域汇总）在 10 万资源规模下 P95 ≤ 800ms；`page_size` 上限 100。
- **NFR-JG-12**：字段清单变更只改服务端 schema；前端不得硬编码字段名与枚举值。
- **NFR-JG-13**：筛选不得绕过授权域收敛，越权条件一律拒绝（fail-closed），不得静默忽略。
- **NFR-JG-14**：全选上限 2000 条；超限必须显式提示，禁止静默截断。

## 7. 数据模型概述

### 7.1 核心实体

| 实体 | 关键属性 | 说明 |
|---|---|---|
| `m01_job_groups`（新） | `id`、`name`（全局唯一）、`resource_category`、`monitor_type`、`exporter_template_id`、`scrape_interval`、`scrape_timeout`、`metrics_path`、`scheme`、`auth_type`/`username`/凭据引用、`label_template_id`、`blackbox_module`、`target_field`、`status`（enabled/disabled）、`created_by`、时间戳 | 公共参数 + 维护单元 |
| `m01_scrape_jobs`（扩展） | 新增 `job_group_id`（可空，索引）；其余字段不变，仍是单域 Job 完整快照 | 执行单元，M09 唯一读取来源 |

### 7.1.1 `job_group_id` 是内部字段（v1.3）

- `m01_job_groups` + `job_group_id` 仅用于把一次任务落成多份域级配置；
- **前端**：不作为表单字段、不作为列、不作为筛选、不进入文案；
- **兼容**：存量单域 Job 的 `job_group_id` 为空，UI 上与跨域任务无差别；编辑为跨域时按 FR-JG-04 晋升。

### 7.2 筛选条件不落库（P0）

- 组合筛选是**查询态**：条件只用于本次挑选实例，不写入组；
- P3「动态成员」才会把条件持久化到 `m01_job_groups.filters`（JSON），届时复用同一份字段 schema；
- 因此 P0 **不新增表 / 列**，也不改变 `selected_instance_ids` 的语义。

### 7.3 核心关系

- 组 1 : N 子 Job（`job_group_id`）；
- 子 Job 1 : 1 网域；
- 组级状态 = 子 Job `sync_status` 聚合（派生，不落库）。

### 7.4 对现有模块的影响

| 模块 | 影响 |
|---|---|
| M09 | **零契约变更**：仍按 `network_domain_id` 读取 Job；同时因 Job 数增加需按 §11 做扇出性能优化 |
| M07 | 无变更；仅作为"按域归组"的数据来源（`resources.network_domain_id`） |
| M08 | 无变更 |
| M06 | 无变更；域禁用时的联动由 M01 侧读取域状态实现 |

## 8. 关键流程

### 8.1 创建组

1. 用户选对象类型 → 过滤 → 多选实例（跨域）；
2. 前端按 `resource.network_domain_id` 分组预览；
3. 用户填公共参数 → 保存；
4. 后端校验：实例存在、域已纳管/启用、参数合法、组名唯一、每域内 `job_name` 唯一；
5. 事务内写组 + N 子 Job（参数快照落子 Job）；
6. 返回组视图（含 N 个域）；前端提示「最长 30s 生效」。

### 8.2 编辑组

1. 加载组 + 子 Job；
2. 用户改公共参数或实例；
3. 前端计算影响（涉及域数、子 Job 数、新增/删除）；
4. 后端事务内：更新组、按目标态对齐子 Job（增加/更新/删除）；
5. M09 watcher 在 ≤30s 内感知 `updated_at` 变化，逐域重新生成；内容未变的域因 checksum 相同不产生新快照。

### 8.3 删除组

1. 二次确认展示「将删除 N 个域的 N 条任务，M09 将停止对这些域的采集」；
2. 事务内软删组 + 子 Job；
3. M09 下次同步自动回收 targets（现有机制）。

### 8.4 域下线

1. M01 定时或事件感知某域被禁用/退纳管；
2. 该域子 Job 置停用 + 标记 `domain_unavailable`（展示态，可派生）；
3. 组状态标注「1 个域不可用」，不自动删除。

### 8.5 跨域组合筛选与批量添加

1. 选择监控对象类型 → 条件区默认 `状态 = 运行中/已停止`；
2. 用户按需追加条件（网域 / 应用 / 业务 / 平台 / 环境 / 集群 / 负责人），AND 组合；
3. 服务端校验条件 → 按授权域收敛 → 返回候选页 + 分域计数；
4. 用户跨页勾选，或「全选筛选结果」（≤2000，超限提示收窄）；
5. 展示「已选 N 台 · 覆盖 M 个网域」→ 填公共参数；
6. 保存 → 组创建（按域归组为 N 条子 Job；M09 最长 30s 感知）。

## 9. 验收标准

### 9.1 功能验收

- [ ] 创建任务时无需先选网域；可按云/业务/应用/环境/关键字筛选并跨域多选实例。
- [ ] 保存前展示分域预览；0 台实例的域不生成子 Job。
- [ ] 保存后生成 1 个组 + N 条单域子 Job，子 Job 参数快照一致，`job_name` 组内一致。
- [ ] 同组内同一 `job_name` 在不同网域合法；同一网域内重名被拒（唯一性口径已调整）。
- [ ] 改公共参数一次即扇出到全部子 Job；改实例按域增量落库，某域清零时删除该域子 Job。
- [ ] **只有一个「新建采集任务」入口**；任务类型（采集/拨测）在第一步选择，其余流程不变。
- [ ] 列表为单视图：无「按组/按 Job」切换、无「所属任务组」「未分组」列；跨域任务以「覆盖网域」表达。
- [ ] 存量单域任务与跨域任务在列表/详情/编辑中表现形式一致。
- [ ] 编辑单域任务为跨域时自动晋升（同事务），用户无额外操作；取消跨域后仍可正常保存。
- [ ] 任务级派生状态（已同步/部分失败/同步失败/待同步/草稿）展示，展开可见逐域状态与失败原因。
- [ ] 删除组级联软删子 Job；停用组全部子 Job 停用；单域退出不影响其他域。
- [ ] 域被禁用后该域子 Job 自动停用并标注不可用，不自动删除；可手动重新启用。
- [ ] 单域 Job 的既有动线与 M09 同步行为不变。
- [ ] 组列表聚合状态不引发逐组查库（一次查询完成）。
- [ ] 筛选条件可自由增删组合（AND）：网域 / 运行状态 / 应用 / 业务 / 平台 / 环境 / 集群 / 负责人均可作为条件。
- [ ] 新增可筛字段只需服务端下发 schema，前端无需改代码即可出现该条件项。
- [ ] 查询响应的分域计数与保存前「分域预览」一致。
- [ ] 「全选筛选结果」可一次纳入（≤2000 条）；超限明确提示收窄条件，不静默截断。
- [ ] 未授权网域条件被拒绝（fail-closed），且提示可执行。
- [ ] 非法字段 / 非法操作符 / 非法枚举值返回 400，点名具体字段。
- [ ] 网域条件为可选条件（不默认、不置顶、不可必填）；界面明确说明它只收窄候选，不决定下发域。
- [ ] 筛选变化不清空已选；不在当前筛选内的已选实例被显式标注并可一键清理。
- [ ] 网域选项展示云/区域归属；P0 不引入独立「云」字段。

### 9.2 非功能验收

- [ ] 200 子 Job 的创建/编辑 P95 ≤ 2s。
- [ ] 组创建/编辑/删除全程事务化，无"建了一半"的中间态。
- [ ] 用户界面不出现内部字段名；提交后给出确定性生效提示。
- [ ] 操作审计覆盖组级增删改。
- [ ] 10 万资源规模下候选查询 P95 ≤ 800ms；`page_size` 上限 100 生效。
- [ ] 翻页勾选不丢选择；条件变化后选择集按产品规则清空/保留有明确提示。

## 11. 依赖与风险

| 风险/依赖 | 影响 | 应对 |
|---|---|---|
| M09 扇出性能 | 组把 Job 数放大 N 倍，串行 watcher、逐 Job 回写、N+1 查询会拖慢同步 | 先做 M09 扇出 P0 优化（并行化、批量取资源、批量回写状态），见 M09 执行记录 |
| M01 同步状态契约 | 现有 `sync_*` 是单域单行；组级状态若落库会双写 | 组级状态一律派生，不落库 |
| `job_name` 唯一索引调整 | 旧索引为全局唯一，跨域同名此前不可能出现，改索引属破坏性 DDL | 用新 migration 重建索引；存量数据天然兼容，先备份再迁移 |
| 组与子 Job 双入口编辑 | 用户可能绕过组直接改子 Job，导致组内外不一致 | 子 Job 在组内时为"受限编辑"（仅实例与排障动作），公共参数只允许在组上改；接口层校验 |
| 指标标签语义 | 组内同名 Job 使不同域数据共享同一 `job` 标签 | 视为收益（跨域同口径查询），但需在文档与看板说明网域维度用 `network_domain` 区分 |
| **候选接口授权缺口** | 现有候选查询未按租户/授权网域收敛；支持多域筛选会把缺口放大成越权可见 | P0 必须补 fail-closed 的授权域收敛（FR-JG-13），并覆盖老 GET 接口 |
| **count(*) 成本** | 多表 join 下 count + 分页在大资源量可能变慢 | 复用/补充索引（domain/app/biz/platform/category+status）；`page_size` ≤ 100；必要时缓存或预聚合 |
| **条件语义歧义** | 同字段多次出现、空条件、全选与分页选择的交互容易出错 | 契约写死「同字段 AND 合并」；前端给出选择集变化提示；用例覆盖边界 |
| **全选体量** | 2000 个 ID 会进入组创建请求体，并存入 `selected_instance_ids` JSON 列 | 上限 + 截断提示；对组创建请求体大小做上限校验 |
| **筛选语义误读** | 用户把「网域筛选」当成「绑定下发域」，后续加域时以为要改组 | 网域条件标注定位；分域预览作为唯一可信来源；验收项覆盖 |
| PRD 与契约归属 | 本增量涉及 M01 SRS、API 契约与验收项 | 由 PRD owner 主笔合并；开发侧只提供提案与实现 |
