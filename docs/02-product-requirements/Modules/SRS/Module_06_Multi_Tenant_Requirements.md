## 1. 文档目的

本文档用**便于人理解的语言**记录 M06 模块的业务需求、功能需求与非功能需求。它站在产品经理和运维架构师的视角，说明「谁来管理平台」「哪些网络域需要被监控」「这些网络域如何接入」，并为后续概要设计、详细设计、开发、测试提供依据。

本文档不直接定义 API 字段级别的技术契约（历史技术 PRD 已覆盖），而是回答：**这个模块为什么存在、在新的中心-采集节点架构下要解决什么问题、必须具备哪些能力、做到什么程度算合格**。

## 2. 业务背景

### 2.1 中心节点只负责管理与存储

MetricCenter 的中心节点（控制面 + 存储面）承担以下职责：

- 统一的管理界面与 API
- 租户、用户、网域等元数据管理
- 监控对象台账（M07）、采集策略（M01）、告警规则（M08）的持久化
- 时序数据的长期存储与查询入口

**中心节点不再直接执行抓取、拨测或配置同步**。这些工作由部署在各个网络域内的**采集节点（采集服务器）**完成。

### 2.2 采集节点按网域分布

在政务网、跨专网、多 VPC、DMZ 或物理隔离场景下，中心节点通常无法直接访问全部监控目标，也不应承担大量出向采集流量。因此：

- 每个需要被监控的网络域都必须部署至少一台采集节点；
- 采集节点负责拉取/接收本域配置、对本域目标执行抓取与拨测、并将指标通过 remote write 回传中心；
- 网域成为「采集边界 + 配置下发边界」，而不是「中心能否直达」的区分标志。

### 2.3 一句话定位

> M06 回答的问题是：**「谁在管理这个平台，以及哪些网络域需要部署采集节点来接入监控」**。

它不负责「怎么生成 Prometheus 配置」「怎么下发到边缘」「怎么抓指标」，只负责「租户/用户/网域这些行政信息对不对、接入边界清不清楚、权限门是否守得住」。

## 3. 核心概念

### 3.1 中心节点（Center Node）

- **业务含义**：MetricCenter 的管理与存储主体。
- **核心职责**：元数据管理、配置编排、数据存储、查询代理。
- **显式约束**：不直接发起抓取、拨测或配置同步；所有面向监控目标的出向操作由采集节点承担。

### 3.2 采集节点 / 采集服务器（Collection Node / Edge Sync Agent）

- **业务含义**：部署在具体网络域内的监控执行单元，可由管理进程 + 采集器 + 拨测器组成。
- **核心职责**：
  - 从中心拉取或接收本域配置；
  - 对本域监控目标执行抓取（node-exporter、MySQL exporter 等）与拨测（blackbox）；
  - 将采集到的指标回传中心存储。
- **用户侧统一称为「采集节点」**，技术文档中可使用 Edge Sync Agent。

### 3.3 网域（Network Domain）

- **业务含义**：一组网络互通、且由同一组采集节点服务的机器的集合；是**采集边界与配置下发边界**。
- **关键变化**：
  - **不再区分「中心直连域」与「采集节点域」**；
  - 所有网域都是采集节点域，都必须通过采集节点接入；
  - 原 `domain_type` 枚举中的 `management`（中心直连域）概念取消，仅保留 `edge`/`collection` 单一类型；
  - 系统**不再预置中心直连的 `default` 管理域**；如需与中心同区域的默认域，也必须按采集节点域登记和纳管。
- **划域原则**：以**可达性同质性 + 故障自治单元**划域。当一片网络需要独立配置下发、断网自治或存在访问边界时，即应登记为独立网域。

### 3.4 租户（Tenant）

- **业务含义**：MetricCenter 内部的数据隔离与权限作用域单位。
- **MVP 阶段**：仅预置 `platform_admin` 租户，用于承载系统级默认配置与初始网域登记。
- **多租户场景（v0.2+）**：一个租户可被授权使用多个网域；一个网域也可授权给多个租户共享。**授权 ≠ 拥有**，网域的登记所有权仍归 `platform_admin`。

### 3.5 用户与角色

- MVP 仅保留 `admin` / `user` 两级**管理后台访问控制门**（H-2）。
- `admin` 可访问租户/用户/登录日志等管理接口；`user` 不能。
- 这不是完整的业务权限体系；业务角色/数据隔离由租户 + 网域标签在 M02/M03 层实现。

### 3.6 网域生命周期三动作

| 动作 | 语义 | 对新资源 / 新纳管 | 对存量采集 | 可逆性 |
|------|------|------------------|-----------|--------|
| **禁用** | 行政冻结：不准新入，不强制停旧 | 拒绝 | 不受影响、继续采集 | 可恢复启用 |
| **退纳管**（v0.2+，M09） | 停止监控：保留网域，清空纳管与凭据 | 网域回到未纳管 | 停止 | 可重新纳管 |
| **删除** | 退场回收：从平台移除该网域 | — | 级联清退（废止 Token / 停止下发 / Agent 转离线） | 软删，不可自助恢复 |

> 三者不可互相替代。删除包含级联清退，是终态动作，不经过 `enabled → disabled`。

## 4. 目标用户与使用场景

### 4.1 目标用户

| 用户角色 | 关注点 | 典型操作 |
|----------|--------|----------|
| 平台管理员 | 租户/用户/网域的全局管理 | 登记网域、授权租户、管理用户 |
| 运维工程师 | 网域接入进度、存储策略 | 登记网域、查看接入进度、调整 TSDB 保留策略 |
| 运维架构师 | 网域划分、采集边界设计 | 定义网域、规划采集节点部署 |
| 安全审计员 | 登录与操作留痕 | 查看登录日志、审计关键操作 |

### 4.2 典型使用场景

#### 场景 1：新网络域接入监控

- **角色**：运维工程师
- **触发**：新增一片隔离网络，需要纳入监控
- **目标**：在平台登记该网域并引导完成采集节点部署
- **成功标准**：
  - 网域行政信息登记完成
  - 系统明确提示「该网域必须通过采集节点接入」
  - 可直接跳转 M09/M11 完成纳管与节点安装

#### 场景 2：为业务团队授权网域

- **角色**：平台管理员
- **触发**：新租户/团队需要查看某网域的监控数据
- **目标**：将已登记网域授权给该租户
- **成功标准**：
  - 租户 `network_domain_ids` 包含该网域
  - 该租户用户只能看到被授权网域的数据

#### 场景 3：回收下线网域

- **角色**：平台管理员
- **触发**：某网络域整体下线
- **目标**：安全移除该网域及其监控接入
- **成功标准**：
  - 若存在 M07 资源引用，拒绝删除并给出迁移入口
  - 无引用时软删网域，并级联清退 M09 纳管状态
  - 采集节点凭据废止、配置停止下发、节点自然离线

#### 场景 4：调整中心存储保留策略

- **角色**：运维工程师
- **触发**：磁盘容量告警或合规要求变更
- **目标**：修改 TSDB 保留时长
- **成功标准**：
  - 保存后原子写入 `prom-retention.env`
  - 页面显示期望值 vs 运行时比对及「待重启生效」提示
  - 不越权重启 Prometheus

## 5. 功能需求

### 5.1 租户管理

#### FR-01：租户台账维护

- 系统必须支持维护租户信息（租户 ID、名称、状态、多网域能力开关等）。
- MVP 仅开放 `platform_admin` 租户的查看与编辑；不开放新建、禁用入口。
- {v0.2+} 支持创建租户、编辑 `multi_site_enabled`、状态变更。

#### FR-02：租户-网域授权

- 一个租户可被授权使用多个网域；一个网域可授权给多个租户共享。
- 授权仅表示「可使用」，不转移网域登记所有权。
- `multi_site_enabled=false` 时，平台侧仅授权单个网域；`true` 时开放多网域授权。

### 5.2 用户管理

#### FR-03：用户增删改查

- 支持创建、编辑、禁用/启用、重置密码。
- 用户名全局唯一，创建后不可变更。
- 密码以 bcrypt 哈希存储，任何接口与日志不返回明文或哈希。

#### FR-04：用户删除与会话失效

- 仅允许删除 `role=user` 的普通用户；删除为软删并立即失效其全部会话。
- `admin` 角色账号不可删除，服务层返回明确提示「admin 账号不可删除，请用禁用替代」。

#### FR-05：登录失败限流与防枚举

- 同一用户名连续失败 5 次 / 15 分钟窗口 → 锁定 15 分钟，返回 429。
- 登录失败原因统一写入「用户名或密码错误」，不区分账号不存在/已禁用/密码错误。

### 5.3 网域管理

#### FR-06：网域登记（新架构）

- 登记网域时**不再询问「中心能否直接访问」**；系统默认所有网域均需通过采集节点接入。
- 登记字段包括：网域名称、描述、云归属（`cloud_code`，必填）、网络分区（`zone_type`，必填）、授权租户、状态。
- `domain_type` 固定为采集节点域（`edge`/`collection`），用户侧只读展示「接入方式：采集节点域」，不可选择。
- `cloud_code` 与 `tenant_id` 登记后不可变更；跨云/跨归属通过「新建网域 + 资源迁移 + 旧网域退役」完成。
- 登记成功后展示行动卡：提示「还需完成采集节点纳管与安装」，并提供直达 M09/M11 的入口。

#### FR-07：网域禁用与删除

- **禁用 = 行政冻结**：禁止新资源登记与新纳管；存量资源与采集配置不受影响、继续采集。
- **删除 = 退场回收**：
  - 存在 M07 资源引用时**硬拒绝**，列出引用清单并引导迁移/删除；
  - 无引用时允许删除，软删网域并在同一次请求内级联清退 M09 纳管状态；
  - 废止 Token、停止配置下发、采集节点心跳鉴权失败后自然离线。
- 由于取消中心直连域概念，**不再存在「系统预置管理域不可删除/禁用」的特殊规则**；但仍保留对系统关键预置域的保护机制（如有）。

#### FR-08：网域接入进度（v0.2+）

- 网域列表展示四态进度：已登记 → 已纳管 → 采集节点已上线 → 已出数据。
- 行内主操作始终指向下一步：
  - 已登记 → 去纳管
  - 已纳管未上线 → 安装采集节点
  - 节点已上线 → 去配置采集
  - 已出数据 → 查看采集任务

#### FR-09：网络分区与云归属字典

- `zone_type` 取自部署级字典（政务云：互联网区 / 政务外网区 / 专线区 / DMZ；公有云：region 列表），不开放自由文本。
- 云字典页面只读展示，MVP 不开放增删改启停入口。

### 5.4 平台管理子能力

#### FR-10：存储与日志管理

- TSDB 保留策略（`retention.time` / `retention.size`）可读写；保存后原子写入 `prom-retention.env`。
- 页面展示期望值 vs 运行时比对状态，不一致时提示「待重启生效」，并提供运维自理指引。
- 磁盘占用只读展示；日志轮转策略只读展示。
- **不提供平台越权重启 Prometheus 按钮**。

#### FR-11：登录日志

- 记录登录成功/失败行为：账号、时间、来源 IP、成败结果。
- 支持按账号、结果、时间筛选。

#### FR-12：审计日志（P2 / v1.0+）

- 记录关键管理操作（租户/网域/用户变更、存储策略变更等）的操作人、时间、变更 Diff。

#### FR-13：平台配置（P2 / v1.0+）

- 维护全局 scrape 策略限制（最小/最大 scrape_interval、scrape_timeout）。
- 维护通知默认配置（默认接收人、告警模板）。

## 6. 非功能需求

### 6.1 架构约束

#### NFR-01：中心节点不直接采集

- 中心节点只承担管理、配置编排、数据存储与查询职责。
- 任何面向监控目标的抓取、拨测、配置同步必须由部署在网域内的采集节点执行。
- 后端代码中应禁止中心进程直接发起 scrape/probe 行为。

#### NFR-02：取消中心直连域概念

- `domain_type` 不再包含 `management`（中心直连域）取值；用户界面不再出现「中心直连域 / 管理域」文案。
- 系统不再预置可被中心直接采集的 `default` 管理域；所有网域均按采集节点域处理。
- 若存在历史 `default` 管理域数据，需在迁移文档中明确处理方式（建议转为采集节点域或退役）。

### 6.2 数据隔离与安全

#### NFR-03：租户与网域双重隔离

- 查询时同时注入 `tenant` 与 `network_domain` 标签；任何用户（含 `platform_admin` 租户用户）不具备 bypass 能力。

#### NFR-04：管理后台最小授权门

- `/api/v2/platform/users*`、`/tenants*`、`/login-logs*` 等管理接口仅 `admin` 角色可访问；普通 `user` 访问返回 403。

#### NFR-05：管理员密码安全

- 生产环境（`METRIC_CENTER_ENV=production`）必须显式配置 `METRIC_CENTER_ADMIN_PASSWORD`，否则后端启动失败。
- 非生产环境可回退默认密码，但须提示修改。

#### NFR-06：敏感信息保护

- 密码哈希、Token、会话密钥不得出现在任何接口响应、日志或前端展示中。

### 6.3 一致性与可维护性

#### NFR-07：编码不可变

- `tenant_id`、`cloud_code`、网域 ID 规则创建后不可变更；展示名可修改。

#### NFR-08：软删与审计

- 网域删除、用户删除均为软删，保留审计记录。
- 关键管理操作变更须留痕。

#### NFR-09：幂等初始化

- `platform_admin` 租户、`admin` 初始管理员由后端 migration upsert 保证存在，幂等可重复执行。

### 6.4 性能与可用性

#### NFR-10：列表响应时间

- 租户/网域/用户/登录日志列表首屏加载时间 ≤ 1 秒（95 分位）；分页/筛选 ≤ 500 毫秒。

#### NFR-11：用户语言一致性

- 用户界面统一使用「租户 / 网域 / 采集节点 / 网络分区 / 云归属」等业务语言；技术枚举（`edge`、`agent_pull` 等）仅出现在折叠区、代码注释或接口文档。

#### NFR-12：错误提示可执行

- 删除被拒绝、字典不存在、网域未登记等错误，须给出下一步操作指引。

## 7. 数据模型概述

### 7.1 核心实体

| 实体 | 说明 | 关键属性 |
|------|------|----------|
| Tenant | 租户 | ID、名称、被授权网域、多网域开关、状态 |
| NetworkDomain | 网域行政信息 | ID、名称、`cloud_code`、`zone_type`、授权租户、状态 |
| User | 用户 | 用户名、角色、状态、所属租户 |
| LoginLog | 登录日志 | 账号、IP、成败、时间 |

### 7.2 网域行政字段（M06 维护）

| 字段 | 说明 |
|------|------|
| `id` | 网域唯一标识，全局唯一，按 `<deploy_code>-<domain_code>` 生成 |
| `name` | 网域展示名 |
| `domain_type` | 固定为采集节点域（`edge`/`collection`），用户侧只读展示 |
| `zone_type` | 网络分区（必填），来自部署级字典 |
| `cloud_code` | 云归属（必填），来自云字典，登记后不可变更 |
| `tenant_id` | 登记归属租户（MVP 固定 `platform_admin`），创建后不可变更 |
| `authorized_tenant_ids` | 被授权可使用该网域的租户列表 |
| `status` | enabled / disabled |

> 监控纳管字段（`channel`、`token`、`remote_write_url`、运行态等）由 Module 09 / Module 11 维护；M06 只维护行政字段。

### 7.3 核心关系

- **租户 → 网域**：多对多授权关系（`Tenant.network_domain_ids` / `NetworkDomain.authorized_tenant_ids`）。
- **租户 → 用户**：一对多。
- **网域 → 资源**：M07 资源通过 `network_domain_id` 引用网域；M06 不维护资源。

## 8. 关键流程

### 8.1 网域登记流程（新架构）

1. 用户进入「网域管理」，点击「登记网域」。
2. 界面直接展示「所有网域均需通过采集节点接入」的说明，不再询问中心可达性。
3. 用户填写行政信息：名称、云归属、网络分区、授权租户、描述等。
4. 系统校验字段、生成网域 ID。
5. 保存后展示行动卡：提示完成「纳管 → 安装采集节点 → 配置采集」三步。

### 8.2 租户与网域授权流程（v0.2+）

1. 平台管理员创建租户，设置 `multi_site_enabled`。
2. 在「网域管理」登记网域行政信息。
3. 将网域授权给一个或多个租户使用。
4. 各租户自行或被授权后，由 Module 09/M11 完成采集节点纳管与部署。

### 8.3 网域禁用/删除流程

1. 用户选择禁用网域：
   - 系统返回影响范围（M07 资源数 / 已纳管采集节点数）；
   - 二次确认后禁用，拒绝新资源登记与新纳管，存量采集继续运行。
2. 用户选择删除网域：
   - 若存在 M07 资源引用，拒绝删除并返回引用清单；
   - 若无引用，二次确认后软删网域，并在同一次请求中级联清退 M09 纳管状态（废止 Token / 停止下发 / 采集节点自然离线）。

### 8.4 用户管理流程

1. 管理员创建用户，设定初始密码与角色。
2. 用户登录后按角色访问对应菜单。
3. 禁用/删除用户时立即失效其会话。
4. 登录成功/失败均记录 LoginLog。

### 8.5 存储保留策略更新流程

1. 用户在「存储与日志管理」页修改保留策略。
2. 后端校验格式，原子写入 `prom-retention.env`。
3. 页面回显期望值 vs 运行时比对状态，提示「待重启生效」。
4. 运维人员在维护窗口手动重启 Prometheus 生效。

## 9. 验收标准

### 9.1 功能验收

- [ ] 中心节点仅承担管理与存储职责，不直接发起抓取、拨测或配置同步。
- [ ] 用户界面与文档中不再出现「中心直连域 / 管理域」概念。
- [ ] `domain_type` 不再包含 `management` 取值；用户侧统一展示「采集节点域」。
- [ ] 系统不再预置可被中心直接采集的 `default` 管理域；如需默认域，也必须按采集节点域登记和纳管。
- [ ] 网域登记流程不再询问「中心能否直接访问」，而是默认该网域需通过采集节点接入。
- [ ] 网域登记字段包含名称、`cloud_code`（必填）、`zone_type`（必填）、授权租户、状态等。
- [ ] `cloud_code` 与 `tenant_id` 登记后不可变更；编辑接口不含这些字段。
- [ ] 网域禁用 = 行政冻结：拒绝新资源登记与新纳管，存量采集继续运行。
- [ ] 网域删除：存在 M07 资源引用时拒绝并返回清单；无引用时软删并级联清退 M09 纳管状态。
- [ ] 租户管理 MVP 仅开放 `platform_admin` 查看/编辑；v0.2+ 支持完整生命周期。
- [ ] 用户管理支持创建/编辑/禁用/启用/重置密码；`admin` 不可删除；删除 `user` 软删并失效会话。
- [ ] 登录日志记录账号/时间/IP/成败，失败原因统一防枚举。
- [ ] 存储与日志管理支持 TSDB 保留策略读写、期望值 vs 运行时比对、磁盘占用与日志轮转只读展示；不做越权重启按钮。
- [ ] {v0.2+} 网域列表展示接入进度四态，行内主操作指向下一步。

### 9.2 非功能验收

- [ ] 后端代码中不存在中心节点直接 scrape/probe 的实现路径。
- [ ] 管理后台接口实现 `RequireAdmin` 门，`user` 角色访问返回 403。
- [ ] 密码以 bcrypt 存储；接口与日志不泄露密码哈希或明文。
- [ ] 生产环境未配置管理员密码时，后端启动失败。
- [ ] 租户/网域/用户/登录日志列表首屏加载 ≤ 1 秒（95 分位）。
- [ ] 关键管理操作落审计日志；网域删除、用户删除为软删并留痕。
- [ ] 用户界面统一使用业务语言，错误提示给出可执行指引。

## 10. 依赖与风险

### 10.1 模块依赖

| 依赖方 | 依赖内容 | 说明 |
|--------|----------|------|
| Module 03 | 认证与会话 | 登录、登出、会话校验、角色门 |
| Module 07 | 监控对象台账 | M06 删除网域时依赖 M07 资源引用检查 |
| Module 09 | 配置生成与下发 | 网域纳管后的配置生成、变更单、下发通道由 M09 负责 |
| Module 11 | 采集节点生命周期 | 采集节点安装、心跳、配置包拉取、退役由 M11 负责 |

### 10.2 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 取消中心直连域后，MVP 最小部署需要至少一个采集节点 | 部署成本与复杂度上升 | 在网域登记流程中明确引导安装采集节点；提供自动化安装脚本与离线包 |
| 现有模块（M09/M11）仍保留 `default` 管理域/`local` 通道假设 | 跨模块口径冲突 | 以本文档行政语义为准，由 M09/M11 后续同步收敛通道与默认域处理 |
| 用户习惯旧版「中心能直连就不建域」心智 | 误登记或漏部署采集节点 | 界面明确提示「所有网域均需采集节点」，并在接入进度中卡住「未上线」状态 |
| 历史数据中存在 `management` 类型网域 | 升级后状态不一致 | 提供迁移指南：将原管理域转为采集节点域，或退役后重建 |
