## 1. 文档目的

本文档用**便于人理解的语言**记录 M05 模块的业务需求、功能需求与非功能需求。它站在产品经理和运维工程师的视角，说明「平台默认落地页应该展示什么」「大屏如何挂载」「各类监控数据如何以可视化方式呈现」，并为后续概要设计、详细设计、开发、测试提供依据。

本文档不重新定义后端业务规则与数据契约（由 M01/M02/M06/M07/M08/M09 等模块承载），而是回答：**作为可视化中心，M05 需要把哪些数据可视化、保留哪些已实现的界面、做到什么程度算合格**。

---

## 2. 业务背景

### 2.1 从「自定义前端门户」到「可视化中心」

原 M05 定位为「自定义前端门户」，侧重门户页面组织与交互设计。随着首页概览、面板挂载、自定义大屏等能力的落地，M05 的核心价值越来越聚焦于**可视化呈现**：

- 把分散在各后端模块的数据（资源、采集、拨测、告警）汇总到首页；
- 通过 Grafana iframe 嵌入提供大屏能力；
- 保留已实现的资源管理、采集配置、查询、告警状态等配套管理界面。

因此，本模块更名为「可视化中心」，定位更清晰：它是 MetricCenter 的**数据可视化层与默认入口**，后端能力边界不变。

### 2.2 一句话定位

> M05 回答的问题是：**「用户打开平台第一眼能看到什么、如何快速发现异常、如何进入大屏深度观测」**。

## 3. 核心概念

### 3.1 可视化中心

- **业务含义**：MetricCenter 的 Web 界面层与默认入口；
- **核心职责**：数据可视化、页面导航、大屏挂载、配套管理界面前端呈现；
- **边界**：不定义后端业务规则，所有规则由对应后端模块 PRD 承载；M05 只消费后端接口并呈现。

### 3.2 首页概览 Dashboard

- 平台默认落地页，一屏总览资源分布、纳管完成率、采集健康、拨测态势、告警状态；
- 面向新用户提供六步开箱引导；
- 各卡片数据来自不同后端模块，M05 负责聚合展示与降级处理。

### 3.3 面板挂载与可视化大屏

- **面板挂载**：管理员登记 Grafana 面板（名称 + URL），普通用户只读；
- **自定义大屏**：首页「自定义大屏」按已登记面板生成动态子菜单，点击进入 iframe 展示页；
- **可视化大屏**：一级导航入口，v0.3 起提供预置仪表盘模板与全屏投屏能力。

### 3.4 配套管理界面

- 资源管理、标签模板、CI-Exporter 映射、采集 Job、实例选择、拨测配置、规则编辑、配置预览/下发、目标状态、查询页、告警状态页等已实现页面；
- 这些页面由 M05 提供前端交互，业务规则与数据分别由 M01/M02/M07/M08/M09 承载。

### 3.5 跨模块数据契约

- M05 与各后端模块通过统一 API 接口消费数据；
- 接口失败时按卡片级/区域级降级，避免整页崩溃；
- 各卡片须明确标注数据来源与口径，避免用户误解。

## 4. 目标用户与使用场景

### 4.1 目标用户

| 用户角色 | 关注点 | 典型操作 |
|----------|--------|----------|
| 运维工程师 | 未监控资源、采集异常、拨测异常、未结告警 | 查看首页、进入大屏、查看目标状态 |
| 业务研发工程师 | 负责服务的指标与告警 | 查看首页资源分布、查询指标、查看告警状态 |
| 管理员 | 大屏挂载、首页布局 | 登记 Grafana 面板、配置首页入口 |
| 值班工程师 | 当前告警与历史告警 | 查看首页告警卡、进入告警状态页 |

### 4.2 典型使用场景

#### 场景 1：一屏掌握平台健康

- **角色**：运维工程师
- **触发**：每日巡检或故障排查
- **目标**：从首页快速发现异常
- **成功标准**：
  - 资源分布、纳管完成率、采集健康、拨测态势、告警状态一目了然；
  - 异常卡片高亮并可直接下钻到对应模块。

#### 场景 2：挂载 Grafana 大屏

- **角色**：管理员
- **触发**：团队需要在大屏/电视墙展示监控
- **目标**：登记 Grafana 面板供团队访问
- **成功标准**：
  - 在「系统与平台管理 → 面板挂载」登记面板；
  - 首页「自定义大屏」动态生成子菜单；
  - iframe 展示页自动追加 `kiosk` / `hideLogo=true`。

#### 场景 3：查询指标与查看告警

- **角色**：业务研发工程师
- **触发**：服务出现异常
- **目标**：查询指标趋势、确认告警状态
- **成功标准**：
  - 通过查询页执行 PromQL；
  - 通过告警状态页查看当前告警与规则评估参考。

#### 场景 4：管理资源与采集配置

- **角色**：运维工程师
- **触发**：新服务上线
- **目标**：录入资源、配置采集 Job、下发配置
- **成功标准**：
  - 在资源管理页维护资源；
  - 在采集 Job 页配置采集策略；
  - 在配置预览/下发页确认并下发。

## 5. 功能需求

### 5.1 首页概览可视化

#### FR-01：首页作为默认落地页

- 用户登录后默认进入首页概览；
- 首页采用五段首屏版式：页头行、资源分布行、纳管完成率卡、告警状态卡、采集健康卡、拨测态势卡、使用指引。

#### FR-02：资源分布展示

- 左侧按云归属展示主机数量与覆盖率；
- 右侧展示平台 × 应用二维主机分布矩阵；
- 支持「隐藏/显示资源分布」开关，偏好持久化到本地存储。

#### FR-03：纳管完成率展示

- 左侧圆环展示整体纳管率（已监控 / 资源总数）；
- 右侧六行资源类型表展示主机、数据库、中间件、应用服务、接口服务、其他监控目标的资源数与已监控数；
- 拨测目标计入已监控口径，但不单独作为资源类型行。

#### FR-04：告警状态卡

- 左四格统计：今日告警 / 今日告警今日恢复 / 历史遗留告警 / 历史遗留今日恢复；
- 右栏「当前告警」列表展示未结三态（告警中 / 静默中 / 抑制中），卡内滚动，不分页；
- 统计接口失败时四格显示 `-`，当前告警接口失败时列表区独立降级。

#### FR-05：采集健康展示

- 展示「采集中」与「已下发未采到」两态；
- 分母为已配置采集任务的资源数；
- 数据缺失时展示「采集健康数据暂不可用」，不显示 0。

#### FR-06：拨测态势展示

- 展示拨测目标总数、正常数、异常数、未知数；
- 按接口服务 / 应用服务分区计数；
- 拨测目标明细由 M01 blackbox Job 所选资源派生。

#### FR-07：使用指引

- 面向新用户展示六步开箱动线：登记网域 → 导入资源 → 建采集 Job → 下发配置 → 配置告警通知 → 查指标/看告警；
- 每步提供深链入口与完成态标识。

### 5.2 面板挂载与可视化大屏

#### FR-08：面板挂载管理页

- 管理员可在「系统与平台管理 → 面板挂载」登记/编辑 Grafana 面板；
- 字段：面板名称（全库唯一，1~100 字符）、Grafana URL（`http`/`https`，非空 host，包含 `/d/` 路径，≤2048 字符）；
- 普通用户只读，写操作返回 403；
- 列表分页展示。

#### FR-09：自定义大屏动态子菜单

- 首页「自定义大屏」按已登记面板动态生成子菜单；
- 无面板时展示空态引导；
- 每个子项进入 `/dashboard/panels/:id` 展示页。

#### FR-10：iframe 展示页

- 展示页通过 iframe 加载 Grafana 面板 URL；
- 自动追加 `kiosk` 与 `hideLogo=true` 参数；
- 同源时屏蔽双击与 Escape 退出全屏；
- Grafana 登录态与 `allow_embedding` 由 Grafana 侧负责，平台不托管。

#### FR-11：可视化大屏一级导航

- 一级导航保留「可视化大屏」入口（第 2 位）；
- v0.3 起提供预置仪表盘模板、大屏快捷入口、全屏/退出全屏按钮。

#### FR-12：大屏全屏动线

- 进入可视化大屏后提供全屏按钮；
- 全屏模式隐藏门户侧边栏与顶部导航，iframe 铺满可视区域。

### 5.3 告警可视化

#### FR-13：告警状态卡数据流

- 四格统计消费 M08 `GET /api/v2/platform/alertmanager/alert-events/stats`；
- 当前告警列表消费 M08 `GET /api/v2/platform/alertmanager/alert-events/current`；
- 两条链路独立降级，互不阻塞。

#### FR-14：告警状态页

- 展示当前告警列表与处理进度；
- 提供「规则评估」页签，参考 M02 代理的 Prometheus `/api/v1/alerts`；
- 告警列表实例名按 `resource_id` 回连资源表回填。

### 5.4 资源/采集/查询可视化

#### FR-15：资源管理页

- 支持主机、数据库、中间件、应用服务、接口服务、其他监控对象的 CRUD 与 Excel 导入；
- 展示「已监控 / 未监控」badge；
- 支持按资源类型编辑监控标签。

#### FR-16：标签模板页

- 按资源类型配置「资源字段 → 监控标签」映射；
- 支持内置模板只读、自定义模板编辑。

#### FR-17：CI-Exporter 映射页

- 维护 CI 类型 ↔ 采集器模板绑定；
- 配置默认端口、采集路径、协议、标签模板引用。

#### FR-18：采集 Job 页

- 创建/编辑采集 Job；
- 选择采集器模板、实例、标签模板。

#### FR-19：实例选择与拨测配置页

- 手动勾选监控实例；
- 配置拨测目标与探测模块。

#### FR-20：规则编辑页

- 类 YAML 表单编辑告警/记录规则；
- 表达式校验与指标实时预览。

#### FR-21：配置预览与下发页

- 实时预览生成的配置产物；
- 与当前生效版本 diff 对比；
- 人工确认后下发（注：随着 M09 合并与配置同步简化，该页面可能退化为「查看最新配置与同步状态」，具体以前端实现为准）。

#### FR-22：目标状态页

- 查看所有采集目标状态与拨测结果；
- 按网域、Job、健康状态筛选。

#### FR-23：查询页

- PromQL 表达式编辑器；
- 查询结果以表格/JSON/简单折线展示；
- 调用 M02 `/api/v1/query*` 代理。

### 5.5 导航与布局

#### FR-24：一级导航

- 首页（默认落地页，第 1 位）；
- 可视化大屏（第 2 位）；
- 资源管理、采集配置、查询、告警状态等按既定顺序排列。

#### FR-25：首页子菜单

- 「概览 Dashboard」（默认 Tab）；
- 「使用引导」；
- 「自定义大屏」动态子菜单。

#### FR-26：管理员入口

- 「系统与平台管理 → 面板挂载」进入面板挂载管理页。

## 6. 非功能需求

### 6.1 职责边界

#### NFR-01：M05 是展示层

- M05 不定义后端业务规则；所有规则由 M01/M02/M06/M07/M08/M09 承载；
- M05 只通过统一 API 消费数据并呈现。

#### NFR-02：数据来源透明

- 首页各卡片须明确数据来源模块与口径；
- 鼠标悬浮或折叠区提供口径说明。

### 6.2 性能与可用性

#### NFR-03：首页加载性能

- 首屏关键内容（四格统计、当前告警列表）加载时间 ≤ 1.5 秒（P95）；
- 非关键资源分布、矩阵等可延迟加载。

#### NFR-04：降级展示

- 任一后端接口失败时，仅该卡片/区域降级，不阻塞整页；
- 数据缺失时展示「暂不可用」或「暂无数据」，不显示误导性 0。

#### NFR-05：iframe 加载

- Grafana iframe 采用懒加载；
- 加载失败时展示明确提示与重试入口。

### 6.3 响应式与交互

#### NFR-06：响应式布局

- 首页五段版式在桌面端完整展示；
- 窄屏/移动端按优先级回落（例如告警状态卡优先、矩阵可横向滚动）。

#### NFR-07：状态持久化

- 「隐藏/显示资源分布」等用户偏好持久化到 `localStorage` 或用户配置。

### 6.4 安全与权限

#### NFR-08：面板挂载权限

- 面板挂载的写操作仅限管理员角色；
- 普通用户只读访问面板列表与展示页。

#### NFR-09：URL 校验

- 面板 URL 仅允许 `http`/`https`、非空 host、包含 `/d/` 路径；
- 平台不主动请求目标 URL，避免 SSRF。

### 6.5 可维护性

#### NFR-10：组件复用

- 首页卡片、告警列表、资源表格等尽量抽离为通用组件；
- 与后端模块的接口调用集中在 `src/api/` 下按模块划分。

#### NFR-11：用户语言一致性

- 用户界面统一使用「可视化大屏 / 面板挂载 / 首页概览 / 当前告警 / 纳管完成率」等业务语言；
- 技术术语（`iframe`、`Grafana`、`PromQL` 等）在首次出现时给出中文解释。

## 8. 关键流程

### 8.1 首页数据加载与降级流程

1. 用户进入首页。
2. 并行请求 dashboard summary、alert-events stats、alert-events current。
3. 各卡片独立渲染：
   - 成功：展示数据；
   - 失败：展示降级状态（`-` 或「暂不可用」）；
   - 空数据：展示空态引导。
4. 非关键资源分布、矩阵等延迟加载。

### 8.2 面板挂载与展示流程

1. 管理员进入「面板挂载」页，填写名称与 URL，保存。
2. 后端校验名称唯一性与 URL 格式。
3. 保存成功后首页「自定义大屏」动态子菜单更新。
4. 普通用户点击子菜单进入 iframe 展示页。
5. 展示页自动追加参数并加载 Grafana URL。

### 8.3 导航访问流程

1. 用户登录后默认进入首页「概览 Dashboard」。
2. 一级导航「可视化大屏」进入 v0.3 预置大屏页（MVP 阶段可跳转至自定义大屏）。
3. 首页顶部 v0.3 提供「进入可视化大屏」快捷入口。

### 8.4 告警状态卡数据流

1. 首页挂载时请求 M08 `alert-events/stats` 与 `alert-events/current`。
2. 四格统计展示在左栏，当前告警列表展示在右栏。
3. 列表按开始时间倒序，卡内滚动。
4. 任一接口失败时对应区域独立降级。

## 9. 验收标准

### 9.1 功能验收

- [ ] 首页为平台默认落地页，采用五段首屏版式。
- [ ] 资源分布行包含按云分组与平台×应用矩阵，支持隐藏/显示开关。

### 10.2 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| 后端接口口径变化导致首页展示错误 | 首页数据失真 | 与各后端模块明确接口契约；首页增加口径说明与降级处理 |
| Grafana 登录态或 `allow_embedding` 配置问题导致 iframe 无法展示 | 大屏不可用 | 文档明确 Grafana 侧配置要求；展示页提供排查指引 |
| 已实现的配置下发/回滚页面随 M09 合并需要调整 | 页面功能与实际流程不一致 | 配置预览/下发页随 M09 新流程同步调整为「查看最新配置与同步状态」 |
| 首页卡片过多导致性能下降 | 加载慢 | 关键数据优先加载，非关键卡片延迟加载；按模块独立请求 |
| 普通用户误操作面板挂载 | 安全风险 | 写操作加管理员权限门；管理入口放在系统设置下 |
