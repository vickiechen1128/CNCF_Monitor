# 概要设计（HLD）与场景演示规范

本 Skill 面向**技术方**。核心原则：**从场景推导实现，能力抽象是技术内部的事，演示脚本必做**。技术方的产出不是为了证明“功能多完善”，而是演示“如何满足需求方的场景”。

---

## 1. 适用场景

- 拿到已确认的 SRS，产出概要设计（HLD）。
- 把 SRS 中的业务场景映射到服务/接口/数据/扩展点。
- 准备给需求方做的场景演示（走查）。
- 维护 Scenario Link 矩阵。

---

## 2. 核心原则

1. **场景 → 实现**：先回答“这个场景怎么走通”，再落到接口/数据/模块。
2. **能力抽象是技术内部动作**：复用/扩展/新建能力（CAP）是技术方从业界参考里抽出来的复用手段，不要求需求方理解，也不写进 SRS。
3. **演示必做**：每个场景必须产出一段可执行的演示脚本；功能清单不能替代演示。
4. **禁止功能清单优先**：不先堆 CRUD/权限/审计等常见能力，除非某场景需要。
5. **不重述需求**：HLD 不复制 SRS 的场景描述/验收，只写技术决策。

---

## 3. 输入

- SRS（业务场景 SCN + 验收）
- 现有代码/契约（`api-contract-snapshot*`、`platform/modules/*`）
- 业界产品/工具参考（用于能力抽象）
- `docs/07-design/README.md` 的分层约定

---

## 4. 设计流程

```text
SRS 场景（SCN）
  → 场景走通：用户怎么完成、系统内部怎么配合
  → 能力映射：复用什么能力 / 扩展什么 / 新建什么（技术内部）
  → 接口与数据：需要哪些接口、哪些实体、归属谁
  → 扩展点与变体：项目差异如何配置化
  → 风险与决策：复用风险、扩展点风险、定制债务
  → 演示脚本：每个场景一段走查脚本
```

### 4.1 场景 → 实现映射

每个 SCN 一行：

```markdown
| SCN | 能力（技术内部） | 服务/模块 | 接口/数据 | 扩展点 | 风险 |
|-----|------------------|-----------|-----------|--------|------|
| SCN-01 | CAP-08 边缘接入 | m09 | /api/v3/edge/* | 心跳周期、离线阈值 | 网络抖动 |
```

- 能力（CAP）由技术方抽象，标注复用/扩展/新建；新建必须写理由。
- 项目差异通过配置/模板/策略/扩展点表达，禁止 `if project == X`。

---

## 5. HLD 结构

> 模板：`docs/07-design/_TEMPLATE_HLD.md`；场景链接模板：`docs/07-design/_TEMPLATE_SCENARIO_LINK.md`。

```text
1. 文档信息与参考（SRS / Capability 参考 / Scenario Link）
2. 设计概述（系统上下文、组件职责、代码结构）
3. 约束与关键决策（复用/扩展/新建的 ADR）
4. 接口清单（语义 + 错误策略；字段级见契约）
5. 数据设计（实体归属、生命周期、迁移）
6. 关键设计与扩展点（变体如何配置化）
7. 关键流程 / 状态机
8. 安全 / 性能 / 可观测性
9. 测试与验证策略（按场景验收）
10. 风险与未决
11. 变更记录
```

**禁止**：复制 SRS 的场景描述/验收；写页面交互细节；维护第二份需求追溯表（只链接 Scenario Link）。

---

## 6. 场景演示脚本（必做）

每个 SCN 一段，放在 `docs/05-execution-records/module-XX/scenario-walkthrough.md`（或任务卡指定位置）：

```markdown
## SCN-01 演示
- 前置：默认网域、一个 host 资源
- 步骤：1. 登记网域 → 2. 安装 agent → 3. 等待心跳 → 4. 查看配置产物
- 预期：节点 online、config 版本 +1
- 实际：...
- 需求方反馈：...
```

演示的目标：让需求方用“感受”判断场景是否满足，而不是看功能清单。功能再完善，走不通场景也不及格。

---

## 7. Scenario Link 矩阵（唯一链接点）

每个模块一份 `docs/07-design/Module_XX_Scenario_Link.md`：

```markdown
# Module XX 场景链接矩阵

> 状态：draft / reviewed / approved
> SRS / HLD 版本、需求 Owner、技术 Owner

| SCN | 验收（需求方语言） | 技术实现（技术内部） | 演示步骤 | 需求方反馈 | 结论 | 状态 |
|-----|--------------------|----------------------|----------|------------|------|------|
| SCN-01 | 节点在线、配置正确下发 | CAP-08 / m09 / /api/v3/edge/* | 1. 纳管 2. 装 agent 3. 看心跳 | “对，就是这样” | 通过 | approved |
```

- 技术方维护；需求方在每次演示后确认/修正“需求方反馈”列。
- 无孤儿场景（没有实现/演示/验收）方可进入开发。

---

## 8. 质量检查清单

- [ ] 每个 SCN 都有实现映射 + 演示脚本
- [ ] 复用/扩展/新建有理由；新建能力有 ADR
- [ ] 项目差异是配置化/扩展点，不是代码分支
- [ ] 接口清单语义完整，字段级指向契约
- [ ] 没有复制 SRS 的需求描述
- [ ] Scenario Link 无孤儿行
